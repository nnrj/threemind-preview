## Summary of user decisions

The user first requested a feasibility assessment: move mistakenly committed experiment artifacts to appropriate data storage and exclude them from Git, remove their history, check similar cases, and consider configurable external data locations comparable to chat-record storage. They subsequently approved addressing other similar committed materials and allowed adding revised reports with an opening explanation for revised paths, while preserving original report bytes and links.

Further discussion approved unified data management and a formal `data-bundle`: shared UI/REST/CLI/Agent interfaces; faithful archiving and reimport of all research materials; native-record restoration for supported types; complete continuation through supported restorers. Unknown outer bundle schemas are rejected for formal import; unsupported objects inside known bundles remain read-only. Missing required restoration dependencies permit material archiving but prevent complete-bundle or complete-continuation claims. Material import, native restoration and continuation are separately declared. Typed entries and a complete dependency closure support import/export selection by experiment, batch/dataset, time range and other dimensions, with stage and type available as filters.

Seven safeguards are approved in this phase: complete archive dependency checks; staged-upload lifecycle; immutable external evidence and project-local deduplication; cross-backend backup manifests and isolated restore validation; frozen task destinations/policy revisions, stable host identity and actual reachability; capacity/integrity auditing; bounded I/O/caches and explicit failures for missing objects.

Actual relocation is limited to mistakenly committed artifacts; other migration capabilities are developed and tested only. Git changes remain local, with no push. Migration, import and packaging have programmatic interfaces. Human CLI deletion retains the preview token and name confirmation; Agent may preview cleanup only. The latest request is to update the plan, so this turn performs no implementation, migration, deletion, history rewrite or service operation.
