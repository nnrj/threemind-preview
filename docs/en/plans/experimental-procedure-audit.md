## Causes and uncertainty

The traceable failure chain is: split the joint system into convenient stages; change several conditions during local engineering; substitute state-continuity tests for behavioral-baseline comparison; then append more training before reconstructing the full successful method. E61's controller change was a clear error. Online learning and a different readout window can be legitimate research conditions, but not an undisclosed version of “only the eye changed.”

Core teaching and peripheral calibration were also conflated under “training.” Reports must distinguish whether Core changes, whether simulated time advances, and whether the same peripheral continues. Offline fitting is not inherently wrong and online fitting is not inherently superior; the declared research question determines their role.

**Context compression is not an established root cause.** No identified compression event has been linked to the loss of a specific constraint and a specific implementation change. Existing sources already contained relevant methods and continuity requirements; enforcement also failed. A long conversation plausibly increases retrieval risk, but that inference neither establishes causation nor excuses the failure. There is no evidence here of external malicious instructions or intentional sabotage.

Primary shape10/16misses the assistant's preregistered12/16branch gate; old-subject calibration and fixed-head edge interventions did not run. This does not erase the substantial25/32and27/32improvement, and is not the user's consciousness criterion. Both sets use one source. The user's condition for a validated success-procedure standard requires both blank and old subjects to work; that has not yet been tested. This page records safeguards and the retrospective, not a proven universal recipe.

## Operational safeguards

1. Before execution, record the complete subject, blank versus experienced origin, retained conditions and exact changes, based on actual sources/snapshots.
2. Retain an executable successful reference. Disclose task/window/peripheral/learning/control-path changes before running, obtaining agreement for changes covered by the existing continuity rule.
3. Separate Core teaching, peripheral calibration, read-only analysis and causal interventions. State where labels go and what inference receives. Calibration success is not automatically Core learning; readout failure is not automatically failed learning.
4. Prioritize actual answers/actions, with fit error as explanation. Return to the full reference after bundled changes rather than endlessly correcting a weak branch or adding mechanisms.
5. Verify necessary continuity without repeated large-evidence hashing. Distinguish completed, stopped and unexecuted work; preserve original criteria and date later decisions.
6. Put user corrections in the current handoff and backlog. A new conversation must read these, the source audit and actual results before changing the model.
