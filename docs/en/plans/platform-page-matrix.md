# Platform hierarchy and page matrix

October 11, 2026. Companion to the [final plan](platform-hierarchy-navigation-workbench.md). This records implementation boundaries, not acceptance claims.

| Entry | Browsing scope | Configuration/operation target | Authorization and state boundary |
|---|---|---|---|
| Consciousness workbench (home) | All authorized individuals; open by identity | Open individual, selected node, page-local capture/playback | Viewing never runs a model; control actions have separate permissions; managed-study restrictions remain |
| Research overview/projects | Authorized research; project is a filter | Ownership, membership, explicit presets and notification rules | Filter is independent of object authority; no first-project fallback |
| Experiments/training/comparison/worlds | Authorized lists and stable details | Protocols, conditions and execution objects | Frozen protocols, lineage and whole-system continuity remain |
| Materials | Authorized records, originals and personal data | Reports, notes, evidence and data operations | Private authority is preserved; superadministrator is global; filtering does not grant access |
| Creation defaults/templates | Independent of projects | Per-kernel defaults and one explicit template | Future individuals only; validation constructs no engine |
| Create consciousness | Configure first, choose project at save | Actual full configuration plus provenance | Prepared by default; old calls still start by default; initialize once on explicit start |
| AI services | Unified platform catalogue and authorized availability | Multiple credentials and project-use grants | Read/manage/use are distinct; original grants do not become global |
| Mail services/notifications | Host transports and global personal inbox | Service credentials; project event rules | Updating a service never resends an old outbox item |
| Devices/adapters | Installed capabilities and creation defaults | Host capabilities; individual wiring in its own controls | Viewing requests no device permission and constructs no model |
| Execution/storage | Authorized host queue/processes/locations | Host limits and persistence policy | Separate from Core energy and simulation rhythm; restart-only fields are explicit |
| Accounts/roles | This deployment | Multiple action-scope grants | Enforced in backend; protect last superadministrator; fresh revocations |
| CLI/MCP/Python | Same platform resources and services | Protected reusable session or bounded delegation | Non-interactive; no implicit local-root fallback; no identity in Core |
| Documentation/help | Public repository documentation | Guides and operation directory | No project gate; original evidence and historical reports remain |

Display preferences are browser-local and user-isolated. Templates contain configuration, not grown weights. Historical restoration uses the individual's original kernel and complete system state.
