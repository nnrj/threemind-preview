## Identity and defaults

New kernel `threemind.continuous-memory/5`, state `threemind.continuous-memory-state/5`. Historical2/3/3.1/4 remain independently creatable/restorable; application default stays unchanged. Renaming old states to5 is rejected.

Default reception is `legacy-source`, arrival handling `sequential`, phase `aligned`. Different external observation packets never become a common stimulus merely because timestamps match. Same-round internal messages preserve the old reception context but create no recipient-pair learning. Unified/coincident/asynchronous options explicitly differ from the principal baseline.

Retain approved local clocks, both H/stability modes, automatic/manual support reclamation, optional dormant/awakening behavior, and the local energy model with its master switch off. Removing H/all forgetting or retuning numerical parameters is not authorized here.

## Performance optimization proposal, October 13, 2026: not yet approved for implementation

### Direction and boundaries

**Keep local dynamics and reduce the representation and scheduling cost of executing them.** Optimize default H and shared implementation paths first; investigate exact lazy stability-S settlement separately. Default H already benefits on the large sparse fixture, and disabling H did not fix dense performance. Removing H, restoring global dynamics scans, limiting graph size, or reducing internal event frequency is outside this proposal.

Nodes still respond only to their inputs, local state, and authorized contacts. Stable-ID mappings, queues, and allocation are execution machinery, not global learning allocation, ranking, budgets, or arbitration. Preserve learning, decay, thresholds, resources, phases, simultaneous-event order, and defaults. Tool overhead affects wall time only.

Cross-version timing is not a pure executor A/B with identical dynamics: version 5 also includes H, support, and reclamation mechanisms. The primary optimization comparison is original `/5` versus candidate `/5`; `/2` and `/3.1` are external performance references and historical witnesses. This phase does not promise to beat `/2` on every workload or count deleted mechanisms as implementation gains.

### Same timestamp does not imply unchanged state

Direct input, internal signals, learning and novelty rewards can modify an object successively at one simulated instant. Timestamp-only caching is invalid. Cache configuration-only constants, or use a tightly limited read-only lifetime/local revision token with correct invalidation. Measure the invalidation mechanism itself; do not add a large unvalidated cache layer.

Invalidation also covers H, eligibility, stability, short-term resources, fast traces, dormancy/awakening, legal configuration changes and before/after-emission phases. Prefer direct current-scalar access and in-place settlement to a general same-time cache.

An already-settled state can avoid redundant time advancement, not a second legitimate reinforcement, transmission charge or reception. Buffers may be shared physically, but scientific events, source packets and summation order must remain distinct. This phase introduces typed representation and fewer allocations, not new signal-batching semantics.

Stability S is a higher-risk investigation: a mathematically equivalent closed form can still change threshold decisions through rounding. Skipped maintenance can affect event identities, checkpoint anchors, diagnostics and restoration. Begin with observable effects and boundary counterexamples, rather than deleting periodic events. If reliable equivalence is unavailable, preserve current behavior and submit any changed-rule alternative for a separate user decision.

- Against the original `/5` on the same backend, compare complete scientific state, event ordering, internal time and subsequent responses at input/causal boundaries. Preserve existing numerical behavior by default; correct answers or similar final states cannot waive intermediate divergence.
- Cover retained research options, learning/decay ablations, strong stimuli, dormancy/awakening, automatic/manual reclamation, local energy, simultaneous inputs, zero input and deletion boundaries. Test below, at and across thresholds.
- Verify old checkpoint loading, new save/restore, complete peripheral-system continuation, cache invalidation after legal configuration changes, observation frequency, advance batching and arbitrary wall-time waits. Read-only operations cannot settle dynamics by mutation or make forgetting depend on observation frequency.
- Keep strict same-backend references; use existing Python/Rust tolerances for continuous values and exact agreement for discrete decisions. Never loosen tolerances to pass an optimization. Preserve historical `/2`, `/3.1`, `/4` witnesses and saved identities.
- Measure Core advancement, enqueueing, observation, encoding, original-file I/O and restoration separately. Record CPU/memory, graph size and event/settlement/deadline work. Do not silently redefine existing audit fields; add profiling counters to isolated tools rather than masking fields to force state equality.
- Repeat the dense 16–128-node and paired 64–1,024-node fixtures, then vary degree, burst/intermittent activity and active fractions independently of graph size. Alternate order, warm up and collect at least seven timings; extend measurements when noise obscures effects.
- Compare each candidate against the original, previous phase and cumulative build. Require repeatable gains without unexplained regressions, including sparse cases. Preserve evidence and reject candidates that lack equivalence, sufficient benefit or acceptable implementation complexity.

Audit counters require an explicit contract review. Scientific state, event chains, identity, effective readouts and restored behavior must remain unchanged. Fields such as `edge_visits` may legitimately fall if they describe implementation accesses only. Before implementation, list expected differences and verify that dynamics, peripherals, scheduling and restoration do not make decisions from them. Preserve fields, original evidence and comparisons; never silently ignore or redefine them. Unclassified fields remain subject to strict comparison. Saved-format or stable observation-contract changes return to the user.
