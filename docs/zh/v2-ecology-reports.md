# 整组生态实验的记录与报告

生态训练可以直接作为“记录与报告”的固定数据来源。进入某次生态训练，选定种群恢复点，点击“用此恢复点创建记录”；也可以在记录或 AI 草案的来源选择器中搜索生态训练。没有自动启动新的训练或发送外部 AI 请求。

## 两种来源

| 来源 | 一行表示什么 | 默认图表 | 包含范围 |
| --- | --- | --- | --- |
| 生态种群轨迹 | 一个已提交的种群恢复点 | 存活身体、累计出生和剩余身体资源的折线图；数据表 | 指定区间内、修订号不超过所选恢复点的全部提交，保留相同模拟时间的不同提交 |
| 生态全体个体 | 固定种群中的一个个体 | 身体储备和实际后代数的直方图；数据表 | 该点的所有个体，包括未繁殖、身体失效和 Core 已死亡的个体 |

轨迹可选择起止模拟微秒；全部个体来源选择的是完整时点，不能混入其他时点或只留下存活者。显示层可调整指标、图形类型、分组和说明；单个体的原始输入、读出、网络及细粒度轨迹继续使用原来的个体来源。

队列接收采集请求时就固定种群恢复点和完整协议。随后继续训练、再产生后代，或延迟执行采集，不会改变先前已选的来源。重复请求使用原操作编号会返回原来源；同一实验可以使用新编号采集多份独立记录。

## 身体、意识和时间的含义

种群同时存在全局意识时间、个体年龄、个体 Core 时间和物理结算时间。物理已结算到 20 ms、意识只运行到 17 ms 时，来源会保留两个时间及待递送标记，不能把未来身体样本当成已经进入意识的刺激。

`body_alive` 表示该物理边界的身体有效状态；`core_not_dead` 表示 Core 尚未被观察到死亡，其中包含从未被激活的 `waiting` 状态。它们不是相同指标，也不能作为意识存在或意识质量的证明。全部个体行保留原始 `outcome`、具体 Core 生命状态和模型恢复点引用，可以继续核对这些区别。

`observed_age_s` 是全局观察时点减去出生时间，**包含已经死亡之后经过的时间，不是存活时长**。`core_observed_time_s` 是 Core 实际推进过的模拟时间，Core 死亡后不会为了对齐世界而继续增加。身体存活观测的删失标记与 Core 是否已观察到死亡分别保存；停止研究进程、取消任务或观察期结束不被伪装为生物死亡。

身体资源初始输入、再生、剩余和支出属于外部生态账本。剩余量包含全部身体储备和所有资源池库存，包括失效身体与已无活动身体的栖息地。它不是 Core 能量、焦耳、奖惩分数或认知评价。Core 能量指标来自原有独立能量账本；关闭能量模拟或记录无效时保留缺失，不填成零。

`offspring_count` 只统计固定恢复点内已经真实出生的直接后代，不把繁殖意向、暂缓事件或将来出生计入。父本、代数、出生及来源哈希、个体恢复点和全组恢复点均保留在来源行的依据中。

## 图表、AI 与导出

轨迹支持折线、散点、直方图、表格和描述性数值摘要；全部个体分布支持直方图、表格和描述性摘要，不把任意个体编号连成时间曲线。默认加入可核对的图表，图形／JSON 编辑、格式化、校验和保存必验复用已有记录工具。

长轨迹的页面图形使用明确标注的显示分组，完整捕获行保留。样本均值不等于时间加权均值，图形极值带不等于置信区间。共处环境、共享祖先和重复提交不构成独立重复实验；同一生态世界的个体数不能直接用作显著性检验的独立样本量。

AI 接收经过用户预览的固定来源摘要和上述边界，只能生成引用真实来源的文档 JSON，数值由数据库解析。摘要不提供逐点轨迹时，不能从均值和极值虚构振荡、因果、合作意图或道德倾向。解释仍属于待审核文本，规则不能证明任意自然语言断言都正确。AI 关闭不影响训练或原始数据；验证使用本地模拟供应商，没有实际外部调用。

同一个来源可复用于多份记录，也可通过固定记录修订引用到报告。Markdown、HTML、Word 和 PDF 导出复用原来的发布服务，可选携带完整来源 JSONL 与清单。导出文件保持固定修订，不是采集时刻之后的“实时报告”。

## 存储与执行能力

schema 40 在既有来源请求表增加种群及种群恢复点引用，使用项目和种群的组合外键；没有新数据库。采集器按游标分批读取，不恢复或推进脑模型。所有来源行与完成清单在一个受租约保护的事务中提交，整组数量不一致或超出工具预算时明确失败，不保存截断成功结果。

沿用单次 200 万行、512 MiB 标量投影预算；全部个体来源不通过丢弃死亡者规避上限。来源、AI 草案和文档导出任务要求 `worker.ecology_evidence_v1`，只有支持生态运行的旧 worker 不会误接这些新文档任务。旧来源请求的重试指纹保持兼容。

生态资源账本页面默认显示收支摘要与逐栖息地库存，库存每页最多 30 个。后端在 PostgreSQL 中去除详情响应的完整 `accounts` 和 `pools` 数组，避免先在 Python 解码再删除；单独接口按固定恢复点分页取库存。完整账本仍留在原恢复点与证据包中。这减少 API、浏览器和 Python 的每次刷新负担，不代表 PostgreSQL 读取大型 JSON 值或 Runtime 历史账本已变成恒定成本。

接口为 `POST /api/v2/projects/{project}/report-sources`，类型 `ecology_trajectory` 或 `ecology_members`；用 `ecology_id` 和可选 `ecology_checkpoint_id` 选择来源。库存分页接口为 `GET /api/v2/projects/{project}/ecologies/{id}/resource-pools?checkpoint_id=...&after=n29`。这些是观测接口，不改变输入、Core 连接或选择规则。

验收范围见[冻结验证记录](../benchmarks/2026-09-07-ecology-reports-validation.json)。运行、出生与恢复原理见[生态训练](v2-ecology.md)；独立部署见[无界面生态 Runtime](v2-ecology-runtime.md)。
