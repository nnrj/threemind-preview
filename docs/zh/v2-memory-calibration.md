# 记忆机制校准内核 continuous-memory/2

本版本保留 `continuous-memory/1` 全部机制，新增一个独立、创建后只读的参数 `novelty_mode`。新状态标识为 `threemind.continuous-memory-state/2`，假设绑定 `threemind.hypotheses/continuous-memory2`。原有四类内核、定义及快照仍可直接恢复，不能靠修改版本字符串转换旧意识。

## 新颖性指什么

沿用 Git `97d8592:core/threemind/runtime.py` 的局部公式。新连接接触原有邻域，而且端点存在弱而非零的联想触达时，获得一次小幅出生增益：`gain × max(0, 1 − min(1, reentry / reference))`。这不是对内容有趣、重要或陌生程度的语义评分；孤立新连接、零传播不算新颖性，强再入达到参考值也没有这项增益。

- `immediate`：保留当前出生时立即计算的顺序，与 memory/1 动力学等价（版本和新增诊断信息除外）。
- `arrival-window`（新建默认）：出生时冻结“是否已有邻域”、增益、参考量，以及当时排定的下一传播时刻加延迟作为截止时间；在这个窗口累计端点真实接收的联想触达。到达事件先处理，然后结算一次增益。公式不变；不预读未来，不以直接刺激冒充联想。

等待期通过节点到待结算连接的局部索引更新，不为获取输入新增全网扫描。断连／删点撤销该连接的待结算项；再次生边获得新序号。时钟、待结算量、序号和计数随完整状态保存，跨 Python/Rust 恢复后保持一致。结构遗传清空这类短时状态；完整快照不清空。等待期间显式关闭可塑性或静默相关节点／边，会在结算时取消增益。增益／参考量修改只影响之后出生的连接，已经开始的出生窗口保持自身参数；`novelty_mode` 需要新建意识才能改变。

两种模式的 `novelty` 指标区分出生数、没有原邻域、关闭增益、没有再入、达到参考值、获得增益和被取消。`requested_bonus` 是公式产生的量；`weight_bonus`、`stability_bonus` 仅用于延迟模式，表示结算时经上限后的实际增量。不能把立即模式这两个零诊断值误认为公式没有生效。

## 强刺激与遗忘

没有另造强刺激公式：旧额外巩固项仍是 `intensity_gain × max(0, intensity − 1)`；强度 1 不触发额外项，普通首次／重复巩固仍然存在。新增说明和校准使用 0.4、1、1.5、2、4，记录饱和与实际耗能。是否更容易形成长期影响，需要观察而不是由参数名字判定。

遗忘实验分别关闭权重遗忘，以及权重、稳定度、节点支持度的慢变化，保留其余机制。300 模拟秒没有可靠的人类寿命换算；应与激活、资源恢复、痕迹、稳定度和遗忘自身的时间常数比较。

## 校准后的默认选择（2026-09-30）

[786 实例校准报告](../../lab/explorations/2026-09-29-mechanism-calibration/report.zh.md)记录了增益、零结果和完整对照。新建意识采用 `continuous-memory/2`＋`arrival-window`；原始基线、memory/1 和立即模式保留。新颖性两种模式的校准都使用易化时间常数 1 秒；该比较没有改变新建默认的易化参数（仍为 0，即关闭额外易化），不能把报告中的增益百分比当成任何配置下的保证。

修改传播周期、延迟或增益只影响后续出生窗口；已经出生的连接保留其截止时间和参数。这样的显式研究干预可能让既有窗口没有实际再入，结果就是零增益，不能为了保持预期结果延长窗口。

新创建的 UI、API、CLI 与内核定义使用当前默认；模型恢复始终使用保存的身份和配置。缺少 `kernel_id` 的历史 RunSpec 和 ecology-job/1 仍解释为 causal/9。传入明确的 Python `Config`／`MemoryConfig` 仍分别创建 causal/9／memory/1；只有未指定身份与类型的新创建才选择当前默认。用户已保存的项目默认配置不覆盖。
