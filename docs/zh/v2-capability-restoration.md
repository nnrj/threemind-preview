# 功能完整性审计与恢复安排

**2026-09-08 状态更正：功能完整性尚未通过验收。** 本页阶段表保留实现历史，其“已完成／已交付”不能作为旧机制完整保留的结论。后续[动力学与行为核查](v2-kernel-behavior-audit.md)列出 41 项内核事项、19 项相关事项和 55／60 项字段对照；除普通意识默认持续运行的修复外，其余缺口待用户审阅决定，暂不继续改内核或 UI。

本清单记录第二代实施中“完成了新路径测试，却没有核对旧能力覆盖”的验收缺口及后续修复。当前交付和验证状态以下表为准；后文保留各阶段当时的验收结果。新内核已验证的时间、状态、存储能力继续保留；旧功能有研究意义就必须恢复，不能以“界面重构”为由消失。

核对范围为项目核心假设、架构边界、时间传输、空间实验、能量/抑制、遥测、多模态、时序读出、实验调试、统计与归档文档，以及 `core/`、`adapters/`、`services/`、`legacy/ui/src/` 与 `src/` 的实际代码。未读取或扫描 `data/`。本表描述代码能力，不把旧文档中的“已实现”自动当作 V2 的实现状态。

## 新配置的精确定义

`GET /api/v2/configuration` 从实际 `Config` 默认值和 `RunSpec` 约束提供参数目录，当前全部 60 个核心字段都有图形控件，统一目录共 420 项。高级分组支持名称/键/说明搜索；JSON 使用 CodeMirror，提供行号、高亮、折叠、格式化、校验与双向同步，重复键不会被悄悄覆盖。

普通意识暂停并完成检查点后，允许修改可变参数；`step_us`、核心身份种子、初始能量储备、环境/感官种子、初始重放/阶段/干预及实验归属保持固定。环境类型可在暂停后切换，适配器重新初始化，在途事件不被追溯修改；真实环境本来就不能随模型倒流。

参数修改会先以旧参数结算截至当前模拟时间的衰减，再使用新参数。数值格点相位和已排队的事件时间保持原样；新延迟只影响以后发出的事件。相同核心参数的重存是核心精确空操作。参数修改历史与新检查点、新协议、操作者、模拟时间在同一事务提交，版本冲突会拒绝覆盖。恢复后的 worker 从修改后的模型继续，旧检查点保持其原配置。

配置默认值是建模初值，不是已经按人类生物学标定的最优参数。图形化让参数可理解和可使用，不应制造不存在的理论保证。
