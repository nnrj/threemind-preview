# 输入注意、显式调制与递送证据

当前版本说明（2026-09-08）：新建意识使用 causal/8、state/6；旧版本只读导出，不再原版本续跑。下文版本引入与升级说明属于历史记录，当前默认值和局部公式以[V3 恢复记录](plans/v3-restoration.md)为准。

此机制恢复旧版两个注意参数及外部全局标量调制能力。它是感官输入的可选环境选择规则，不提供语义打分，不根据节点标签决定关注什么，不创建先天连接。默认关闭竞争且不安装调制来源时，刺激透明通过。

## 参数与图形入口

| 核心参数 | 默认值 | 约束与含义 |
| --- | --- | --- |
| `attention_competition_enabled` | false | 是否对每个实际递送的感官帧选择有限通道 |
| `attention_budget` | 28 | 0～100,000 的整数；只在竞争开启时限制每帧通道数，0 表示不通过通道 |

两项都位于新建、暂停参数编辑和项目默认参数的高级分类“输入注意与环境竞争”，与 JSON 双向同步。暂停改变参数不改写已接受的原始帧；尚未递送的帧在其实际递送时使用届时有效的参数。显示性能档位不控制这些科学参数。

“感官与输入 → 输入注意”显示最近检查点账本、生效来源、临时调制表单、时间筛选、采样图表和分页记录，提供 CSV、JSONL 及完整调制日志。输入记录的帧详情同时显示原始通道数与通过／抑制数，并保留实际值。

## 按真实感官帧选择

旧版在宿主 tick 收集的输入中选择；新版以**一个带时间戳的感官帧**为选择范围。不同帧即使拥有相同时间戳也保持独立，不能把多个载体或图像 patch 拼成一次共同触达。这是时间架构改变后的显式规则调整，不宣称逐数值复现旧 tick 插件。

若竞争开启，有效通道容量为：

$$K=\min(100000,\lfloor B\,M\rfloor)$$

其中 $B$ 是核心容量，$M$ 为当前容量倍率。选取编码幅度最大的 $K$ 个通道；并列时使用原始帧内顺序，选择后仍保留原始相对顺序。一个帧共有的强度和增益不会改变排名，因此排名直接比较通道编码幅度，避免乘积溢出。零值通道也可能占位；通过通道不等于必然产生激活。

实际帧强度为 $I'=I\,G$。增益为 0 时不通过任何通道；浮点乘积超过有限范围时饱和为最大有限值，并在该帧记录 `intensity_saturated=true`。核心响应、抑制、能量和结构预算在输入选择之后按各自规则处理。

Python 使用有界候选选择，Rust 使用局部选择；均避免为了小容量完整排序全部帧。候选扫描仍有成本，容量不是固定 CPU 时间保证。

## 标量端口与模拟时间

Python SDK 与原生内核均支持独立调用：

```python
engine.modulate_input(
    time_us=10000,
    source="external-device",
    gain=0.5,
    budget_multiplier=1.0,
    competition_enabled=False,
    ttl_us=30_000_000,
)
```

| 字段 | 默认值 | 边界 |
| --- | --- | --- |
| source | external-modulator | 1～128 个字符；只标识外部来源 |
| gain | 1 | 单来源 0～2 |
| budget_multiplier | 1 | 单来源 0～2 |
| competition_enabled | false | 是否显式请求竞争 |
| ttl_us | 30,000,000 | 1～10¹² 个模拟微秒 |

同一来源的最新递送覆盖旧值；最多同时存在 64 个有效来源。多个来源按来源名称顺序相乘，汇总增益和容量倍率各自封顶为 8。竞争由核心开关或任一有效来源的明确请求开启；**增益与容量倍率本身不会开启竞争**。模型内没有按节点身份定向写连接、标签、意义或动作的调制命令。

调制在 `t` 生效，在 `t + ttl_us` 失效，失效端点不包含在有效区间。期限随模拟时间流逝，暂停不消耗期限，加速不需要等待相同宿主时长。读取状态不删除过期来源或改变核心；过期记录可留在恢复状态中，下次实际调制递送时清理。过多有效来源在递送时明确拒绝并记录原因，不静默挤掉其他来源。

Lab 人工表单使用 `manual-input-port`，请求进入命令队列，随后在**命令处理时刻加上至少一个 `delay_us`** 的时间递送。提前提交命令不能保证它在更早时间戳的刺激之前生效。排队响应不是成功生效凭证，以 `input_modulation_delivered` 记录为准；命令、排队时间／拒绝和实际递送均保留。

Lab 接口：

* `POST .../runs/{id}/attention/modulate`：上述字段加 UUID `request_id`、可选非负 `delay_us`。同一请求重试返回原命令；同编号不同内容拒绝。请求在已经结束后仍可查询原成功回执，但不能插入新调制。
* `GET .../attention` 与 `.../attention/export`：按包含端点的模拟时间筛选。`format=csv|jsonl`。
* `GET .../attention/events`：按事件编号分页；`.../attention/events/export` 导出全部已提交调制记录。

冻结实验、终止／死亡实例和已关闭输入的实例拒绝人工端口；只读成员不能提交。真正的远端设备令牌、会话和 WebSocket 协议仍是另一项交付，HTTP 管理端口不能冒充它。

## 原始证据、账本与恢复

Core 观察事件的 `payload` 保持原始刺激，只有注意门实际参与时才附加 `input_gate`，其中保存有效来源、倍率、容量、输入／通过／抑制数和 `effective_stimulus`。Runtime 输入总线保留原始来源关联，向输出读出提供实际通过的刺激；载体的递送首末帧语义不因一个帧全部被阻挡而消失。

数据库 schema 10 在同一个 PostgreSQL 的 `input_frames` 上增加可空 `input_gate`，不覆写 `stimulus`。递送证据、核心、账本和检查点在同一事务提交。历史检查点导出不会提前展示未来版本才发生的选择结果。没有注意记录时，既可能是透明通过，也可能是旧内核不支持；必须结合版本和原始输入解释，不能补造历史。

`attention/1` 账本只累计**竞争开启或存在有效调制来源**时评估的帧及通道。默认透明基线不增加计数。有有效来源但其数值为中性时仍计为参与，以便审计显式安装的外部干预。累计数以 128 位整数保存，对外使用十进制字符串；饱和后设置标记，数值只能视为下界。图表不绘制超出 JavaScript 安全整数范围的精确计数，表格与导出保持原字符串。

新建为 `state/5`、`causal/5`。旧 `causal/1～4` 继续原动力学与格式，默认不自动升级。显式启用注意参数或递送调制端口时升级，保留已有资源和能量账本；缺失账本从升级边界建立，不填补之前历史。旧 4 的冻结控制包含能量和在途刺激／供给，验证原生继续仍匹配原终点哈希。profile/4 不变。

JSON、`.tmind` 二进制工件、独立 SQLite 恢复均保存累计值、来源期限和待递送调制。普通暂停／恢复继续原状态；显式继承为新出生清空临时来源与统计，同时保留继承的连接结构。

独立 Rust 与 Python CLI 都支持 `--modulation-input file.jsonl`，每行是含十进制字符串 `time_us` 的调制对象，无需 Lab 或 PostgreSQL。CLI 依次登记刺激文件、供给文件、调制文件；相同时间戳按登记得到的事件编号处理，已经在模型中的事件保持先前编号。需要任意交错登记顺序时使用 SDK，并保存实际排队后的模型。

此项验证功能、因果顺序、恢复与证据完整性，不据此推断意识、理解能力或 AGI 已成立。空间基底、远端设备、环境身体工具及研究工作台的剩余能力继续按[功能清单](v2-capability-restoration.md)推进。
