# 发育训练与先天版本

这份文档说明单个体发育、先天登记与继承。多代定向筛选见[多代训练](v2-evolution.md)；可配置世界、虚拟躯体及生态选择按[演化方案](v2-evolution-and-world-plan.md)继续实施。训练器是围绕 ThreeMind Core 的研究工具，不是另一套学习内核。

## 使用流程

在「实验与训练 → 发育与先天模型」新建发育训练。默认是 MuJoCo 模拟物理环境、60 模拟秒和尽速时钟；全部 Core／Runtime 参数沿用统一目录，基础参数直接显示，高级参数折叠，支持图形与带高亮、行号、格式化和校验的 JSON 双向切换。

训练创建时，在同一个 PostgreSQL 事务中写入运行、发育登记和普通运行任务。worker 使用现有 Runtime、输入／输出总线、身体适配器、器官、参数修改、观察和证据路径执行；界面可以关闭。点击「观察、控制与证据」进入普通意识详情，可暂停、恢复、查询输入、读出与网络变化，也可以生成研究记录和报告。

训练的初始声明和研究目标不可覆写。后来通过普通入口加入的输入或参数修改继续留在运行证据中；先天登记以**所选恢复点当时的实际配置**为准，不能把初始声明冒充整个过程中未发生变化的协议。

运行有已提交恢复点后，可以「登记先天版本」。也可以检索已有意识并选择历史恢复点。每次选择固定恢复点 ID、状态校验和、形成时间、当时协议及其校验和，并记录研究者的选择依据。同一次发育可以登记多个版本；它们不是被迫覆盖同一模型文件的“最新状态”。缺少当时感官协议的旧恢复点不能猜测补齐；需要先明确配置并提交新的恢复点。

## 出生与继续

完整继续是从检查点恢复原个体的全部状态，包括模拟时间、活动、在途事件、环境和采样进度。暂停及 worker 中断不等于意识死亡。

继承出生使用 Runtime 的纯函数 `threemind_runtime.birth(image)`，规则编号为 `threemind.birth/1`。它不依赖 Lab、数据库、图形界面或宿主时钟，输入与输出都是 `StateImage`。

用 $S$ 表示已形成的结构及慢变量，用 $F$ 表示个体活动与在途状态，出生规则可写成：

$$
B(S,F,t)=(S,F_0,0).
$$

这里保留节点／通道身份、连接端点和权重、支持度、稳定度、触达累计量、空间结构及内核参数。激活、抑制、资格痕迹、直接／联想活动归零；队列、干预静默集合和注意调制归零；资源账本与能量状态按配置初始化，时间与活动事件序号归零。连接的出生／最近触达时间以新个体时间零为基准。感官身份继续沿用先天版本的协议。

这是显式构造**新个体的初始条件**，不是让已死亡的原个体恢复意识，也不表示新个体在没有活动时已有意识。新的空活动状态为 `waiting`，等待其声明的外界来源；后续生命周期仍由 Core 的来源关闭与活动消退规则决定。来源个体及其证据保持原样。

首次继承在普通运行任务的租约内延迟执行。首次提交前进程崩溃，可以从同一不可变来源重复执行确定性的出生；首次提交后，一律完整继续自己的检查点，不能再次出生。证据事件 `development_birth` 保存来源版本、出生规则、来源状态哈希和出生初态哈希；同一次运行不会因恢复产生多次出生。

运行时仍能持续学习。导出或复制初态不会冻结可塑性，是否学习由模型自己的 `plasticity` 等参数及后续刺激决定。

## 先天谱系与存储

发育登记位于同库 `development_sessions`，先天登记位于 `innate_versions`。先天版本引用已经保存的检查点，不额外保存一份全图，也不在每次刺激后改写模型文件。后代登记追溯本次发育所使用的先天版本，其代数表示**登记谱系层数**，不是自然选择已经发生的证明。

直接从已有意识登记时，如果本模块没有记录其此前发育，界面明确展示这个边界；不能编造祖先或训练史。普通模型档案中的运行分支谱系仍可从来源意识查看。

登记内容不可变，需要新的声明时登记新版本。外键与归档清理检查保护来源运行、检查点及其增量链和过程证据。当前提供归档，不提供删除已有发育／先天登记的功能。项目的研究者和所有者可创建，观察者只读；所有查询、登记与导出沿现有项目隔离。请求操作标识防止丢失响应后的重复创建。

## 导出与独立部署

先天版本可按需导出：

| 格式 | 含义 |
| --- | --- |
| `.tmind` | 标准模型本体：出生后的结构／初态和感官 profile，可由独立 Runtime 加载 |
| JSON | 同一出生模型的等价转换，可检查与调试 |
| ZIP | `model.tmind` 与 `manifest.json`，包含来源、协议、选择依据和可追溯谱系 |

出生后的状态哈希通常与来源恢复点的哈希不同，导出元数据同时提供两者。出生规则没有改变 Core `causal/7`、状态 `state/5` 或感官 `profile/5` 格式。

形成清单**不包含原始刺激及完整观测数据**，会写明 `raw_evidence_included: false`。需要论文证据包时，从来源意识另外导出完整过程证据和原始载体。原个体的精确继续模型同样从来源意识导出，不能把出生模型作为精确恢复包使用。

设备部署可以直接使用 `ArtifactCodec.decode` 后的状态建立 Runtime，接入自己的输入／输出适配器，不要求 PostgreSQL，也不要求导入 Lab。Lab 的模型导入仍先形成数据库中的暂停实例，再从数据库启动。

## 自动演化与世界工具

2026-09-07 用户确认：首版计划扩大到**自动多代筛选**，并支持通过上层协议、适配器与图形工具构建世界及虚拟躯体。此前架构评估将种群演化后置的范围判断已被此次决定修订。单个体发育与手工登记不是完整演化训练器，不能以当前页面替代后续交付。

规划分层为：

- Core：匿名刺激、激活、可塑结构与生命周期；不依赖物理引擎或 Three.js。
- Runtime：时钟、输入输出总线、适配器生命周期；可无界面运行。
- 世界／躯体协议：声明几何、物理属性、感官与执行器映射，物理环境有独立可恢复状态；AI 只能提出受校验的协议。
- 训练器：冻结发育与评估协议、调度个体、记录外部筛选依据、保留候选版本与谱系。
- 图形工具：编辑世界和躯体，观察物理状态、感官、激活及演化进度；关闭页面不改变模拟输入或科学时钟。

已接入的定向筛选要求研究者显式配置指标、方向和环境，并固定评估副本与候选父本隔离的边界。它不暗含“活跃度越高即意识越好”；AI 世界和训练计划也不能凭空给 Core 添加语义连接。生态选择及世界工具仍单独验收。

`RunSpec.seed` 固定感官通道、执行器映射和躯体过滤身份；高级配置中的 `environment_seed`（环境随机化种子）可另外指定模拟身体的初态／外力相位或合成环境的随机过程。留空时沿用 `seed`，保持此前行为。继承出生保持 `seed`，允许新后代使用不同的 `environment_seed`；同一实例创建后两个种子均不可修改，恢复使用已记录的环境状态。切换到人工等其他来源时保留此配置，但不据此产生额外刺激。

配对实验仍由独立区组种子列表管理，基础配置中的 `environment_seed` 必须留空，避免多个区组意外复用同一个随机环境。多代训练可为固定感官身份声明独立的发育／评估环境计划。不要把更换时钟或重复同一固定环境称为独立实验样本。直接遗传网络与未来基因式发育配方的区别，见[自动演化方案](v2-evolution-and-world-plan.md#遗传载体直接继承塑形网络)。

## 验证

具体实测和边界记录在 [验证记录](v2-validation.md)。发育阶段检查独立 Runtime 出生、图／JSON 配置、事务回滚、旧 worker 能力拒绝、选中历史状态、项目权限、谱系、暂停恢复与三种导出往返。自动定向筛选另见其阶段记录，自定义 3D 世界仍须各自验收，不能由发育检查推断已完成。
