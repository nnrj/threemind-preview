## 可归档、可导入、可续跑分别验收

正式 `data-bundle` 采用有类型的目录和依赖清单，覆盖全部研究资料，并按项目、实验、意识、批次／数据集及时间范围等维度选择导入导出，阶段和类型可参与筛选。管理 UI、REST、CLI 与 Agent 共用同一协议、权限、目标解析和操作收据，不能各自另存一份权威记录。

归档及重导入资料、还原已支持的原生记录、通过已支持恢复器完整续跑，是三个独立能力。未知外层包 schema 拒绝正式导入；已知包内未知对象 schema 保留原字节并只读登记。缺恢复必需依赖或没有恢复器的资料可保真归档，但不能声明完整包或完整续跑能力；仅缺可选资料须明确限制。完整恢复必须覆盖 Core、个人外围权重和学习状态、读出历史、身体与环境、映射、随机状态及相关输入，保留版本身份和时钟；不能用 Core 单独保存替代整个个体。

导入、迁移和打包提供程序接口。CLI 的人工删除沿用预览令牌与名称确认；Agent 可预览清理，实际删除仍保持人工边界。资料导入不授权运行未知代码、替换旧个体或启动教学。

## 七项配套补强纳入本期

1. 检查归档的完整依赖闭包，包括语言外围，并接入已支持的专用验证器／恢复器；缺恢复必需依赖时保留资料归档，禁止完整恢复与续跑声明。
2. 为实验包上传暂存补齐取消、过期、继续上传及清理预览；已被证据引用的原件不按暂存删除。
3. 外部证据固定存储目标修订、对象键和哈希，必要时固定 S3 对象版本；去重限定在项目内，保持不可变与引用保护。
4. 备份清单同时包含数据库快照、外部对象、代码版本及密钥安全保管要求；恢复验证在隔离环境进行。
5. 任务冻结目标和策略修订；稳定主机 ID 与重启后 worker ID 分开，领取任务依据真实目标的可达能力。
6. 容量审计分列逻辑量、实际占用、暂存、缓存和可回收量；完整性哈希扫描由用户手动发起。
7. 外部 I/O 有界，避免长时间占用数据库事务，并使用有界本地缓存；缺失对象阻塞或报错，不能返回空值、重置个体或跳过刺激。

这些是批准的实施要求，不是已经验证的功能。后续交付须分别报告保真归档、原生记录还原、完整续跑、权限/引用保护和容量完整性验收；清理缓存不等于可以删除原始证据。工具总表新增 [T10](../../plans/research-backlog.md)，与已有 T03/T05 联结。此前 `/4` 的保持阴性结果及 E64/E65/E66 证据不由本期存储计划重新解释。
