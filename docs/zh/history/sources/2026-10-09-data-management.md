## 用户决定摘要

用户首先要求评估：将误提交的实验产物移至正确数据位置并排除 Git 跟踪，清除有关 Git 历史，检查同类情况，并考虑类似聊天记录的可配置外部数据目录。其后同意同时处理其他类似误提交资料，允许新增修订版，在修订版开头说明路径修订原因，原报告字节及原链接保留。

后续讨论批准统一数据管理及正式 `data-bundle`：UI、REST、CLI、Agent 共用接口；全部研究数据可归档并重导入资料，已支持类型可还原原生记录，已支持恢复器可完整续跑。未知外层包 schema 拒绝正式导入；已知包内未知对象只读，缺恢复必需依赖不能宣称完整包或完整续跑，可作为资料归档。资料导入、原生记录还原和续跑能力分别声明。数据包使用有类型的条目与完整依赖闭包，支持按实验、批次／数据集及时间范围等维度选择导入导出，阶段和类型可参与筛选。

用户同意将七项补强并入本期：完整归档依赖检查；实验包上传暂存生命周期；外部证据不可变保护与项目内去重；跨后端备份清单及隔离恢复验证；冻结任务目标/策略修订、稳定主机 ID 与真实可达能力；容量/完整性审计；有界 I/O、缓存及缺失对象明确失败。

本期实际搬迁仅针对误提交实验产物，其他迁移能力只开发测试；Git 处理先本地、不推送。迁移、导入、打包提供程序接口；CLI 人工删除保持预览令牌加名称确认，Agent 只预览清理。最新请求是更新计划，因此本轮不实施代码、迁移、删除、历史重写或服务操作。
