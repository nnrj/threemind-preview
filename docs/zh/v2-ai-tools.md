# AI 供应商与外部研究工具

AI 是 ThreeMind 周围的工具，不属于意识内核。供应商协议、网络凭据、提示词与费用不会进入模型本体或 Runtime 参数。AI 环境生成器只能通过普通感官输入形成刺激；外部解读不回灌模型；实验助手只能提议已注册的受控命令。

供应商与请求基础设施（D3a）以及环境调度、解读器、实验助手（D3b）均已接入。意识详情的“AI 工具”包含环境刺激、外部解读、实验助手、请求记录四个入口。工具使用独立配置及历史版本；模型的 419 项科学参数目录保持原样。

## 三类工具与图形配置

默认三类工具均停用，分别选择供应商。页面默认图形配置，高级区折叠；右上角可切换整份工具配置的 JSON，使用行号、高亮、格式化、严格校验和双向同步。保存始终重新校验，不依赖用户先点击校验。项目研究者和所有者可以编辑；观察者只读。

| 工具 | 基础参数 | 折叠高级参数 |
| --- | --- | --- |
| 环境刺激 | 开关、供应商、自动生成、情境、间隔（默认 12 s）、输入强度（0.7） | 宿主／模拟调度时钟、间隔随机化及种子、不规则程度（0.65）、单条字符上限（2,000） |
| 外部解读 | 开关、供应商、周期启停、间隔（30 s）、语言 | 时钟、结构复现触发、复现附带活跃节点、人工刺激时序读出触发、背景活跃结构监听、读出去重、激活范围（0.08～1）、节点（200）与已记录连接（400）上限 |
| 实验助手 | 开关、供应商、语言 | 步骤（100）、刺激次数（20）、文本总量（20,000 字）、模拟推进（60,000,000 μs）、单次刺激（2,000 字）上限，以及沙箱受限自动执行许可 |

工具配置允许运行中改变；只修改某一类工具时，只取消该类尚未完成的请求，其他工具的调度、发起者与在途请求保持独立。配置有比较并交换版本检查，旧页面不会覆盖新保存。每次自动调用使用最后修改该工具的研究者身份；该成员被撤销权限后不会借其他工具的编辑者身份继续调用。

## 环境刺激的因果边界

生成器只收到情境、强度、不规则程度和文本长度上限，不收到模型状态、读出、节点或研究者对内部意义的解释。返回的完整文本必须先通过长度、运行状态、文本感官、来源策略和受控计划互斥检查，再作为 `ai-environment` 原始载体进入普通 InputBus。依然按字符感官分帧、竞争和递送，不能直接写节点或连接。

“已接收”是输入载体回执，不能冒充已经完成递送。详情可跳到载体与逐帧记录核查。生成内容和回执在同一事务提交，重复作业确认不会重复输入；事务失败不留下半条刺激。全部输入已关闭、意识终止、冻结研究或独占计划正在执行时，工具不会绕过这些边界。默认物理环境保持不变；AI 情境是用户显式选择的外部实验条件。

## 调度、触发与时间

自动调度保存在数据库，由 AI worker 检查。宿主时钟使用实际经过时间，模拟时钟使用最近已提交的模拟进度；二者都不修改内核时钟。随机间隔由意识 ID、工具种子和已排队次数确定，范围为基准间隔的 0.5～1.5 倍，最短 1 秒。

每类自动工具最多保留一个在途请求。模拟加速跨过多个周期时，只为最新已提交状态生成一次，记录合并周期数，不向过去补造刺激。网络响应按实际接收时刻进入总线；宿主时钟受暂停、线程调度和供应商延迟影响，不宣称硬实时精度。

周期任务只在运行／排队状态发起；已产生的人工刺激、结构复现和背景活跃结构触发按索引游标排队，可在暂停状态完成观察。启用触发从当前游标开始，不自动对所有旧记录收费重放。终态停止创建自动请求；已有原始读出仍可手动选择解读。

结构复现与背景触发依赖结构读出已启用并实际记录；人工刺激触发依赖关联的时序读出完成。来源分类来自实际输入／读出索引，不按相邻时间猜测。前一次调用失败会保留错误和原始记录，不悄悄重发。下一次独立周期或触发是新的请求。

可选去重比较所提供的采样值、读出摘要、所选节点与连接，忽略记录 ID 和绝对窗口时刻。它用于省去重复观察的调用，不代表两个意识等价，也不能当作跨时间一致性的科研测量。关闭去重可保留每次独立解读。

## 历史证据与分析

手动解读和分析可按恢复点名称搜索、翻页并固定历史版本，默认在请求受理时固定最新已提交点。筛选同时限制模拟时间和提交修订；同一模拟时刻后来提交的数据不会泄漏进早期证据。

快照包含恢复点身份、哈希、最近最多 32 个已记录采样、最近结构／时序读出，以及显式选定计划最近最多 50 个边界内已完成操作。旧采样若缺失提交修订，明确省略并标注未知，不推测回填。空数据不是零激活；限量和覆盖说明一起冻结。

周期解读使用整体摘要。手动、人工刺激及背景解读可附带按激活筛选的节点，结构复现是否附带节点由开关决定。连接只来自已记录的结构读出内部边，不把它冒充内核全图。计划“当前状态”单独标注为请求时的管理元数据，不能误认为历史回放状态。

外部解读保存原文和证据引用，不回灌模型。分析要求严格 JSON：摘要、带来源引用的观察、解释、其他解释、结论、后续建议与信心等级。未知来源、重复键、无效类型和格式会拒绝应用，保留供应商原文。服务器验证引用真实存在，无法据此保证 AI 的推论正确；所有分析均标记未审阅。没有允许 AI 提交或覆盖原始数值的入口。

## 受控计划与人工修订

实验助手从普通暂停意识的稳定边界提议计划，不能在请求期间静默覆盖新到达的命令。只接受注册命令、指定执行模式、预先配置的预算；不存在任意代码、文件、网络或人工造边指令。生成请求与应用结果之间再次核查运行、权限、工具及供应商版本。

默认生成后保存待确认计划。用户可查看原协议、明确开始，也可使用已有图形／JSON 计划编辑器复用为修订版本；修订保留来源计划和 AI 原始调用引用。原冻结提议不覆盖。

人工逐步模式每次执行一个步骤；确认模式在用户开始后执行有限计划；受限自动模式须在工具设置中显式允许，并且对象必须是明确分叉的暂停沙箱。计划由原有受控执行器运行，文本来源为 `ai-debug`，等待、暂停、回执和恢复沿用相同命令总线。完整生成、计划落库和可选排队在同一事务中，不会产生“计划创建了但来源回执丢失”的半完成状态。

## 设置与权限

“设置 → AI 供应商”分为项目供应商、平台共享、请求记录。支持多个供应商，云端和本地服务使用相同界面。基础字段为名称、协议、基础地址、模型、API Key 和启用状态；高级区默认折叠，包含超时、输出上限、温度、流式响应、配额、单价和 HTTP 代理。没有隐含的默认模型或备用供应商。

项目所有者管理自己的配置；研究者可调用；观察者只读。平台管理员可配置共享供应商并逐项目授权。共享授权不允许项目成员读取或修改平台密钥，平台管理员身份也不自动获得项目内研究权限。调用前、调用中检查发起者的有效项目身份及供应商授权，撤销时中止请求。

新增配置默认停用。编辑时 API Key 和代理密码不回填；空白表示保留，清除使用独立选项。校验错误也不会回显提交的凭据。协议、模型或凭据更新会增加供应商版本，已排队请求不能偷偷改用新版本，会明确拒绝；调用记录保留原公开配置。

## 请求协议

| 协议 | 请求与完整性要求 |
| --- | --- |
| Chat Completions 兼容 | 默认使用 `max_completion_tokens`，兼容旧服务时可明确选择 `max_tokens`；流式使用 SSE，可独立关闭 `stream_options.include_usage` |
| OpenAI Responses | 使用 `max_output_tokens`、`store=false`，接受完整文本消息；流式要求 `response.completed`，并核对最终文本与收到的增量一致 |

温度默认不传，以兼容不接受此参数的模型。HTTP 地址可以是基础地址或对应协议的完整请求路径。客户端不会跟随重定向，也不会自动继承宿主代理环境变量。代理必须在供应商配置中明确指定；HTTP 代理可代理 HTTPS 目标，支持单独的用户名和加密密码。

请求包含系统和用户文本，最大 200 KB。单次文本响应最多 2 MiB，完整 SSE 载体最多 8 MiB。超时同时约束连接、持续读入与总耗时。取消会中断等待响应的连接；已经发送的请求可能仍被供应商计费，页面不会把取消当成费用退款。

只有正常完成的非空文本才可交给后续工具。截断、拒绝、工具调用、不完整事件、格式错误及流式最终文本不一致都会保留已收到的部分内容并标记失败。这里没有启用模型的 function calling、代码执行或任意网络工具。

实现按 [Chat Completions 参数说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)区分两种 Token 上限字段；Responses 的完成事件依据 [OpenAI 流式接口说明](https://developers.openai.com/api/docs/guides/streaming-responses)。服务商的兼容程度仍应通过本地界面的真实连接测试确认。

## 数据库、队列与恢复

全部记录仍在同一个 PostgreSQL 中，schema 18 增加以下表：

| 表 | 职责 |
| --- | --- |
| `ai_providers` / `ai_provider_grants` | 公开配置、加密凭据、平台项目授权 |
| `ai_calls` | 冻结提示、证据引用、配置版本、响应、用量、状态和取消请求；按项目行级隔离 |
| `ai_reservations` | 跨授权项目的供应商配额与费用预留；不含提示或凭据 |
| 既有 `jobs` / `workers` | 新增 `ai` 队列，继续采用租约和提交栅栏 |

schema 19 增加 `ai_run_tools` 当前配置、`ai_tool_versions` 历史、`ai_tool_schedules` 非秘密调度索引及 `ai_call_checkpoints` 精确证据引用，并为计划保留 AI 调用／修订来源。原始恢复点受外键保护。不存在第二个数据库、文件模型定时改写或自制持久化日志。

AI worker 与模拟 worker 分别领取任务和计算并发容量。一个长时间运行的意识不会占用 AI 请求的执行位置，不需要额外 MQ。工作站启动器默认启动两个模拟 worker 和两个 AI worker，可分别用 `THREEMIND_MAX_ACTIVE_JOBS` 与 `THREEMIND_MAX_AI_JOBS` 调整。Docker Compose 增加独立 `ai-worker` 服务；可按所需并发增加副本。

同一请求 ID 只代表同一份内容。丢失 HTTP 确认后重试原 ID 会返回原记录；内容变化必须用新 ID。发送前先提交 `sent_at`。若 worker 在发送之后、完整结果提交之前崩溃，接管者标记为“结果不确定”，不自动再发。这可能保守地把实际上尚未发出的请求也标为不确定，但能避免重复费用与重复外部刺激。完整结果已经入库而作业确认丢失时，重试读取原结果。

调用记录按游标分页，列表不加载整段提示和响应；详情可以查看输入、返回文本与证据，JSON 导出保存完整记录。原始调用不是经过人工审阅的研究结论。归档清理预览计入相关 AI 内容；清理后保留不含内容的费用回执，避免删除意识变成绕过配额的方法。

详情只首次读取冻结提示和证据，随后轮询轻量状态及返回文本，直到校验／应用结束。供应商完成与工具成功应用分别显示；取消、配置变化或应用拒绝不会伪装成成功刺激。工具配置有分页历史与全量流式 JSONL 导出，每次调用可导出包含原始提示、范围、响应与应用结果的 JSON。

## 配额与费用

记录与报告现在也使用同一供应商、预算和请求队列，按显式选择的固定来源生成新的待复核文档。详见[研究文档 AI 生成](v2-research-ai.md)。它没有意识运行入口，也不应用输入刺激或实验计划命令。

供应商待处理上限同时计算排队和发送中请求；每日数量统计按 UTC 当日已受理的请求，包括后来取消的请求。平台共享供应商的授权项目共用供应商配额。数据库事务和供应商锁使并发受理也不能跨过同一配额检查。

输入和输出单价以美元／百万 Token 填写，默认未知；免费本地模型可明确填 0。启用月金额预算须同时填写两种单价。提交前按文本 UTF-8 字节数、消息开销余量和输出上限预留费用；这不是实际 Token 测量。完成后用供应商返回的输入／输出 Token 数结算估算费用，缺失用量不会伪造为 0，已发送而用量未知的请求保留预留额。未发送即取消或拒绝可结算为 0。

账单可能包含服务商特有计价、缓存或其他开销，ThreeMind 的估算不能替代服务商账单限额。它的作用是使当前实验调用的配置、已知用量和不确定部分可查。

## 部署凭据与网络范围

凭据使用 [Fernet 认证加密](https://cryptography.io/en/latest/fernet/)，只用于小型秘密，不用于加密整份模型。`THREEMIND_SECRET_KEYS` 保存部署加密钥，位于忽略的 `.env` 或部署秘密配置中，不在数据库中。工作站启动器在缺失时自动生成；所有服务器 API 和 AI worker 必须使用相同的钥匙列表。

备份数据库时另行安全备份部署加密钥；只有数据库备份无法解密供应商密码。支持 MultiFernet：逗号分隔，新钥匙放在第一位，旧钥匙用于解密旧记录。保存配置会以第一把钥匙重新加密；旧配置全部重新保存前不能移除旧钥匙。接口从不提供导出解密凭据的功能。

工作站允许用户指定本地模型与本地代理。服务器模式要求部署者在 `THREEMIND_AI_ALLOWED_ORIGINS` 中明确列出信任的目标及代理来源（协议、主机、端口）；路径不作为来源。没有通配许可，不允许普通项目用户借供应商地址随意访问服务器内网。部署者只应允许自己信任和控制的服务来源，公网出口策略仍由部署环境管理。

已有 Compose 配置可执行 `python scripts/init-compose.py --ensure-ai-key`，只补充缺失的加密钥，保留现有数据库密码。不要将展开秘密后的 Compose 配置打印到聊天或提交到 Git。HTTP 代理实现依据 [HTTPX 官方说明](https://www.python-httpx.org/advanced/proxies/)。
