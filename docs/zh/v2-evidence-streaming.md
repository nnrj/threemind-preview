# 历史观察与完整证据导出

模型与证据的导出继续按用户请求生成。运行过程中不反复写模型 JSON；数据库中的恢复点、输入载体和研究记录是 Lab 的权威存储。本批没有新增数据库、消息队列、文件日志或数据迁移，Core、模型格式与科学参数保持不变。

## 证据必须固定到提交边界

历史证据不能只按模拟时间筛选。后一次提交可能包含较早时间的记录；如果只比较时间，导出的旧版本可能混入后来才出现的数据。

`observations.csv`、主事件文件、分类读出文件、统计摘要及动力学图同时使用两个条件：`time_us <= checkpoint.time_us`，且已知的 `commit_revision <= checkpoint.revision`。输入仍依据逐帧排队和实际递送版本重建当时状态，不用今天的递送结果替换历史状态。

未记录提交版本的采样和事件不会被猜测归入某个恢复点。所选时间范围内的这些行分别保留在 `unscoped-observations.jsonl` 和 `unscoped-events.jsonl`；不计入该恢复点的统计或图形。`manifest.json` 的 `commit_boundary` 标明规则、恢复点修订和数量。产物列表同步显示这些数量；旧产物没有这项元数据时，不追溯宣称其边界已经核实。

已知属于后来修订的行不进入这份历史包。源记录不被删除或修改。未知版本文件保留的是可核查的原记录，不能据此认定其在所选恢复点已经存在。

## 流式打包与存储

事件、器官输出、结构与时序读出、输入载体和感官帧逐批读取，不先载入整段历史。JSONB 载荷由 PostgreSQL 转为有效 JSON 文本，头部字段正常编码，逐条写出；不把大载荷反复解析成 Python 对象树。中文、转义、空值和大整数保持 JSON 含义。

数据库读取使用 Psycopg 行／小批流。支持 libpq 17 及以上的分块能力时每批读取 8 行，旧 libpq 使用单行模式。每份 ZIP 成员的压缩写入缓冲不超过 1 MiB；ZIP 暂存最多使用 8 MiB 内存，超过后落入系统临时文件。最终产物按 4 MiB 数据块写入同一个 PostgreSQL。临时文件在成功或失败后关闭删除，不成为另一份模型主存储。

驱动流在查询期间独占自己的连接。任何压缩写入异常都显式关闭各层迭代器，再回滚事务、归还连接；不依赖垃圾回收来释放查询。采用的接口及中途关闭规则见 [Psycopg Cursor.stream](https://www.psycopg.org/psycopg3/docs/api/cursors.html#psycopg.Cursor.stream)。已验证版本为 Psycopg 3.3.5、libpq 18；官方仍将该 API 标为实验性，依赖升级需重跑中断和有界读取验证。

每个成员逐块计算 SHA-256 和实际字节数，写入证据清单；ZIP 使用 ZIP64。工件的元数据与所有数据块在同一事务中提交，读取者不会看到半份文件。开始写入先检查作业身份，提交前再次锁定并验证 worker、领取代数、状态及真实当前时间下的租约。上传期间不长期锁住作业行，另一连接可以正常续租。读取失败、租约过期或领取代数变化时，整份未提交工件回滚。

## 历史图的条件查询

普通历史图先读取恢复点的小型身份信息；修订未改变时直接返回 304，不再解码完整模型。空间图第一次仍须读取并验证实际空间参数；服务进程最多缓存 256 份小型投影头信息，随后未变更的条件请求不再恢复全图。

缓存键包含项目、意识、恢复点及状态哈希；每次仍在 PostgreSQL 中核对项目隔离与恢复点身份，参数非法也不能因命中缓存而得到 304。缓存不保存完整模型、节点或连接，重启后重新建立。

## 实测范围和剩余成本

使用隔离的 PostgreSQL 55439，生成 20,000 条、每条 4,096 字节的可压缩事件，共 78.125 MiB 载荷；模型仅 2 个节点、2 个数值采样。每个版本在新 Python 进程测量，先初始化模型和绘图库。基线使用提交 `3b0db4d` 的旧导出 worker，两个版本共用当前数据库工件写入接口。

| 单次工程测量 | 旧导出 | 本批导出 |
| --- | ---: | ---: |
| Python 跟踪峰值分配 | 334.11 MiB | 9.00 MiB |
| 同次测量的进程 RSS 峰值增量 | 309.77 MiB | 25.56 MiB |
| 开启分配跟踪的耗时 | 7.90 s | 8.94 s |
| 未开启分配跟踪的耗时 | 3.77 s | 4.72 s |

本批以小幅耗时增加换取事件历史内存的大幅下降。以上是单次合成数据结果，不是吞吐保证；RSS 每 10 ms 采样可能漏掉短峰，Python 分配跟踪不覆盖原生库内存。可用 `scripts/benchmark-evidence-export.py` 重现，`--no-tracemalloc` 单独测常规耗时；脚本不读取 `.env` 或旧 `data/`，只创建并清理带特定前缀的隔离测试数据库。

流式事件读取不等于整份导出具有固定内存上限：单条大型记录、小批载荷、完整模型恢复与编码仍占用内存；数值采样列表仍完整保留，以维持已有积分、统计规约顺序和图形内容。未改变科学采样率，也未把少量显示点冒充完整证据。空间图冷查询、模型增大和采样数量长期增长仍是需要持续测量的成本。

具体测试、故障用例及原始测量见[本批验证记录](../benchmarks/2026-09-07-evidence-streaming-validation.json)。本说明属于性能与证据工具验证，没有增加意识研究结论。
