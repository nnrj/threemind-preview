# 可配置物理世界与虚拟躯体

世界适配器是 Core 外部的工具。它把匿名激活映射到声明的执行器，让物理环境实际步进，再把测量编码为普通带时间戳的刺激。Core 不依赖 MuJoCo、数据库或页面，不接收物体名称、目标标签或预制语义连接。

本批提供单个意识接入可配置世界的基础，支持[AI 辅助世界草案](v2-world-ai.md)。共享种群与独立栖息环境的生态策略、资源与繁殖规则仍是后续工作，不能把本页的物理世界称为已完成的生态训练器。

## 图形工作流

侧栏「世界与躯体」保存项目世界库。新建或编辑时默认使用图形配置：物理与时间、躯体层级、几何体、关节、执行器、感官端口、外力。基本参数直接展示；更细的物理与接线参数默认折叠。右上方的轻量链接切换到带行号、高亮的 JSON 编辑；提供格式化、校验和双向同步。

「校验与预览」检查类型、数值范围、引用、层级环路、端口唯一性及 MuJoCo 模型编译，然后显示初始姿态。预览不运行意识、不制造感官事件。编辑后的旧预览会明确标记；它不会被当作新参数已生效的结果。

每次保存形成不可变修订。可以复制为新世界、查看历史修订、归档和导出 `.world.json`。运行创建时嵌入完整协议，因此世界库之后的编辑不会改变已存在的运行。归档不删除历史修订。世界协议可以独立保存和复用，不混入脑模型本体。

编辑器可直接导入不超过 4 MiB 的 JSON 文件。导入先校验再替换草稿；无效文件保留原有编辑内容。选中眼睛或测距感官时，三维初始预览显示方向辅助线。相机视锥长度仅用于观察；测距箭头表示声明量程，不是实际命中结果。

在世界库选择「配置意识并接入此世界」，可继续调整完整 Core／Runtime 参数再开始。普通新建、发育与多代训练的共用配置入口也可选择「可配置物理世界与躯体」。创建后世界协议只读；需更改时创建新实例或实验分支，不能将新物理状态伪装成旧检查点的精确继续。

运行页「环境与躯体」展示固定检查点中的世界状态、执行器值和原始感官量；可手动选择历史或跟随最新检查点。三维视角仅用于观察。拖动视角、改显示档位或关闭页面，不会改变感官分辨率、物理步长或内核动力学。

## 协议和实际参数

主格式是 `schema_id = threemind.world/1` 的 JSON。版本库保存协议哈希和排除观察名称后的物理哈希。协议只允许已实现的声明式部件，不执行任意脚本、XML include、外部网格路径或插件代码。

几何体支持球、长方体、胶囊、圆柱和固定无限平面。尺寸遵循 MuJoCo 的半长度／半径约定；三维观察器中的平面只绘制有限范围，但其物理碰撞平面是无限的。密度、摩擦、碰撞开关及 RGBA 都来自真实物理协议。颜色会影响 RGB 眼睛，不属于可以偷偷改变的显示偏好。

躯体支持最多 32 层的父子关系。根级自由躯体包含六个自由度；其他部件可声明有限范围的平移或转动关节、阻尼及初始位置随机化。关节轴和姿态四元数须归一化；位置为米，转动关节为弧度。初始随机化必须完全落在关节限位内。力和力矩在世界坐标系施加到躯体质心；数值来自显式协议。

世界物理默认步长 5,000 μs、感官间隔 20,000 μs、`implicitfast` 积分器。感官间隔必须是物理步长的整数倍，包含 1～1,000 次物理步。改变这些参数属于实验条件变更。模型编译或步进告警、非有限状态会明确失败，不将物理引擎自动纠错或重置后的状态当作正常结果。

## 感官与执行器公式

每个感官拥有显式且唯一的端口号 \(p\)，范围 0～4095。端口内部编号 \(i\) 与感官身份种子、接线命名空间派生的 32 位掩码 \(M\) 组成匿名通道：

\[
c = ((p \ll 20) \;|\; i) \oplus M.
\]

这是同一世界内的双射，不靠逐像素随机哈希碰运气避免碰撞。名称不参加计算。端口号与命名空间属于接线身份；更改它们会改变匿名通道。它们不在 Core 内创建连接，只有真实递送的正幅度刺激才可能触达或形成受体。

关节位置和速度按 \(\tanh(x/s)\) 编码，正负值使用该端口的两个独立编号。接触感官累加目标几何体实际接触力向量的模，再按尺度归一化。测距沿局部 +Z；输出归一化距离及命中标记，未命中和超过量程不会伪造为零距离。原始距离及命中事实保留在证据中。

RGB 眼睛朝局部 −Z，通过 MuJoCo 离屏渲染器生成实际像素，按行、列、RGB 顺序将 \(v/255\) 编码。不从 Three.js 观察画面取像素，不使用语义标签代替成像。无界面运行仍承担成像成本；缺少离屏支持的 worker 不接收 RGB 任务，也不会自动降分辨率或改用其他感官。

一次躯体采样中的所有感官通道组成一个共同刺激帧，协议证据标记 `whole-body-sample`。这是外部感官分帧约定；Core 如何从共同触达形成连接仍由现有动力学决定。没有额外根据观察者的语义解释筛除原始激活。

每个执行器对完整的节点激活投影。设 \(a_n\) 为节点激活，\(s_{n,m}\in\{-1,+1\}\) 是由感官种子、命名空间、执行器端口和节点编号确定的外部接线符号，则：

\[
u_m = L_m \tanh\left(g_m \sum_n s_{n,m}a_n\right).
\]

\(L_m\) 是控制上限，\(g_m\) 是投影增益；传动比例再由物理引擎执行。这是人工声明的**固定哈希投影工程基线**，虽然没有语义标签或正确动作，仍不能当作输出选择性由物理差异自然形成的证据。它不创建 Core 连接、不改写原始读出；执行器控制量独立记录。新的研究边界见[具身差异与功能分化预测](embodied-functional-differentiation.md)。

## 时间、检查点与恢复

在意识时间 \(t\) 读取激活后，动作作用于物理区间 \([t,t+T]\)，测量得到的刺激只在 \(t+T\) 递送。检查点可能位于区间内部，例如意识已经到 87,000 μs，而物理已算到 100,000 μs、感官事件仍在队列中。界面分别标明意识时间、物理累计时间和感官递送时间，不把尚未递送的刺激称作内核已知事实。

`threemind.world-state/1` 保存 MuJoCo `mjSTATE_INTEGRATION` 状态、精确整数采样时钟、执行器与感官观测、物理哈希、编译 XML 哈希、引擎版本和 RGB 初始场景校准哈希。恢复时先检查兼容性，再恢复求解器热启动与在途事件；读取和显示不重跑物理步。

RGB 校准不匹配会拒绝精确继续；校准相同也不是跨 GPU、驱动和平台的全场景像素等价证明。精确重现须记录并控制实际执行环境。本机验证范围见阶段验证记录，不能外推为所有平台位级相等。

载体证据保存每次采样的原始感官量、执行器量、编码结果和协议身份；完整物体姿态保存于检查点，不承诺每个物理步的完整运动轨迹。图形界面不会为稀疏检查点插值制造研究数据。

## 独立部署

独立 Python 世界适配器不需要 Lab 服务或 PostgreSQL：

```powershell
python -m threemind_runtime.world_cli --write-example example.world.json
python -m threemind_runtime.world_cli --world example.world.json --model brain.tmind --clock unbounded --until-us 1000000 --store device.sqlite --export learned.tmind
python -m threemind_runtime.world_cli --resume --store device.sqlite --clock realtime --until-us 2000000
```

不提供 `--model` 时从空白 Core 开始。训练后的脑模型仍会在运行时继续塑形；输入模型文件不会被覆盖。只有显式请求才导出模型或通过 `--evidence` 写 JSONL 证据。

可选 SQLite 以同一个事务保存脑状态、Runtime profile 和外部世界恢复状态，保留最近八个恢复点。纯 Core 的 Python／Rust CLI 会拒绝直接继续带外部状态的 SQLite 实例，避免只恢复脑而丢失世界。显式导出的 `.tmind` 或模型 JSON 仍能交给纯 Rust Runtime 接收新的匿名刺激；它不依赖这个世界。

## 资源与研究边界

协议上限为 256 个躯体、1024 个几何体、512 个标量关节、512 个执行器、256 个感官和 256 个外力；RGB 每帧总共最多 786,432 个标量。上限是实现范围，不是对本机实时速度的承诺。高分辨率会增加感官编码、网络塑形、原始证据与检查点成本；尤其应同时检查 Core 节点、连边和传播预算。显示档位不会替用户改动这些科学参数。

生态策略后续默认共享世界，同时支持独立栖息环境。竞争、合作、资源、损伤和繁殖规则都必须明确并实际作用于环境；不把“友善”等名称变成内核奖励或预设连接，也不声称某种配置必然产生人类意识或消除特定缺点。

MuJoCo 接口依据其[官方 Python 文档](https://mujoco.readthedocs.io/en/stable/python.html)和[状态及物理 API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html)。这些工程接口只承担外部世界，不作为 ThreeMind 意识假设成立的依据。
