# 物理遥测、实例执行计量与递送证据

本页描述 V2 的 `physical-telemetry/2` 实现。旧[物理遥测文档](physical-telemetry-sensory-adapters.md)用于对照旧版能力，接口及 tick 单位以本页为准。

## 使用与开关

意识详情 → **感官与输入 → 物理遥测**，可分页查看原始计数、归一化、平滑、升降变化、采样来源及相应输入信封。指标支持名称／键筛选，采样支持宿主、进程、实例范围筛选；CSV 和 JSONL 导出覆盖所选范围的全部已提交记录，展示筛选不裁剪证据。

新建、暂停后编辑和项目默认参数共用三组图形配置，均支持 JSON 往返、严格校验与保存校验。每组含启用、真实采样间隔、平滑时间常数、水平／变化总开关；每个指标含水平／变化分开开关、增益、手动尺度开关及尺度值。共 35 个指标、190 个配置字段。

宿主、进程和实例均可作为额外感官独立启用；默认关闭。图形界面选择“宿主物理遥测”环境时自动启用宿主组并切换实时调度。历史协议只声明 `environment=host` 时补入启用的宿主组；明确写出的 `enabled=false` 始终保留。模拟环境可以在实时模式下叠加遥测。配对实验禁止各条件单独采集当前计算机状态；需要使用遥测时应事先记录并重放同源刺激。

这些开关控制实际采样和递送，不只是界面显示。所有来源显式关闭后停止采集。暂停时 OS 不可倒流；恢复后开始新的采样会话，重置累计计数与变化基线，不补造暂停期间的体验。已经形成并排入 InputBus 的匿名脉冲仍随检查点保存并继续递送。

## 三种计量范围

| 范围 | 指标 | 解释边界 |
| --- | --- | --- |
| 宿主 | CPU 利用率／频率，物理／提交／交换内存，换页／缺页，磁盘吞吐／IOPS，网络吞吐／包／错误／丢包，电池／供电／充电 | OS 汇总计数；不读取网络地址、内容或其他进程文件 |
| 进程 | CPU、RSS、私有内存、缺页、读写吞吐、线程／句柄数，当前运行的调度与内核调用耗时 | 当前 worker 整个进程；包含数据库客户端、租约线程等开销。计时项另有“测量的内核调用”来源说明 |
| 实例 | 线程 CPU 占比、内核调用忙碌占比、平均调用耗时、平均调度迟到 | 仅包围当前实例的 `advance_to` 调用；不包括采样器、观察图表、数据库写入等其他宿主操作 |

当前 worker 一次执行一个作业，API 服务是另一进程。多个 worker 分别采集自己的进程和所处宿主，不把不同服务器的测量合并成一个计算机。共享宿主的跨进程去重采集服务尚未单独建设；采样中的 worker PID、会话、后端和实例归属均保留。

温度、GPU、风扇、SMART、瓦特数不在这些内置指标中；没有可靠探针就不生成这些量。无电池机器、Windows 未公开的系统换页字节和缺页计数等显示不可用及原因。提交内存使用真实 OS 提交计数，不由“RAM 使用量＋交换使用量”估算。CPU 频率有测量而最大频率未知时保留原始 Hz，允许用户提供明确的归一化尺度。

## 时间与编码公式

采样由真实单调时间控制，三组间隔独立，范围为 100–60000 ms。宿主负载导致迟到时记录实际迟到时长，跳过未能采集的间隔，不以重复旧值补齐。仅允许实时调度，避免尽速训练中重复消费同一瞬间的物理数据。

累计计数 $C$ 转为速率：

$$
r_k = \frac{C_k-C_{k-1}}{t_k-t_{k-1}}
$$

首个计数、计数回绕／重置、读数缺失后的首个有效计数只建立基线。不存在的速率不是 0。

探针有真实比例或容量时使用它；网络汇总吞吐使用可读取的活动网卡链路速率之和。没有物理上限的磁盘等指标使用明确标注的参考尺度。手动覆盖只改变转换尺度，不改原始值：

$$
x_k = \operatorname{clip}(r_k / R, 0, 1),\qquad
a_k = e^{-(t_k-t_{k-1})/\tau}
$$

$$
s_k = a_k s_{k-1} + (1-a_k)x_k,\qquad
u_k=\max(0,s_k-s_{k-1}),\quad d_k=\max(0,s_{k-1}-s_k)
$$

$\tau=0$ 时直接取当前归一化值。默认 $\tau=-1/\ln(0.8)$ 秒，使 1 秒间隔下保留旧值 80%；其他真实间隔按同一时间常数计算，不把平滑强度绑死在调用次数上。首次或中断后只有水平，没有臆造的上升／下降。三个非负通道分别乘增益并钳至 `[0,1]`；总开关与每指标开关取交集。

接线使用与文本／视听相同的种子 u32 双射，遥测占独立 receptor 域 `0x3000000 + scope_index*4096 + metric_index*3 + component`。这只是感受器身份，连接仍由实际递送的刺激形成。35 项名称仅存在于观察层，不进入 Core。

一次采样完成后，刺激排到当前模拟时间加该组一个采样周期。记录同时含 UTC、真实单调时间、采集时模拟时间、计划递送时间及实际递送证据。CPU 实例反馈来自已结束的测量窗，绝不影响正在计量的同一调用。慢机器的延迟通过实际采样迟到、调度迟到和递送时间公开，不能把它描述成硬实时保证。

实例计量的分母是实际测量窗时长 $T$：

$$
\text{CPU ratio}=\frac{\sum\Delta t_{thread\ CPU}}{T},\qquad
\text{busy ratio}=\frac{\sum\Delta t_{Core\ wall}}{T}
$$

调用平均耗时与调度迟到按该窗真实调用次数取平均。没有调用时平均耗时不可用；CPU 占比为实测的零累计用时。进程 CPU 另除宿主逻辑 CPU 数，表示整机算力中的占比；不能拿它直接与单线程占比等同。

## 数据与运行时模型

不新增数据库产品。PostgreSQL `events` 中的 `telemetry_sample` 保存原始测量和编码审计；`input_envelopes` 保存该采样的载体关联、算法版本、完整配置及哈希，`input_frames` 保存冻结刺激与递送。它们和内核检查点在同一个事务提交，中途失败整体回滚。006 只增加分页索引。无正幅值刺激的采样也保留零帧信封，并标为已处理。

普通因果事件列表不默认加载大块遥测载荷；物理遥测专页采用游标分页。显式按 `kind=telemetry_sample` 查询或完整证据导出仍保留这些事件。证据包额外提供 `telemetry-samples.jsonl`；不能将最新屏幕上的几项数值当成完整记录。

Runtime 配置升级为 `threemind.runtime-profile/3`，模型 JSON／`.tmind` 包及 SQLite 往返均保留三组配置，仍读取原有 profile/1、profile/2。配置校验在 Python 与 Rust 间共用生成契约并由测试核对。内核状态及其哈希算法没有因遥测配置改变。

纯编码器 `TelemetryEncoder` 可以从给定测量与时间戳运行、捕获／恢复状态，不依赖 OS 或数据库。OS 探针单独位于 `telemetry_probe.py`。Rust 命令行当前验证／保存此配置，直接消费匿名帧；不会凭模型配置自动启动操作系统探针。部署宿主决定绑定什么实际设备。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/v2/projects/{p}/runs/{r}/telemetry` | 按 `scope`、`before_id`、`limit` 查看已提交采样，返回指标名称与当前配置 |
| `GET .../telemetry/export?format=jsonl` | 流式导出完整原始／转换证据；可按 scope 限定采样范围 |
| `GET .../telemetry/export?format=csv` | 每个指标一行的表格，保留缺失值、单位、尺度、信封和提交版本 |
| `GET .../inputs/{envelope_id}` | 查看该采样对应的冻结刺激、计划／实际递送与筛选结果 |

接口复用项目授权和数据库行隔离。JSONL 按 scope 选择包含该组的采样；同一次采样中其余组的上下文保留以便核对，CSV 则仅输出所选组。采样单位、配置版本和原始原因均随导出保存。
