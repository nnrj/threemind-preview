# 自动演化、世界与虚拟躯体实施方案

2026-09-07 用户决定扩大首版训练器范围：包含自动多代筛选，允许用图形工具构造或由 AI 提议小型 3D 世界及虚拟躯体，并在关闭界面时继续训练。本文是后续实施约束，不是已完成功能清单；已经实现的基础见[发育与先天版本](v2-development.md)。

## 分层契约

Core 接受带时间戳的匿名刺激，输出激活和结构状态。它不依赖账号、数据库、MuJoCo、Three.js、编辑器或评价任务。世界和身体可以是纯参数环境、模拟物理环境或真实设备，只要适配器提供相同的时间、身份、输入／输出及来源契约。

Runtime 驱动感官和输出总线。世界适配器执行物理步进，维护自己的物理状态，把声明的感官量转换为刺激，把声明的外部读出映射为执行器控制。外部的感官／执行器映射不应暗中给内核添加连接或语义。名称、颜色、相机位置和研究者的任务解释属于世界协议或观察层。

关闭页面不改变环境、刺激、Core 步长或训练速度。若虚拟眼睛使用像素输入，无界面运行仍需生成相同的离屏图像；它不需要可见窗口，却仍有感官计算成本。不能把自动降低视觉刺激分辨率当成纯 UI 性能优化。显示档位只调整观察传输、显示采样和几何预算；改变科学刺激必须显式改协议并记录。

## F2：自动多代训练与筛选

首先分离环境随机化种子与感官身份种子，保留原有默认行为和旧检查点继续。继承保持感官及执行器身份；不同训练／评估环境能够使用独立随机化，不因随机化而悄悄更换通道身份。

实验配置冻结起始版本、每代规模、代数、发育协议、评估协议、随机化计划、遗传规则和选择规则。2026-09-07 用户确认先采用已塑形网络的直接遗传，同时区分环境选择与人为定向选择。两者是独立配置维度，不能合并成一个“自然演化”开关。

**生态选择**由声明的外部环境决定资源获取、消耗、伤害、生存和繁殖条件。个体能否留下后代由这些条件产生，不由研究者对网络形状或某个排行榜的偏好决定。模拟器仍有明确的环境和繁殖规则；“生态”不意味着没有设计假设。实验期满的幸存者不必自动获得相同后代数，存活和繁殖应分别记录。生态死亡也不冒充 Core 的意识死亡。

2026-09-07 用户进一步确认：生态环境默认使用种群共处的共享世界，同时支持独立栖息环境，通过版本化策略配置。共享世界可以形成个体间直接竞争或合作；独立栖息环境保留各自的资源与生存／繁殖条件，不应被描述为发生了个体间直接竞争。资源再生、获取与分配、损伤、合作交互、繁殖条件和人口边界均属于显式环境规则。不能把残酷竞争设为形成意识的必然条件，也不能用“友善”名称掩盖未实现的交互。研究者可以比较不同环境塑造的行为；环境配置不能保证产生类人意识、善恶属性或消除人类缺点，这些需由独立的行为实验检验，不给 Core 写入道德标签或指定连接。

**定向选择**才采用研究者明确选择的指标、排序方向、聚合和繁殖配额。默认不提供隐含的“意识质量”分数。内核观测指标是实验指标；躯体任务指标是外部表现。两者都不等于意识或 AGI 已被证明。实现顺序可以先完成定向协调器，但在资源、伤害和繁殖机制实际接通之前，不得把定向排序改个名称就称为生态演化。

候选差异优先来自声明的环境与刺激历史。首批不随意重连、拼接两张父本网络或引入预训练语义表示，也不把自动选择写成 Core 内置奖励机制。若将来研究参数变异或结构交叉，应另行声明其理论意义和协议，不能混入当前“刺激塑造连接”的主张。

定向实验每代分为发育、候选登记、评估、选择和后代出生几个可恢复状态。发育的已学习结构构成候选先天版本。用户已确认评估使用候选的独立出生副本，并与下一代继承源分离；评估可以继续学习，但其学习结果不写回候选父本。生态个体在实际环境中获取资源、存活和繁殖的经历属于它自己的发育史，可以按声明的出生规则遗传；另外抽取的测试副本仍遵循隔离原则。

评价保留逐个体、逐环境的原始观測、聚合规则、缺失值处理、排序和确定性的同分规则。失败或缺数据不冒充零分；死亡与后台任务失败分开，后者应使实验进入可诊断的阻塞状态。以相同评估环境比较候选，并保留未入选者的证据，避免只报告获胜样本。

定向选择进一步区分发育、重复用于选父本的筛选评估、最终验证三组环境种子，三组不得重叠。最终验证在最终父本名单固定后执行，覆盖最终一代全部候选，不重新排序、不参与遗传。重复筛选可能适应该评估组，因此不能把筛选成绩当作独立验证成绩。不同种子也不是样本统计独立的充分证明。这一划分参考[模型选择对评估过拟合的分析](https://www.jmlr.org/papers/volume11/cawley10a/cawley10a.pdf)，属于实验设计边界，不改变 Core 学习假设。已实现的定向协调器见[使用说明](v2-evolution.md)。

训练调度复用 PostgreSQL 作业、项目资源额度和 worker 能力匹配。协调逻辑应是短事务状态推进，不能长期占着一个 worker 等待同一额度下的子任务，以免单 worker 自锁。代次和任务身份要确定，重复调度或崩溃不能产生重复个体或重新选择父本。暂停、取消、恢复及并发操作都必须有证据。

界面提供图形协议、JSON 校验、代次进度、候选／父本谱系、个体观察入口、评分表、跨代图表和完整协议／数据导出。既有记录与报告可引用固定评估结果；不能仅留下一个排行榜。

## 遗传载体：直接继承塑形网络

2026-09-07 用户确认默认沿用 `threemind.birth/1`。ThreeMind 不必先建立 DNA 或基因到网络的生成层，才能研究具有遗传差异的种群。当前候选的持久结构本身就是可复制的遗传载体；后代在不同环境历史中产生的新结构可再次被继承。没有差异的复制加上相同、确定性的经历不会自行产生持续的变化，不能用代数增加冒充有利变异积累。

这是一项允许后天获得结构遗传的工程假设，可称为“获得性结构遗传”，不声称等同于地球生物的完整基因遗传。直接复制避免了把学到的网络反推为发育配方，但放弃了研究基因压缩、发育重建和躯体共同生成等问题。当前目标没有要求必须解决这些问题，因此不把基因层设为训练器的前置依赖。

设父本持久网络为 \(H_g\)，其活动及短期状态为 \(A\)，声明的出生转换为 \(B\)，可塑运行过程为 \(D\)，个体环境历史为 \(E_{g,i}\)。后代从 \(B(H_g,A)\) 出生，经过 \(D(B(H_g,A),E_{g,i})\) 形成候选，选择规则决定哪些候选及其多少副本进入后代。这里的差异可以由环境经历与内核可塑性产生，不要求给连接加入独立的随机“突变”。若这种差异来源不足，应如实展示种群同质化，再单独讨论新的变异机制。

当前出生转换保留节点／通道身份、连接、权重、支持度、稳定性、触达计数和空间结构；清空活动、抑制、短期痕迹、待递送事件和临时干预，重置模拟时钟、资源与初始能量。Core 参数作为该规则的固定运行条件保留，不能偷偷按评分改变。它不是整份运行快照复活，也不复制父本的环境位置、躯体运动状态或测试经历；具体字段以 Runtime 的版本化出生实现和验证为准。

默认不按研究者判断筛掉“无用连接”。如果遗传全部持久结构，有害或偶然形成的结构同样会被传递；环境选择针对个体，不保证逐条连接最优。结构规模成本、躯体资源和繁殖成本如要参与选择，必须在协议中明确说明怎样观测、怎样计费，不能隐藏为删边启发式或默认适应度。

基因式发育配方可以作为将来的独立研究路线：遗传的是发育参数或生成规则，后代通过发育与刺激重新形成网络。它与当前直接继承网络回答不同问题，不能只把字段重命名为“基因”就视为实现。目前不默认改变遗传的 Core 参数、不做父本网络拼接，也不自动共同演化躯体。躯体协议与脑模型分别版本化，保留未来研究共同演化的接口。

验证工具应允许比较：继承已塑形网络、每次从共同初态重新发育、相同种群预算下不依表现选择，以及相同总刺激／运行预算的一条连续训练谱系。固定的独立环境组用来比较祖先与后代，并记录全部候选、灭绝、失败、结构差异和分布。评价副本不能成为下一代来源。先建成这些工具，研究实验由明确协议启动；工程验收不会自动转化为意识或演化成功的结论。

相关文献只帮助区分概念：[Hinton 与 Nowlan（1987）的原始模拟](https://www.cs.toronto.edu/~hinton/absps/evolution.htm)表明，即使不直接遗传获得特征，学习也可能改变演化搜索过程；其简化实验不能直接证明 ThreeMind 的网络遗传有效。[数字演化概述](https://alife.org/encyclopedia/digital-evolution/introduction-to-digital-evolution/)区分遗传、差异和选择，也区分外部显式评分与生存／繁殖产生的选择。这里据此作出的工程选择是继续现有网络遗传，并把其效果留给可重复的对照实验检验。

## F3：可配置世界、躯体与图形编辑

世界协议与模型文件分开版本化：描述物体、关节、物理属性、外力、感官采样与执行器映射。Lab 保存不可变修订；Runtime 能从明确的协议文件独立运行同一世界。模型可以离开这个世界，接入其他符合身份及输入／输出契约的适配器。

首批采用现有 MuJoCo 技术栈，通过受校验的声明式协议生成物理模型，不以任意脚本执行充当世界接口。记录协议哈希、物理引擎版本、感官布局、种子和时间规则。世界、躯体和模型各有可恢复状态；必须验证中断继续的物理状态、刺激序列和 Core 结果。

图形工具提供对象／躯体层级、添加和删除几何体、变换及物理属性、关节和端口配置、运行预览。Three.js 呈现同一世界的观察状态；前端布局、轨道控制和显示质量不能反向改变物理事实。模拟引擎的视觉／射线感官也不能被前端摄像机取代。

AI 生成遵循现有供应商、权限、调用与费用审计，只提出符合 schema 的世界／躯体草案；展示差异、校验问题和可编辑预览后，由用户明确采用。AI 的任务解释或物体名称不会送入匿名通道，除非用户明确选择语言或其他感官刺激。

## 验收边界

- 关闭全部页面，后台多代训练仍完成；相同协议与种子可重放，物理版本变更不伪装成精确继续。
- 图形与 JSON 编辑双向同步，全部字段均来自实际协议；无实现的参数不能只放一个开关。
- 评估副本与候选父本隔离；选择、失败、同分、暂停和恢复有可查询证据。
- 独立 Runtime 无 PostgreSQL 仍能加载出生模型、运行声明的世界并继续学习。
- UI 观察开关与档位变化不改变刺激序列或 Core 状态哈希；配置科学刺激时则记录新的协议身份。
- 真实浏览器验证桌面和窄屏编辑、3D 预览、状态观察及导出；工程验收数据不作为研究结论。
