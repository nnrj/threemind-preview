# 命名状态捕获

意识详情的“恢复与版本”提供“捕获并命名状态”。它向正在执行的意识请求一个新的已提交恢复点，随后显示具体修订号、模拟时间、完整状态哈希及查询／分支入口。收到请求只表示排队；页面直到收到保存回执才显示完成。

## 图形交互与偏好

默认先弹出命名窗口。名称最多 120 字符，留空时自动生成，可以同时选择保留该版本。取消窗口不提交请求。已暂停、结束或阻塞的意识通过下方“命名与保留”直接编辑已有恢复点；不会为了改名而重新运行模型。

“设置 → 显示与交互 → 存档与命名”包含：

- **捕获状态前询问名称**：默认开启；关闭后直接使用自动命名。
- **自动命名方式**：意识名称与实际修订号，或者加上恢复点的 UTC 创建时间。

自动名字在服务器保存恢复点时形成，例如 `触觉试验 · r18 · 2026-09-07T03:20:00Z`。界面不会预先猜测下一修订号。名称前缀过长时只缩短意识名称部分，保留修订号和时间，使总长度不超过 120 字符。UTC 时间是数据库恢复点记录的创建时间，不是模拟时间或测量时刻。

这些是当前浏览器的交互偏好，不是科学参数。后台自动检查点不会因此弹窗或被批量命名。浏览器存储不可用时当前页面仍可使用，关闭页面后偏好可能无法保留。

## 精确保存与失败

捕获使用 UUID 请求编号，在同一项目内去重。重复确认只返回原请求，内容发生变化则拒绝沿用同一编号。一个意识同时最多有一份未完成的命名捕获，避免重复点击堆积请求。

运行 worker 处理这个检查点命令后，先排空先前的检查点写入，再在明确的因果边界保存状态。名称、保留标记、独立注释历史以及捕获回执在同一个数据库事务中提交。任一步失败都会回滚，不能把名字附到另一份“最新状态”上。命名命令与后面的其他命令之间有提交边界，模型的连接规则、可塑性和时间机制不因此更换。

回执保留捕获时的名称和状态身份。之后在版本列表改名、编辑笔记、取消保留，仍使用独立 m 版本和编辑历史；这些操作不反写最初捕获回执。保留标记遵守现有整份档案清理规则。

响应丢失时可以重试原 UUID；页面读取到同一请求的数据库回执后也能确认成功，不会自动新建第二次捕获。任务恢复尝试耗尽、运行在处理请求前结束，或发起者失去项目编辑权限，均保存明确失败原因，不把旧恢复点假称为本次捕获。已经持久化的命令和请求可在 worker 接管后继续处理。

受控实验计划执行中仍遵守原有控制锁，不允许计划外命令插入；可先暂停计划，或在计划内部使用既有 `snapshot.capture` 观察命令。后者引用当时已提交的恢复点，不等同于本页面请求新的保存边界。

## 存储与接口

schema 22 在同一个 PostgreSQL 增加 `state_captures`，关联真实命令、运行任务和恢复点，启用项目行级隔离。它是小型命令回执表，不是另一份模型库，不写模型 JSON 文件，不扫描或迁移旧 `data/`。

`POST /api/v2/projects/{project}/runs/{run}/state-captures` 接受：

```json
{
  "request_id": "由客户端生成的 UUID",
  "label": "",
  "auto_name": "timestamp",
  "pinned": false
}
```

`GET` 同一路径返回按游标分页的回执，可传 `limit` 与 `before`。项目成员可查询，只有具有编辑权限的成员可创建；实际应用命名时再次核验账号与项目角色。查询不展开完整模型。

“导出档案注释”的 JSONL 包含全部捕获回执、当前注释及编辑历史。证据包仍包含所选恢复点的注释快照。可运行 `.tmind`／模型 JSON 保持原格式，用户命名不成为核心参数。清理整份档案会在同一事务删除其捕获回执，现有后代引用、保留标记、冻结研究等保护不变。

升级时停止旧 worker，执行 `threemind migrate` 后再启动新版本；工作站与服务器使用相同迁移。此次 schema 变化不改变 causal/7、state/5、profile/5 或 419 项科学配置。
