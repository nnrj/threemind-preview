# 时序读出、连续聊天与实验记录

[English](../en/v2-temporal-research.md) · [实施与验收](plans/temporal-chat-restoration.md)

本轮把已有时序读出接入主要操作和记录流程，未修改 Core、感官映射、采样公式、候选选择或收敛判据。时序读出描述一个观察时间段内的活动，不是某个瞬间的最大激活，也不自动等于语言回答。

## 聊天操作

意识网络右侧和“刺激与读出”使用同一个连续聊天组件。输入在右侧，被动读出、时序读出及已开启的独立解读在左侧。没有要求先选择消息类别的主下拉框。正文直接显示外部标签；匿名记录显示原始匿名标识，不由 AI 编造文字。

被动标签按激活强度排序，平局沿用旧版触达痕迹、稳定度及节点编号顺序；关闭排序后按编号展示。时序正文默认取读出器已经记录的科学排名前 7 项；聊天显示设置可以改变项数，0 表示可分段查看全部候选。该项不会修改收敛比较所用的 `comparison_top_k`。同一标签文字去重只作用于正文，不合并节点或删除记录。匿名编号摘要前 7 项用于控制辅助信息高度，完整节点仍在消息内展开。

“完整节点与记录详情”可以按页检查全部节点，包括非候选与零活动。时序表区分窗末激活、窗内峰值和综合得分；“图表与导出”进入完整指标页。输入信封编号只用于溯源，不证明所有同时活动都由该输入引起。

媒体“＋”和耳朵、眼睛、嘴巴、图像读出按钮位于文本框上方，强度和发送按钮在下方。媒体弹窗初始继承当前输入强度。默认 Enter 发送，Shift+Enter 换行；保留已有浏览器偏好。成功发送清空，失败保留草稿；输入法组词不发送。采集和输出开关继续经过运行时确认。

新消息跟随到底部；长消息先展示开头。向上翻阅后保持阅读位置，出现新消息时可回到最新。组件每批 40 条、最多缓存 8 批，只挂载视口附近的气泡。缓存移出不等于记录删除，前后游标可继续取回；不会用去重相似内容来丢弃采样。递送状态单独刷新。显示被动读出开关只隐藏被动消息，时序消息仍保留；其他来源筛选仅影响显示。

## 时序实验

入口：意识 → 时序与截面读出 → 时序观察实验；也可在人工实验 → 感官与探针校准进入。默认选择时序观察，原来的固定窗口校准在另一标签中保留。

1. 选择恢复点，或留空，在提交时固定最新已保存点。
2. 每行填写一句完整探针，设置强度。工具按原感官 profile 编码，不改写句式、标点或映射规则。
3. 默认每个探针独立延续来源的完整状态，继承活动、在途事件及可恢复观察上下文，刺激前等待为 0，学习设置继承来源。没有自动清空活动或关闭可塑性。
4. 高级配置可显式选择重新出生、学习开关、等待及观察参数。图形和 JSON 双向同步；JSON 转图形前及提交时均校验。
5. 完成后查看分类、覆盖时间、曲线、排名、全部节点，下载完整证据 ZIP，或点击“用此时序实验创建记录”。

默认时序参数沿用现有读出器：100 ms 采样、最后一帧实际递送后至少观察 1.2 s、0.8 s 稳定判定段、从首帧起最多观察 12 s。窗口可能因收敛或其他分类提前结束；模型死亡、关闭、预算中断等均保留真实原因。观察结束不会停止来源意识。

预算：每批最多 8 个句子 × 6 个强度，来源最多 2,000 节点、100,000 边、64 MiB；默认墙钟 60 秒，可显式配置至 300 秒；Lab 校准进程上限 2 GiB RSS，证据包上限 64 MiB。达到批次预算后，尚未测量的条目记录为 `not_observed`；已开始但未完成的窗口保留删失／中断状态，不能计为正常完成或零响应。最终包仍超过硬上限时任务明确失败，不发布伪装完整的结果。

## 数据和报告的含义

| 来源 | 一行代表什么 | 主要内容 |
| --- | --- | --- |
| 时序读出：窗口汇总 | 一个窗口或一个明确未观察的探针 | 起止与递送时间、覆盖、分类及原因、收敛耗时、原始窗口数据 |
| 时序读出：节点与排名 | 一个窗口中的一个节点 | 科学排名、得分、活动时长、积分、窗末与峰值、原始节点指标及外部标签 |
| 时序读出：变化曲线 | 一个窗口的一个采样点 | 超基线活动总量和活动节点数 |

持续意识的读出固定到所选检查点的提交版本与区间；独立实验来源固定到已完成实验的结果哈希。曲线必须选一个窗口，避免把不同探针的时间段连接成一条虚构曲线。多种来源可组合进同一份记录或报告，支持 Markdown、HTML、Word、PDF，以及包含完整数据的 ZIP。

`convergence_seconds` 仅在满足收敛判据时有值，其他状态为缺失。峰值不是窗末值；综合排名不是峰值排名。窗口的节点积分来自已记录的离散采样汇总，不能冒充每节点连续波形。多个节点、采样点和继承同一来源的副本并不自动构成独立重复实验。本轮不重跑、回填或修复旧实验；缺少时序观察的旧数据不能补造出时序结论。

## 独立 Runtime 命令行

Python Runtime 主机可使用 Rust 原生或 Python 参考后端，无需 Lab 数据库。`--readouts` 指向一个不存在的 JSONL 文件，保存配置、时序／截面证据及最终观察状态。

```powershell
.\.venv\Scripts\python.exe -m threemind_runtime.cli --model source.tmind --text-input cue.txt --clock unbounded --until-us 15000000 --readouts readouts.jsonl --export after.tmind
```

`cue.txt` 作为一个完整载体，经模型原感官编码。`--until-us` 是该 CLI 作业的绝对模拟截止时间，不是普通意识的默认寿命。截止太早时未完成窗口标记删失。可用 `--readout-config reader.json` 显式配置 `structural_readout` 和 `temporal_readout`。

```powershell
.\.venv\Scripts\python.exe -m threemind_runtime.cli --model source.tmind --text-input cue.txt --clock unbounded --until-us 400000 --store recovery.sqlite --readouts part1.jsonl
.\.venv\Scripts\python.exe -m threemind_runtime.cli --resume --store recovery.sqlite --clock unbounded --until-us 15000000 --readouts part2.jsonl
```

恢复库保存 Core、输入总线及读出器上下文；暂停期间不推进模拟时间。恢复时仍需 `--readouts`。这里只扩展 Python Runtime 主机 CLI；纯 Rust 最小运行程序仍承担其原有的模型执行职责，不宣称新增了同名读出参数。

独立校准 CLI 使用协议 `{"mode":"temporal","cues":["甲。"],"intensities":[1]}`：

```powershell
.\.venv\Scripts\python.exe -m threemind_runtime.calibration_cli --model source.tmind --protocol temporal.json --output temporal-evidence.zip
```

没有 `mode` 的旧协议仍按固定窗口校准解释。模型文件没有 Lab 的观察上下文时，不能凭空恢复训练前基线和外部标签，覆盖情况会如实记录。
