# 物理遥测感官适配器

[中文](physical-telemetry-sensory-adapters.md) | [English](../en/physical-telemetry-sensory-adapters.md)

## 定位与边界

ThreeMind 把计算机的实测运行状态作为意识所处环境的一部分。实现完全位于宿主应用和感官适配器层：

```text
操作系统只读计数器
  → 共享 HostTelemetryCollector
  → 每个意识独立的匿名感官映射
  → SensoryFrame / InputBus
  → Core

单意识 Core 调用的真实线程 CPU 时间与墙钟时序
  → 应用层 _HostObservedRuntime 只读计量
  → runtime-telemetry-field 匿名感官映射
  → 下一采样周期的 SensoryFrame / InputBus
  → Core
```

采集器不读取节点、连接或可读载体；适配器不修改 Core 的遗忘、巩固、联想、抑制、传播、注意或能量规则。物理遥测是感官刺激，不是能量供应，也不会自动启用能量模拟。实例反馈不会把 OutputBus、节点激活或可读内容直接回灌。

## 三种感官

- `host-telemetry-field`：宿主计算机环境，默认开启。采集 CPU、内存、磁盘、网络汇总计数以及电池／交流供电状态。
- `process-telemetry-field`：整个 ThreeMind 服务进程的自体状态，默认关闭，避免未经研究者选择形成自反馈。多意识并行时，它不能解释为某个意识的独立资源消耗。
- `runtime-telemetry-field`：单个意识实例的真实运行代价，默认关闭。它分别计量该实例执行 epoch 时的线程 CPU 时间、忙碌比例、平均执行时长和调度延迟，然后延迟编码为该意识自己的匿名输入。
- `ambient-field`：原随机环境场仍保留，但默认关闭。
- “全部背景输入”是最外层许可；各感官仍有宿主设备开关和模型实例绑定开关。

模型包显式写出 `enabled: false` 时优先关闭。未声明宿主遥测的包按默认开启解析，并在下一次保存、快照、导入规范化或重命名时写入完整配置。当前模型包模式版本为 `3.0.0`；本项目尚未发布，因此不迁移旧实验包。

## 指标与可用性

宿主首期指标包括：

- CPU 总体利用率与频率；
- 物理内存压力、提交／交换空间压力，以及平台可用时的换页速率；
- 磁盘读写吞吐和 IOPS；
- 网络收发吞吐、收发包、错误和丢包速率；仅使用全局汇总计数，不读取地址、连接或内容；
- 电池电量、交流供电和可靠可得时的充电状态。

进程指标包括 CPU、RSS、私有内存、缺页变化、读写吞吐、线程数、句柄数、宿主遥测调度延迟，以及由应用宿主只读测得的运行时 epoch 执行时长。该组指标是整个 ThreeMind 服务进程的观测量，不能冒充某一个意识独占的资源消耗。

实例指标包括：

- `thread_cpu_load`：该意识实例执行 epoch 所消耗的真实线程 CPU 时间占采样区间的比例；
- `epoch_busy_ratio`：该实例执行 epoch 的真实墙钟时间占比；
- `epoch_execution_time_ms`：采样窗内 epoch 的平均墙钟执行时长；
- `scheduler_latency_ms`：运行线程实际开始执行相对于预期 tick 时刻的平均延迟。

这些指标由应用层包装器围绕 Core 调用测量。多意识分别拥有计量窗；操作系统层面的相互竞争只会通过实际时延自然反映，不会被标记成某个实例的独占 CPU 或内存。

温度、风扇、GPU、SMART 和真实功率通过 `TelemetryPlugin` 插件边界预留。只有获得可靠实测值的插件才能启用；不可用值始终带原因，不能伪造为零，也不能从 CPU 利用率推算温度或功耗。

`psutil` 是可选依赖：

```powershell
python -m pip install -e ".[telemetry]"
```

未安装时服务仍能启动，并在 Windows／Linux 上使用原生 CPU、内存降级采集；磁盘、网络、电池和进程指标明确显示为不可用。

## 真实时间、编码和归一化

宿主／进程指标由共享采集器按单调时间采样，实例指标由每个运行时独立关闭自己的单调时间计量窗；默认均为 `1000 ms`，不随意识 tick 或模拟速度变化。多个意识共享宿主原始采样，但利用各自感官种子映射到不同匿名通道；实例原始采样则分别归属于对应意识。

每个连续指标可生成：

- `metric.level`：平滑后的水平；
- `metric.rise`：相对上次水平的上升量；
- `metric.fall`：相对上次水平的下降量。

Core 会把负输入钳为零，因此下降使用独立的非负通道。首次采样只建立变化基线；暂停、禁用、恢复和服务重启后也会重置基线，暂停期间不积压体验。磁盘和网络累计计数先除以真实时间差变成速率；计数器回绕或重置只重建基线。

实例反馈在一个计量窗结束后才生成感官帧，并排入后续输入 epoch，因此不能在正在被测量的同一个 epoch 内同步递归。反馈帧自身引起的真实后续开销可以在下一采样窗被感知，这是显式、可审计的物理闭环。

CPU、内存和电池按物理比例归一化，CPU 频率使用报告的最大频率。网络汇总吞吐优先使用所有活动的非回环网卡链路速度之和；磁盘等无可靠上限的量使用明确记录的参考尺度。每个参考尺度都可在高级设置中显式覆盖，未勾选“手动”时不会盖掉探针提供的物理尺度。

## 配置与运行时管理

适配器管理页面按“可用性／水平／变化／增益”分组显示指标。水平和变化均有总开关与逐指标开关，总开关关闭只停止相应通道，不删除子项配置。模型绑定关闭后仍可预先编辑配置，但不会挂载或投递感官帧。

公开接口包括：

- `GET /api/adapters`：采集后端、依赖完整度、可用／不可用指标、最后采样时间、插件和最近错误；
- `GET /api/consciousnesses/{id}/adapters` 与 `PATCH /api/consciousnesses/{id}/adapters/{adapter_id}`：意识实例级绑定；
- `PATCH /api/background-input`：全部背景输入总开关；
- `GET /api/telemetry/samples`：去重后的全局原始采样；
- `GET /api/telemetry/history`：按意识和适配器查询投递关联；
- `GET /api/telemetry/export?records=deliveries|samples&format=csv|jsonl`：分别导出逐意识投递审计或原始采样；可用 `adapter_id=runtime-telemetry-field&consciousness_id=...` 查询和导出单个意识的实例反馈。

## 审计数据

SQLite `data/telemetry-audit.sqlite3` 只保存一份共享原始采样，并为每个意识保存投递关联；实例原始采样使用 `scope=runtime` 与所属意识 ID 单独归档。记录包含 UTC 与单调时间、采集后端、原始值与单位、可用性原因、归一化／平滑水平、rise/fall、尺度来源、增益、平滑参数、实际匿名输入帧、意识 ID、适配器 ID 和投递 `envelope_id`。实例记录还包含采样 tick 范围、epoch 数、线程 CPU／墙钟累计量，以及该窗内已处理输入信封的非语义关联。重启后仍可分页查询和导出；没有形成正值通道的原始采样也不会从原始导出中消失。

这些数据属于实验仪器记录，不写入节点或连接，也不作为网络动力学输入之外的隐藏反馈。
