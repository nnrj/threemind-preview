# 意识档案、恢复点注释、谱系与清理

“模型与证据”默认展示意识档案库，可按名称／说明、标签、执行状态及归档状态检索。另一子页保留导出文件和后台任务。意识列表和详情均有档案编辑入口；“恢复与版本”提供所有恢复点的分页检索、命名、笔记、标签、保留标记、来源链和直接后代。

## 科学版本与档案版本

`runs.revision` 和 `checkpoints.revision` 标识科学状态提交，记为 r。名称、说明、标签、归档，以及恢复点的注释使用独立的 `metadata_revision`，记为 m。修改档案不捕获新模型，不改变状态哈希、连接、活跃状态、排队事件或模拟时间；已完成、失败或死亡的意识仍可整理。

每次实质修改写入同事务的 `model_metadata_history`，记录操作者、前后值和编辑时间。没有变化的重存为空操作。保存必须提供读取时的 m 版本，防止旧表单覆盖新注释；原参数编辑器中的名称修改也走同一条档案历史，并检查 m 版本。科学参数仍按原来的暂停规则和 r 版本校验。

名称／恢复点标签最长 120 字，说明／版本笔记最长 20,000 字。标签最多 20 个，每个 1～48 字且不重复。标签是研究者注释，不是网络节点已有的语义。读者角色可浏览和导出，写作者可编辑；永久清理只允许项目所有者；管理员身份不绕过该项目的角色边界。

## 版本与来源

每个恢复点仍是完整因果状态的一种数据库表示。完整锚点与有界差量链的恢复规则不变。版本列表以科学修订号为游标分页；注释查询不会展开神经网络或恢复上下文。

新分叉记录精确的 `origin_checkpoint_id`，区分精确继续、继承出生、配对实验分支、导入和空白创建。新配对分支指向共同培养的真实恢复点。父意识、来源哈希和精确恢复点都由数据库关系保护；给恢复点命名不会创建另一份模型。

早期记录可能只有父意识与来源哈希。多个恢复点可能具有相同哈希，因此不根据哈希猜测某个版本，也不补造继承方式。谱系页明确显示缺失信息。祖先链一次最多展示 64 层，并说明截断；直接后代独立分页，可以进入任意一项继续浏览。

## 导出注释

“导出档案注释”以 JSONL 流式导出当前档案、全部版本注释、状态捕获回执和编辑历史，服务端使用游标逐条读取。完整研究证据包增加 `annotations.json`，包含导出事务时的档案和所选恢复点的注释；它们明确是研究者当前的描述，不冒充该实验发生时就存在的事实。文件纳入证据包清单校验。

标准 `.tmind`／模型 JSON 继续只承载可运行的状态与 Runtime 接线配置。整理档案不影响模型本体的哈希和等价转换。若需要同时交换研究者注释，使用证据包或独立注释导出。实验笔记、结构化记录与论文报告仍属于后续 E 模块，不能用这些短注释替代完整编辑器。

## 归档与永久清理

只有已完成、终止、失败或死亡的意识可以归档。归档可撤销，只使其从默认列表隐藏；详情、科研数据、恢复点、导出、谱系和新分支仍可访问。冻结实验的分析仍包括其已归档对象，不因整理列表而删除实验臂。

永久清理以**整份已归档意识**为单位。界面先请求实际计数与引用检查，展示恢复点、输入、观测、事件、设备、上传、生成文件和未共享原件的范围。确认时须输入完整名称；服务端重新检查预览指纹，在同一个事务中执行删除并保存清理回执。以下情况拒绝清理：

- 意识尚未结束或未归档。
- 属于冻结实验，包括共同培养记录。
- 有后代意识引用，或存在“保留此版本”的恢复点。
- 有未完成后台任务，或媒体仍在处理。
- 预览后数据、档案注释或引用已变化，或出现其他外键引用。

这里不提供逐个删除差量锚点的操作。单独移除历史恢复点可能破坏状态重建及某个时间边界的证据；整份档案清理在检查外部引用后，一次删除本档案的完整链及其记录。任意错误都会回滚，不能留下删了一半的模型。

媒体原件按项目内容哈希去重。schema 15 把输入载体到原件的引用升级为真实外键；同一事务先保存载体、后保存二进制原件，因此约束在提交时核验。清理只回收没有其他载体引用的原件，共享媒体保留。并发引用受数据库约束保护，不靠前端按钮推断。删除不会触碰旧 `data/` 目录；现有数据库的原件引用由 SQL 建立，无需逐件手动迁移。

清理后保留项目内的回执：删除对象编号、名称、最终状态哈希、预览范围、操作者、时间和回收原件字节数。界面可查询清理记录。回收量是逻辑内容字节，PostgreSQL 可能留作后续复用，不宣称删除后操作系统文件立即缩小；日常维护仍由 PostgreSQL 管理。

## 接口与存储

同一 PostgreSQL schema 15 为 `runs`／`checkpoints` 增加注释字段，新增项目隔离的编辑历史和清理回执表，没有引入新数据库。

| 接口（项目／意识前缀省略） | 用途 |
| --- | --- |
| `GET model-library` | 有界档案摘要、筛选和分页 |
| `GET/PATCH runs/{id}/metadata` | 独立档案信息与版本校验 |
| `GET runs/{id}/versions` | 全部恢复点的游标查询 |
| `GET versions/{cp}`、`PATCH versions/{cp}/metadata` | 指定恢复点注释 |
| `GET lineage`、`GET metadata-history` | 谱系和有界编辑历史 |
| `GET metadata-export` | 完整注释流 |
| `GET cleanup-preview`、`POST cleanup` | 先预览、再校验并清理 |
| `GET cleanup-history` | 项目所有者的项目清理回执 |

本批验证范围以[验证页](v2-validation.md)为准。更大网络的读出计算、研究命令与协议编辑、AI 工具、E 的笔记／报告及先天演化训练器仍按[恢复清单](v2-capability-restoration.md)推进。

## 捕获前命名与自动命名（D5b）

运行中的意识可以在“恢复与版本”捕获并命名一个新的实际状态边界。名称、保留标记及回执与恢复点同事务提交；默认弹出命名窗口，交互偏好在设置中切换。schema 22 只新增小型请求回执表，完整规则和失败边界见[命名状态捕获](v2-state-captures.md)。已停止对象仍直接编辑既有恢复点，历史注释与模型哈希保持分开。
