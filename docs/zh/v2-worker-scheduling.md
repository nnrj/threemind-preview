# 执行节点能力匹配与任务回执

本模块管理 Lab 中任务由哪个执行节点领取。它不修改意识参数、模拟时间或模型格式。与[集中执行额度](v2-execution-resources.md)共同工作，仍使用同一 PostgreSQL，不引入独立 MQ。

## 领取前匹配

任务在入队时根据冻结协议计算所需能力。普通运行、分析和导出需要意识内核；MuJoCo 环境还需要物理环境依赖；已启用且未被来源策略关闭的宿主机、进程、运行时遥测分别需要对应采集能力。关闭相应来源或背景总开关时，不要求闲置的采集能力。共同培养任务根据实验基础协议判断，随后生成的每个条件运行仍单独匹配。AI 和通知邮件各自使用独立队列及能力键。

执行节点先报告实际依赖，再在领取事务内检查能力集合。缺少能力的节点跳过该任务，继续寻找它能执行的任务；不会把不适用任务领取后反复报错、耗尽重试次数。未报告能力的节点不能领取。遥测的“部分可用”允许执行，具体缺失指标仍按原有遥测协议记录，不能填 0 冒充真实观测。

能力报告描述依赖可用性，不代表具体供应商凭据、设备授权、模型预算或输入有效。原有运行时校验继续执行。节点没有自动切换数值后端或替换物理环境的权利。

暂停后的协议修改会刷新仍待领取任务的需求；恢复及实验条件等直接 SQL 入队路径也受数据库触发器约束。正在执行任务的领取条件保持原记录，不追溯改写。

## 页面入口

“设置 → 执行队列与额度”可查看当前项目的任务。管理页面可选择项目查看调度元数据。意识排队时，其详情页直接展示等待原因。默认只列待处理和执行中任务，可勾选“包含已结束任务”查看历史；每页最多 50 条，使用时间与任务编号组成稳定游标。

| 原因 | 含义 |
| --- | --- |
| 等待来源恢复点 | 捕获屏障未完成，尚不能开始处理来源数据 |
| 额度为 0 | 部署或项目明确暂停新领取 |
| 无可用执行节点 | 最近 90 秒内没有在线、启用且满足能力集合的节点 |
| 额度已满 | 已有有效租约占用了部署或项目额度 |
| 等待领取 | 已观察到基本执行条件，等待节点下一次领取 |
| 租约过期 | 原执行节点失去租约，等待恢复或达到重试上限后的失败处理 |

页面原因是查询时的观察，不是位置预留或即将启动的承诺。在线时间采用数据库时钟，避免 API 主机与数据库的时钟差异造成误判。诊断只读取有限任务元数据、活跃队列计数和在线能力报告，不读取模型正文、刺激正文或科学采样。项目成员不能借此读取其他项目的任务；平台管理员的调度查看权限不自动赋予模型访问权限。

## 每次领取的证据

领取任务与保存执行回执在同一事务中完成。回执含任务编号、租约代次、节点编号、所需能力、当时的实际能力报告、明确的内核后端和领取时间。回执写入失败时领取也回滚；节点重新报告依赖或另一节点接管，不会覆盖早先回执。

“查看执行回执”展示最多五次领取，与当前重试上限一致，并可按需导出 JSON。AI／邮件无内核后端，界面显示“不适用”。旧版本已结束任务没有这一记录，显示历史未知，不凭当前机器配置补造旧事实。

worker 使用本进程持有的能力报告参与匹配及回执保存，避免显式同名节点覆盖注册表后，使另一进程按错误能力领取。部署仍应使用唯一节点名；同名会影响在线状态和管理辨识。运行时依赖变更后需重启节点重新检测。

领取及续租使用数据库实际时钟；等待事务锁的时间不从新租约的 60 秒有效期中扣除。租约代次继续阻止旧节点覆盖新节点结果。停用节点的状态在取得节点行锁后再次检查，已确认停用不会被此前的未锁定读取绕过。

## 升级与范围

schema 24 增加任务需求字段、维护触发器和受项目 RLS 保护的执行回执表。仅更新当前待处理／租用任务的小型需求元数据；不扫描旧 data，不重新计算已结束实验，不迁移测试模型。升级前停止旧 API 与 worker，运行 `threemind migrate`，再整体启动新版。旧 worker 不能与严格能力匹配版本混用。

能力匹配不建立不同数值后端、硬件和依赖版本的等价性，也不保证恢复到原来的物理宿主机。实际后端与节点必须作为研究执行条件审查，原始恢复点中的实现清单仍需保留。当前连接数据库的 worker 是受信任部署组件；本模块没有把它变成可向任意第三方分发数据库凭据的公共算力平台。托管资源隔离和分享另行实现。
