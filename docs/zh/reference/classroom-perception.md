# 课堂视觉与指向工具

这些是研究外设，复用现有输入、输出总线，不改变 ThreeMind 内核动力学。初始验证见 [E56 计划](../plans/vision-correction.md)；工具可用不等于意识已掌握所有课堂任务。

## 视觉采样

`lab/tools/classroom_eye.py` 的 `DetailedClassroom` 使用协议 `threemind.grounded-classroom/2`，允许每个固定视场采用 4、6、8、12 或16个横纵采样点。每点传递深度与 RGB，四个视场同时保留场景中的四个对象。MuJoCo 光线测量产生输入；观察界面的物体图标不是送入内核的视觉。

4×4配置沿用旧通道和输入量。更密配置使用另一组匿名端口，每通道增益为 `0.03 × 16 / resolution²`，使固定视场总增益不随点数增加。它仍会改变实际空间采样、通道数以及局部入射量，不能称为完全相同的刺激。身体位置、速度、接触、风、温湿度、惯性和重力支撑的端口与物理规则继续沿用旧世界。

`state()` 与 `restore()` 保存、恢复分辨率和物理状态；旧 `/1` 世界不升级。仅改观察标签不会改内核刺激。更高分辨率可能增加节点和连接，需先估算计算与存储。

## 选物和移动分开

两类外部读头均读取总线上的原始激活、抑制、直接触达、联想触达过程，不做无提示副本相减或逐题幅度归一化。训练时允许教师给标签，实际选择时没有问题原文、对象名称或正确坐标参数。

- `ActivityController`：把已登记端口的活动一起读入，输出四个位置分数。
- `SpatialChoice`：按眼睛外设本来就有的四个物理视场，把**同一个读取函数**分别用于四块视觉活动；每块同时看到相同的其余端口活动。没有为 Core 指定脑区，也没有在意识状态中增设物体标签。协议为 `threemind.spatial-choice-reader/1`。

后者利用了已知的眼睛布局，是外设的结构选择，不能冒称这套分工由 Core 自行演化而来。任何读头都可能凭自己的监督训练解决部分任务；准确率提高后仍需检查是否依赖 Core 的经历与内部连接。

读头选定端点后，独立伺服器用实际身体位置、速度控制移动，只得到**读头所选位置**，不会得到评分用的正确位置。因此分别记录“选对没有”“有没有抵达所选位置”“有没有抵达请求目标”。这能定位选物与执行的故障，也意味着伺服技能本身不是意识新学会的能力。

有界课程、校准、纠错、独立验收、原始过程与回放命令见 [E56 操作说明](../../../lab/explorations/2026-10-06-vision-correction/README.md)。不同意识来源、纠错分支、分辨率分别保存；不覆盖旧快照。回放标示每帧的控制来源，避免将风力或教师示范误认为意识自己发出的运动指令。
