# continuous-memory/3.1：零响应节点局部回收修复

日期：2026-10-11。按用户决定新增 `/3.1`，保留 `/3` 原行为，并核查 `/4`。这是工程行为修复，不是正式教学实验或保持效果对照。

## 缺口与行为边界

`/3` 先为正输入创建节点，再经过能量及响应门控。能量耗尽时，节点和保持锚点已经存在，实际响应却为零；原代码只有正响应才登记节点回收期限。保存能成功，但恢复时重新核验局部期限会拒绝该状态。普通闲置不会补期限。

原最小见证使用初始能量0.05、直接响应成本0.2，时刻0输入两个通道0.7／0.6。第一节点响应0.25，第二节点响应0；两后端原状态哈希均为 `ba7714ed08fbb9283098a36101cbcf57aadc45294ea257e25f82489614d16fd6`。保留该见证及原恢复失败，不能以加载时补事件、放宽校验或改写旧检查点掩盖。

修复会改变异常分支的结构演化：零响应节点按照已有回收规则接受局部失效判定，满足条件时删除。因此后续节点身份及连接形成也可能受到影响。它不是纯粹的保存功能修复。没有更改普通有效激活、传播、权重学习、H／D公式及参数；零响应不获得支持度、活动剂量或半衰期增益。

默认静默死亡宽限下，原最小案例在2.26模拟秒死亡并停止推进；不能将它描述为默认运行100秒。长时回收工程用例显式把宽限延长到200模拟秒，仅用于独立测试副本，不改仓库默认或旧个体。
