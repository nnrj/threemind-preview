# 平台层级、意识工作台与授权实施验收

实施日期：2026-10-11。本交付追加实施与测量事实，原五章计划、历史建议和原实验资料保留。未开展正式新实验，不改变 Core／Runtime 动力学、默认内核版本或旧个体。

## 实现

- 默认首页恢复意识工作台，提供新建、只读打开、图像及属性／文本刺激／感官面板。导航按工作台、研究、资料、系统与帮助分组。系统页面独立于项目；旧研究工具迁入独立项目详情，资料筛选不会替换整页功能。
- 新建默认和命名模板分版本保存。项目预设显式选择，草稿不被项目切换覆盖。默认创建并准备，不创建引擎、任务或假检查点；首次开始与准备态编辑检查并发版本。旧调用缺省仍立即开始。
- 平台登录、多角色、具体动作与资源范围、超管全量资料访问及限定委托统一进入后台服务。普通角色仍受项目和私人资料授权约束；菜单隐藏不能替代后台授权。认证不进入 Core 或检查点。
- 平台 AI 目录保留旧服务身份、修订、密钥、授权和费用关系。配置管理与付费调用分别授权，诊断不要求虚构项目；研究用途还须具体科研动作权限。报告、普通工具和校准不再复用 AI 调用权限。
- 邮件运输服务与项目事件／收件人规则分开，旧策略和待发送队列不重写、不重发。全局铃铛汇总本人有权访问的通知。
- 浏览器会话、受保护的非交互客户端配置、限时委托和后台运行分别处理。主动退出默认继续运行；可以选择有暂停权的非受管实例，确认暂停后退出。已受理但尚未确认的暂停重试仅查询。过期、断网和关页不自动暂停已接受运行任务。
- CLI、MCP 和 Python 共用 REST 保存服务。凭据按 origin 和配置隔离，Windows DPAPI 加密，不保存密码；无凭据时非交互报错，不退回匿名超管。认证和账号管理不作为普通 MCP 实验工具暴露。

## 显式本地迁移

先在独立数据库实际建立 schema 65 的旧私有供应商、加密密钥、完成调用、通知历史与待发送队列、私人笔记及账号关系，再执行 66／67。原身份、密码哈希、密文、旧调用、通知及笔记全行保持；重复迁移无重复服务或版本。

确认真实库无待运行／已租约任务及其他连接后，保存受影响配置快照 145,101 字节和 schema 定义 363,691 字节，再显式升级 **65 → 67**。这两份是小型配置回退证据，并非重新复制大型原件的全库备份。既有完整备份与历史原件不由此删除。

未逐件重新读取大型 Core／媒体原件计算新哈希；本次无相关写入代码，核验的是上述逻辑记录和已保存科学哈希。迁移回执及配置快照在忽略目录 `.work/t14-migration/`，不得提交 Git；用户日常服务未由本任务启动或接管。

旧 AI 编辑历史缺失不补造：新版本记录的 `current_import` 操作者来自原 `created_by`，`call_snapshot` 来自原请求者，不能当作该修订的实际编辑者。`saved` 才记录新保存行为。邮件运输导入来自旧项目策略快照，也不倒推缺失编辑历史。

## 日常使用与回退

沿用原启动命令即可，首次打开按页面设置平台密码。默认账号身份保持，密码由用户选择，本任务未生成或打印它。之后 AI 使用一次初始化的受保护配置或限定委托，见[访问说明](../platform-access.md)。

新 API、worker 和新构建 UI 必须配套使用，旧服务需由其操作者正常重启。本任务不自动接管用户进程。系统默认、模板和平台服务更新不能重新初始化旧意识。

迁移失败事务不会提交；成功后的 schema 回退须在停止相关写入并确认新资料依赖后显式处理。配置快照只覆盖本期受影响元数据，不能单凭它恢复整个数据库。不要直接删除新表或把数据库版本号改回 65。
