# 原始海洋：从摄食机会到环境选择

日期：2026-10-03。状态：实验与外部工具已启动，完成情况以 E28 报告和研究总表为准。

## 为什么改用这个环境

E27 的24个体都未完成机械臂颗粒转移，没有任务供能和后代。用户提出从容易获得第一份营养的躯体开始，而不是把任务动作提示写进内核。原实验保留；新环境只要求实际接触营养，不预设游动方向、不以不动或绕圈作为异常。

本轮核心、遗忘、抑制、能量耗竭和恢复保留原义。摄食与繁殖、外部身体和感官为研究工具；不往 Core 注入“营养是好的”“应该游动”或个体适应度。动力学身份仍为 `threemind.continuous-memory/2`，环境和出生初始化分别用 `threemind.ocean/1`、`ocean-birth/1` 标识。

2026-10-03 身份说明：`ocean-birth/1` 是本研究初始化规则的名称，尚不是快照中的独立字段；实际恢复按 `threemind.ocean/1`、冻结工具源码摘要、Core 版本及状态摘要一起核对。不能把文档名称误认为另有一套已实现的 Core 出生协议。

实现采用二维中性浮力水层：有惯性、黏性阻力、均匀水流、局部营养浓度、接触、运动和姿态感官。物理近似、感官转换及固定无语义运动投影全部显式登记。它不是完整地球生态或真实流体仿真。本轮正式实验最多16个同时存在的躯体，是计算上限，不是生物承载力；超限只推迟繁殖，不能记作自然淘汰。通用工具模板的上限是24，两者不要混淆。

## 能量账本的关键改动在外设

已有生态模块区分身体资源和 Core 能量，原身体失效不等于意识死亡。因此 E28 没有直接把旧生态训练器的身体淘汰计作内核死亡。颗粒接触将食物存入外部身体储备，原有能量接口补充 Core 的实际支出；缺粮如何影响活动仍由原内核决定。

原 `birth/1` 会为新个体给定初始能量。若在封闭资源海洋中无限复制这份能量，繁殖本身就成了供能来源。新工具在出生初态上明确把免费启动量置零，从亲代已摄入的食物扣除后代启动量和繁殖损耗。亲代脑状态不修改，旧出生协议不改；新初态的配置与协议摘要重新绑定。

第二阶段才随机改变身体半径、推力和局部感官范围。完整包裹加短暂持续才算吞食；普通接触不算。只转化可回收的身体食物储备，并有损失。身体消失与意识活动停止分别记录：被吞食个体关闭输入，内核自然推进，证据和快照保留。

## 操作

在项目根目录，用项目 Python：

```powershell
$py = '.work/kernel-venv/Scripts/python.exe'
& $py -m lab.tools.ocean_cli template | Set-Content -Encoding utf8 ocean.json
& $py -m lab.tools.ocean_cli validate ocean.json
& $py -m lab.tools.ocean_cli run ocean.json .work/my-ocean --seconds 900 --wall-seconds 1200
& $py -m lab.tools.ocean_cli verify .work/my-ocean
& $py -m lab.tools.ocean_view .work/my-ocean .work/my-ocean-view.html
```

JSON 配置、Python `Ocean` 接口与命令行运行同一个环境。`schema` 输出完整配置协议。`--resume` 指向含 `manifest.json` 的 `final` 或检查点目录，输出必须是新目录；继续时不能替换协议。检查点中含全体脑状态、出生偏移、环境、随机数状态、食物、储备和谱系；不依赖数据库也可运行。

通用模板用于配置新场景，不等于E28已标定的正式条件。复现第一个意识驱动世界时使用已保存的实际配置：

```powershell
& $py -m lab.tools.ocean_cli run lab/explorations/2026-10-03-primitive-ocean/protocols/phase1-core.json .work/my-ocean-replica --seconds 900 --wall-seconds 1800
```

第二阶段还继承第一阶段存活者的脑状态，不能只打开 `predation` 就冒称复现了本轮第二阶段；完整来源由实验编排及证据包记录。

普通观看用生成的 HTML：时间滑条、播放、各个体与谱系、摄入和储备。它只读实际记录，不控制训练，不向 Core 注入输入。现有平台实验笔记、记录与报告用于查看登记和结论。海洋的专用图形启动/编排表单仍属于后续工作，不能把离线观察器说成完整实时训练 UI。

环境不设置死亡年龄。`--seconds` 是观察长度，仍存活者暂停保存；资源限制、异常中断和自然死亡分别标记。手动停止可在当前输出目录创建 `STOP` 空文件，完成当前采样边界后保存。直接终止进程时可恢复最近完整检查点，未写完 `manifest.json` 的目录不能恢复。

## 依据和判定

正式比较、进入第二阶段条件与资源预算见 [E28 预登记](../../../lab/explorations/2026-10-03-primitive-ocean/design.zh.md)。原4GiB预算在保留完整证据的需要下明确修订为软限6GiB、硬限8GiB；不改实验判据，见 [执行记录](../../../lab/explorations/2026-10-03-primitive-ocean/execution-notes.md)。

生存、繁殖、运动有用、继承有用和形成新物种逐层判定。共同环境比较用同样身体、同样启动能量和接线，把继承网络与空白网络分别测试；不能只凭胜者繁殖较多就宣布学会适应。无性谱系的大小差异不是已经形成新物种，需要稳定遗传分化和生态差别。

## 用户原话

> 就目前的实验结果看，可能是目标太难了，能量摄入条件过于苛刻。意识的训练需要循序渐进。进行一个新的实验方案：
> 模拟一片原始海洋，里面有丰富的营养物质。能量来自这些营养物质，意识有一个类似浮游生物的躯体，若碰到营养物质即完成摄入。除了机械臂换成了浮游躯体，能量摄入变成了触碰到营养物质，其他不变。浮游生物可在原始海洋中自由游走（由意识控制，不事先告诉内核游走这个偏好）。得不到营养的就会慢慢饿死。仍然将环境信息作为刺激传入，未必传入视觉信息，但传入的刺激信息应该足以区分水和营养物质，以及本体姿态等。不设置死亡时间，但一段时间内整体营养物质（能量）上限有限，如果繁殖超过能量供给，部分个体就会因能量不足而饿死。
> 若上述浮游实验获得明显结果。
> 引入竞争机制，引入一个躯体的变异机制，变异是随机的，有可能有利，有可能有害。允许浮游生物摄入彼此，标准是浮游生物把另一个浮游生物包裹起来，即摄入，摄入应有损耗，不是百分比转换。
> 进行适当时间的演化，观察：是否出现优胜劣汰、生成竞争。是否演化出了适应环境的版本，是否出现了不同的物种。
> 我的设想有问题的地方，你可与我讨论或直接纠正。

“不是百分比转换”结合“应有损耗”按不完全回收理解，当前取60%是可配置外部环境条件，不是生物常数。如果用户原意是拒绝固定比例的任何形式，须另行讨论消化动力学，而不把该解释写成用户已指定的数值。
