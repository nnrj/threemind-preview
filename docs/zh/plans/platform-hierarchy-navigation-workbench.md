## 一、核查结论与目标

### 2026-10-11 追加修订：内核、模板和参数层次

用户确认内核版本是上层选择，模板与手动编辑都是配置该内核参数的方式。这是同页层次，不是分步向导。实施本修订；前文原计划及已交付阶段记录保留。

- 明确显示内核版本和简述；内核选择移出普通参数表。模板按核筛选，默认选中该核系统默认模板；研究预设并入模板层，项目归属不替换配置。
- 修复切核后创建来源仍记录旧核、双重切核、跨核同名参数误继承。有未保存修改才确认替换，取消保留草稿，旧请求不得覆盖新选择。
- 一核多模板，支持保存草稿及从实例的已保存参数创建模板；不复制个体、权重、检查点或实验身份。旧修订不改，未来修订不改变模板所属核。
- 所有有真实历史实现的内核允许新建。恢复 causal/1～8 的 Python／Rust 历史实现；旧统一帧内核 unified-associative 原样接入 Python，暂不新增 Rust 移植。旧 UI V1／V2／V3作为该核模板，不虚构三个动力学版本。
- 创建／恢复时利用已有路由绑定实现和规则。历史代码按算法兼容性隔离，可共享兼容骨架；撤回“必须拆成四个 Rust 连续版本对象”的建议，未有实测证明该结构导致退化。
- 保留当前连续家族共享实现和已批准参数开关，只核对身份、算子、配置及状态边界；旧帧、LIF、/4等明显不同实现继续独立。物理拆包、插件管理及深度重构后置，不改公式、默认内核或动力学数值。
- 宿主执行后端存于科学配置之外，仅 Python旧核由匹配 worker执行；不让 native worker误认领，不静默换核。两个后端分别独立运行。
- 验证全部版本新建、同版恢复及冻结行为，核对来源、模板、权限、准备态和观察无副作用。仅工程验证，不启动长期教学；更新双语指南、研究进度及规定历史，本地提交、不 push。

### 产品定位与组件边界

ThreeMind 定位为**本地优先的研究应用，以 Web 提供界面**；云端能力服务于本地内核和研究工作，可选部署为自建团队服务，不要求云端注册。技术上的前后端分工继续存在，但不建设一套独立的后台管理网站；管理功能在同一应用中按权限显示。

| 组件 | 边界 |
|---|---|
| Core | 节点、连接和意识动力学；不认识账号、角色、项目、令牌或登录状态 |
| 独立 Runtime | 可独立构建、安装、发布和运行模型的宿主／库／CLI；本机使用不依赖平台登录或 Lab 数据库 |
| 研究平台 Lab | 用户、权限、项目、服务配置、研究记录和界面；在资源访问和管理操作边界实施授权 |

团队可以访问同一自建平台；分别安装的本地平台是不同部署，通过正式资料包交换资料。本期不承诺跨部署账号互认、实时同步或分布式意识。

按原稿的以下层次重新组织：

| 层次 | 管理内容 |
|---|---|
| 系统／宿主 | 存储、执行进程、后端能力、网络许可、共享服务、平台账号与角色 |
| 用户／设备 | 语言、主题、显示预算、交互偏好、个人通知 |
| 创建默认与模板 | 创建新意识时使用的版本和参数 |
| 研究项目 | 资料归属、成员权限、项目模板、研究规则和额度 |
| 意识实例 | 自身版本、有效参数、感官、身体、状态和完整恢复点 |

**项目从属于本部署的平台，是组织和授权容器，不再是进入系统功能的前置条件。** 创建者、负责人、成员和研究来源继续记录。平台所有权不等于每位用户都能访问全部资料；访问范围由角色和资源授权决定。超级管理员按后续明确决定能够访问全部项目和私人研究资料。

原稿中的“本轮仅核查与规划，未修改文件、数据库或运行状态”描述的是当时的规划阶段；当前阶段以本文件开头的状态说明为准。

## 二、导航与“意识工作台”

### 导航整体重组

| 一级入口 | 内容 |
|---|---|
| **意识工作台** | 默认首页；新建、打开、观察意识及直接交互 |
| 研究中心 | 研究总览、项目、实验与训练、比较、世界与躯体、专项对话实验 |
| 资料中心 | 意识档案与模型、数据查询、记录与报告、笔记、数据管理 |
| 系统设置 | 创建默认、配置模板、设备能力、AI 服务、邮件服务、执行资源、存储、用户与权限 |
| 文档与帮助 | 使用说明、内核与适配器说明、研究历史、CLI／Agent 接口 |

保留现有功能，通过整合、拆分和明确命名消除重复入口。项目筛选只出现在研究和资料页面，不再占据系统页面的全局位置。菜单、页面、功能和按钮按权限呈现；隐藏按钮不能代替后端授权。登录后默认进入意识工作台，不因零项目而改成受阻的欢迎页。

### 恢复门面

“意识工作台”采用播放器式布局：

```text
左侧导航 │ 中央视图                         │ 右侧面板
         │ 未打开：新建意识／打开意识       │ 属性
         │ 已打开：真实意识图               │ 文本刺激与意识读出
         │ 操作栏：开始／暂停／继续／切换   │ 眼睛、耳朵、嘴巴等
```

- 未打开意识时，不自动选取最近实例；最近打开记录仅提供快捷按钮。
- “打开意识”从全部授权实例中选择，只读取状态和图像，不启动、暂停、恢复或复制。
- 已运行的实例显示其真实运行状态；查看它不会改变后台执行。
- 新建默认采用“创建并准备”，另提供明确的“创建并开始”操作。
- 中央视图复用现有图形组件。缩放、布局、冻结画面与暂停意识分别操作。
- 右侧显示实例与选中节点属性、刺激聊天、真实读出、感官和输出控制；高级协议、恢复、事件与研究工具进入详情。
- 空图区分“未启动”“尚无节点”“没有匹配结果”和“读取失败”，不把未测量显示为零。
- 窄屏将右侧面板改为抽屉或页签，保持图像和运行控制容易到达。

### 修正工作台交互

- 分别显示**实例配置是否启用、本次采集是否连接、本页播放是否开启**，避免把“浏览器未连接”写成“意识感官关闭”。
- 页面打开不申请摄像头、麦克风权限，不自动采集或播放。
- 实时采集按现有规则要求“运行中＋实时模式”；条件不满足时提前说明，不自动续跑或改变模拟时钟。
- 修复上传窗口打开前就启用感官的问题：选择并确认发送后才执行所需操作，取消选择不修改实例。
- 离开页面释放本页设备和播放资源，但不自动暂停意识；采集中断原因如实记录。
- 刺激通过原输入服务递送，聊天显示真实保存的读出；外部 AI 解读另作标识。
- 生态、冻结评估等受管对象可观察，但控制仍交给所属实验；不能从工作台绕过限制。
- 查看历史、继续当前实例、历史分叉和导入分别提供操作，完整个体恢复不以 Core-only 包替代。
- 暂停、继续、刺激、干预、恢复、导出等动作分别检查权限。允许看图或暂停不能推导出其他控制权。
- 登录失效、退出或权限撤销不重置、清空、升级个体，也不以退出页面代替暂停命令。后续控制及采集请求重新校验权限，已有运行仍遵守原执行与保存规则。

## 三、配置、服务和资料的拆分

### 创建默认、模板与实例配置

- 增加按内核版本保存的新建默认，以及有名称、稳定身份和修订的配置模板。
- 初始值采用当前内核目录的真实默认；**本任务不改变默认内核版本或动力学参数数值**。
- 解析顺序固定为：内核出厂默认 → 系统新建默认 → 显式选择的一份模板 → 本次修改。项目预设也是显式选择的配置来源，不再隐式叠加。
- 原项目默认保留为可显式采用的项目预设，不再因选择归属项目而自动替换草稿。
- 创建流程先允许查看、编辑参数；保存时明确归属项目，可在流程中直接新建项目。禁止自动选择第一个项目。
- 创建记录保存完整实际配置及模板身份、修订和来源。模板只保存配置，不包含成长后的权重或完整个体状态。
- 已有实例继续读取自身保存的版本、配置和完整检查点，系统默认或模板更新不能影响它。
- 配置目录增加所属层次、作用对象、来源和生效方式说明：仅显示、仅影响新建、暂停后生效、需重启。
- 修正适配器目录误用历史解析默认展示“新建默认”的问题；历史缺字段的解释规则保持原样。

### 系统功能与项目功能

| 功能 | 拆分方式 |
|---|---|
| AI | **统一平台服务目录，取消“项目私有供应商”作为独立配置类型**；服务管理、查看、使用授权与项目／实例／工具选择分开，调用与消费仍关联实际对象 |
| 通知 | 发送服务、个人通知中心、项目事件规则分开；全局铃铛汇总授权通知，不要求先选项目 |
| 执行 | 系统页展示宿主队列与并发；项目页展示项目额度和任务。明确它是宿主调度，不是 Core 能量 |
| 设备 | 系统显示安装、能力和适配器目录；实际接线、令牌及感官控制属于实例 |
| 存储 | 系统管理位置、保存策略、迁移和备份状态；证据完整性和资源清理进入资料管理 |
| 用户权限 | 平台用户、角色及授权在系统管理；项目成员在独立项目详情，不能反向决定平台设置的入口 |
| 工具接口 | 计算能力、操作目录和 Agent 接入说明无需项目；执行科研操作时明确目标和归属，并检查相应操作权限 |

AI 服务的后续讨论决定具体落实如下：

- “项目私有供应商”来自原先按多租户服务划分配置的思路，不是导入项目必需的业务类型；本期统一为平台目录与资源授权。
- 同一供应商可登记多个连接，使用不同账号或密钥。不因地址、模型名或供应商品牌相同而自动合并。
- 已有服务身份、修订、加密凭据、历史公开配置、调用和费用关系保留；原项目范围转为授权来源，不自动扩大普通用户的使用范围。
- 有服务查看权限的用户不再因服务原先存于某项目而看不到；是否能管理或调用由各自权限决定。超级管理员能查看、管理全部服务，密钥明文仍不回显。
- 项目、实例和工具选择获授权的服务及调用参数，不各自另造供应商管理体系。平台级服务诊断不为通过接口而虚构研究项目。
- 正式项目／模型资料包不携带平台账号、密钥、会话和授权关系。导入不自动创建供应商或按名称绑定源平台服务；需要调用时，明确绑定本部署可用服务。

既有项目凭据**不自动变成对所有用户可用的共享资源**。通知拆分后，原项目发送服务仍只授权原项目；历史规则、通知版本和待发队列保留，不因迁移重发邮件。超级管理员的全平台管理权与普通使用授权分别落实。

### 平台账号、角色与权限

- 平台默认提供登录界面和记住会话；复用现有认证与会话能力。登录策略与本机／网络部署访问范围分开，不能因有登录便自动开放局域网。
- 保留现有 `local` 用户的稳定身份及资料关系，通过本机首次设置完成密码初始化，不内置通用默认密码，不新建另一个身份造成旧资料失联。
- 内置超级管理员、管理员、普通用户；超级管理员可创建角色并授权，一个用户可绑定多个角色。支持菜单、功能、按钮所对应的具体操作权限及资源范围。
- 每个授权同时表达“什么动作＋哪些资源”。多角色合并不能把一个角色的查看范围与另一个角色的写入能力交叉组合成额外写权限。
- 超级管理员按用户明确决定访问**全部项目、个人笔记、附件和私人资料包**；普通管理员不自动取得全部科研资料，普通用户与自定义角色按明确授权访问。
- 本部署尚未正式发布，现有使用者为用户及协助工作的 AI；无需为不存在的旧用户设计兼容告知或并行旧权限模式。保留作者、创建者和科研来源身份，不因此改写历史。
- REST、CLI、MCP／Agent、下载、导入导出及后台任务的操作边界共用后端授权。聚合查询也按权限过滤字段和对象；不能只靠菜单隐藏，也不能用一个笼统写权限放行全部控制动作。
- 保留最后一个有效超级管理员，限制越权授予；角色、成员和权限变更可追溯。服务凭据继续加密，界面只展示脱敏值、是否已配置和明确的更新操作。
- 超级管理员是应用管理角色，不等于数据库超级用户；不豁免证据修订、冻结对象、版本冲突、个体连续性、引用保护及受管实验的控制边界。
- 显示偏好本期保留为本浏览器偏好，在共享浏览器中按登录用户隔离；不宣称已经跨设备同步。

### AI、脚本与命令行的非交互实验渠道

- AI 与人工采用相同的实验接口、权限规则和研究记录要求。用户在对话中明确授权的普通实验，应能通过 REST、CLI、MCP／Agent 或 Python 客户端连续完成，不要求改用人工页面逐步点击。
- 对话中的任务授权与服务端认证分开：聊天指令不会自动成为登录凭据。AI 使用用户明确授权的账号，或绑定该账号的委托身份；记录授权主体及 AI／脚本执行来源，不默认新建拥有全局特权的 AI 账号。
- 提供统一的非交互认证入口和受保护的可复用命令行会话；允许使用可撤销、限定操作及资源范围的委托凭据。一次初始化后，后续客户端自动携带所需会话／令牌及 CSRF，不在每个实验步骤重新索要密码。
- 在 Lab CLI 提供认证的登录、状态查询、退出及委托凭据创建／撤销渠道；REST、CLI、MCP 和 Python 共用解析与授权。命令名称属于新增接口，不把本期尚未实现的认证命令写成已经可用。
- 浏览器的“记住会话”不等于命令行已经认证；不偷偷读取浏览器 Cookie。宿主显式配置的现有账号／密码渠道可继续兼容，新增受保护的凭据存储或会话引用，避免让密码经聊天、命令参数、日志或 Git 传递。
- 委托权限不能超出授权账号实际权限；角色、项目授权变化及账号停用／委托撤销及时生效。会话续期仅在仍有效的授权内进行，不能通过续期扩大范围或绕过撤销。此认证状态不进入 Core 或科学检查点，不随研究包导出。
- CLI／Agent 提供明确非交互模式。缺少凭据、会话失效或权限不足时返回清楚的错误及恢复入口，不停在密码提示，不静默使用本地超管身份，不绕过接口直接写库；正常交互 CLI 可以保留明确的人工登录流程。
- 明确授予完整实验所需的创建、控制、刺激、训练、观察、恢复、实验登记、报告／笔记、证据关联和结项权限，并保留各动作的科学前置条件。普通实验在授权有效期内无需每一步再次人工批准；超出原任务授权或涉及真正敏感操作时另行处理。
- 逐项复核 MCP／操作目录的“只能人工操作”硬编码。不能仅因执行者是 AI 而阻断普通实验及记录保存；凭据、账号、破坏性清理等敏感操作仍遵守已确定的权限和确认规则，不借本项一律放开。
- 登录或权限错误不重置、清空、升级或偷偷暂停个体；已运行任务遵守原执行规则。对未知提交结果先查原请求回执，不重复递送刺激。待同步研究记录持久保留；原件无法可靠保存时仍遵守既有停止宿主推进规则，不能继续制造无记录的正式实验。
- 独立 Runtime 的本机计算仍免平台登录；使用它做正式研究时，研究登记与证据保存仍走统一记录服务，不能把独立运行当作规避记录的渠道。

### 资料页面与上下文

- 将浏览筛选、对象归属、创建目标和系统权限拆成独立上下文。

### 独立 Runtime 与发布访问边界

- **发布、导出或本机运行模型不强制创建账号或密码。** 拿到模型后，独立库、SDK、CLI 和受信任的进程内调用可直接使用，不要求平台激活或云端校验。
- 库方法可用与网络接口开放是两件事。独立 Runtime 默认不新增远程管理监听；RuntimeHost／承载应用决定是否开放接口以及采用何种访问策略。
- 业务／输入输出接口与暂停、配置、干预、恢复、导出等高权限管理接口分别制定访问策略；宿主可明确声明业务接口匿名公开，不强制全部接口登录。宿主可使用自己的账号、令牌与能力范围、操作系统 IPC 权限或外部认证，不要求每份模型都内置一套完整角色系统。
- 同一 Lab 中多个实例共用平台登录及各自权限。独立部署有自己的信任边界，不能自动沿用源平台的用户、会话或凭据；可以复用认证代码，不默认共享账号数据。
- 回环 HTTP 地址不能单独证明调用者是本机用户或可信浏览器；本机 Web 访问可采用自动建立的本地令牌／会话及来源检查。可信代理认证必须防止绕过代理直接访问后端。
- 模型与科研资料包不烘焙平台密码或公共默认密码。网络部署时由宿主初始化访问控制；普通模型导出不因此被要求先设置密码。
- 当前部署声明的模型哈希、静态干预等检查属于科学与部署约束，不是身份认证边界；不能据此宣称 Python／Rust 独立网络管理已具备相同安全能力。
- 本期明确契约、保持独立运行能力并验收平台边界，**不借此次导航改造新增独立网络维护服务器**。该服务器与真实网络部署验收另列后续任务。授权在宿主边界完成，不进入 Core 配置、科学状态或动力学。

- 验证一次初始化后的跨命令、跨进程和客户端重启复用，以及授权范围内的会话续期；不能靠每次人工输入密码使测试通过，也不能把浏览器会话当命令行凭据。
- 验证无凭据、失效、撤销、停用、跨项目和动作权限不足，非交互模式明确返回、不等待输入、不退回超管；委托不扩权，权限变化与任务边界仍有效。
- 验证中断续录、响应丢失与原回执查询，不重复输入、不丢待同步记录、不清空或重启个体；原件保存失败沿用既有科研保护规则。
- 核对实际实验链中的 MCP 操作均可在有效授权下调用，普通创建／刺激／训练／报告／证据保存不被人工专用标签误挡；敏感操作仍有原权限及确认。
