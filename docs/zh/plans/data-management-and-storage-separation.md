## 1. 目标、授权及实施边界

- 先清理误提交产物及同类问题，再交付统一数据管理、可配置数据位置、正式包导入导出和迁移程序。数据管理本期完成，不另建一套独立事实库。
- 本期实际搬动仅限清单核准的误提交实验产物，目标为已忽略的 `data/experiments/<原实验目录>/<原相对路径>`。其他现有数据迁移只实现、用临时夹具验证，等显式操作再执行。
- 保留原始证据的完整字节、旧报告及固定标准、原版本／实现身份和全部正式旧内核。不重跑实验，不修改 Core 动力学、个体、外设、观察或模拟时序。
- 不自动执行真实云端传输、永久删除或现有数据库升级；结构升级脚本在隔离库验收，部署操作另行执行。不接管用户服务，不 push。
- 新功能不触发启动时迁移，不因设置变更搬移旧资源。真实历史数据不按失败状态、零结果、文件名称或“已导出”自动判为垃圾。
- 本期不引入第二个权威数据库、独立 MQ、数据库分片、跨项目全局去重、云盘多主写入或任意版本转换；无现场性能证据时不将架构风险说成已经测得的瓶颈。

## 3. Git 历史清理及证据修订

### 3.1 清单、归档与历史改写

1. 在不批量读取无关历史数据的前提下，建立精确文件清单：原路径及历史曾用路径、实验身份、相关提交、字节数、SHA-256、目的地和分类理由。
2. 首批覆盖 `2026-10-08-retention-telemetry-text`、`2026-10-08-retention-repair` 的生成产物，再处理审计发现的其他原始轨迹、大型逐项结果、嵌入完整数据的页面及证据／实现快照压缩包。小型汇总、源代码、协议、必要冻结夹具和文档保留；不按 JSON／GZ 后缀一律移除。
3. 两批新增文件此前合计约 64.8 MiB，另有同类产物；这是文件逻辑量，不能冒充 Git 最终节省量。执行前重核当前分支、工作树、所有引用和对象尺寸。
4. 完整旧 Git 备份置于忽略的 `data/git-backups/<批次>`，独立于活动对象库；核验可恢复。备份仍占本地空间，报告分别列出活动仓库与证据备份体积。
5. 复制产物到数据区并逐文件校验；保留原清单、源码、输入、结果、指纹及失败证据，不改内部 `source_commit`。位置登记关联原路径、逻辑资源与校验值。
6. 补齐最小位置解析和报告修订后，在无 alternates／共享对象库的隔离新克隆中，通过明确清单使用 `git-filter-repo` 清理所有相关历史路径；保留代码历史，输出旧／新提交映射。不要重建成只有一个根提交的仓库。
7. 确认工作树、索引和原 HEAD 未变化后才替换本地 Git 元数据；清除活动库中仍保留旧对象的备份引用、远端跟踪和 reflog，依工具安全流程重打包。发生并发变更则停止，不覆盖他人工作。
8. 原 Git 备份、原实验字节和提交映射保留；原指纹不得靠改写提交值“匹配”新实现。实际恢复仍遵守旧实现验证。

本期仅处理本地历史，不强推。保留远端配置及预期旧引用值，提供后续远端同步步骤；本地变小不代表服务器历史已清理，不与未改写的远端直接合并。

### 3.2 防止复发与报告修订

- 完善精确生成路径忽略规则和 `scripts/check-git-data.py`。已识别原始产物无论大小都拦截；非明确放行文件达到 1 MiB 时要求分类核查。必要冻结夹具、汇总与派生文档示例显式放行，不能靠放宽全局限制放行整批数据。
- 大型文档资源改用小型派生示例，并保留原件的证据引用。维护中的公共 writer 使用位置解析；历史冻结脚本不批量改源码，在隔离复现目录执行。
- 仓库报告新增同目录 `report-revisions.json`，登记系列、语言、修订、父版、日期、原因、相对路径和内容哈希；修订文件采用原名加 `.r2` 等标识，原文件内容及原链接保留。
- 修订版开头说明搬移／更正原因，链接原版；只更改位置与当前状态，不暗改结论、标准或缺失证据。实际移动成功后才写“已搬移”。
- 共用修订 writer 和 `Publication.revise_document()`，采用父版校验、预期修订、幂等操作及原子登记。数据库报告追加同身份的下一修订；旧导出与分享继续绑定原修订。
- 阅读器提供原版、指定版和最新版。证据链接通过登记的逻辑位置及原权限解析，不把外部文件根目录整体公开。

## 4. 存储架构、配置及生命周期

### 4.1 三层职责与默认策略

权威记录层为 PostgreSQL；不可变资源层通过统一接口访问数据库／文件／S3；可重建缓存层独立管理。新增登记与任务属于宿主，不参与 Core、传播、学习、遗忘或模拟调度。

| 数据 | 支持位置 | 默认／限制 |
| --- | --- | --- |
| 运行、检查点、转换帧、输入／输出因果记录、个体科学学习状态、权限、报告版本 | PostgreSQL | 保持现有权威存储；不因二进制 MIME 被当作普通文件外置 |
| 活动离线实验目录 | 注册本地／共享文件根 | 现有个体保留原位置；新维护入口默认研究根为 `data/experiments/` |
| 图片、音视频原件、导出包 | PostgreSQL／文件目录／S3 | 默认沿用各类别现状；已有媒体／制品仍数据库，现有文件导出默认位置不变 |
| 封存研究目录 | 文件目录；打包后可存 S3 | 对象存储不伪装成可追加写入目录 |
| 缓存、下载暂存、构建与依赖 | 本地主机目录 | 有界；不整体搬 `.work`，保留既有专项覆盖配置 |

- `ResearchStorage` 负责研究目录解析、登记、封存和迁移；`BlobStore` 负责不可变字节。共用校验及回执，避免第二套运行事实。
- 分类配置限定上述图片／音视频／导出语义，不能仅按文件后缀或 MIME 识别。数据库、文件及 S3 的设置仅影响新写入。
- 每个资源绑定实际后端、`target_id/config_revision`、相对对象键、大小、内容哈希及必要的 S3 对象版本；旧记录缺省数据库。已被引用的配置版本不能覆盖、删除或改桶导致失联。
- 文件根按稳定部署／主机身份登记，worker 会话身份保持独立。作业创建时固定目标和策略修订，只有实际有对应读写能力的 worker 可领取。
- 主机控制配置、登记、迁移日志与密钥标识位于不参与迁移的控制区，默认 `data/storage-control/`；运行管理记录继续数据库，不复制一套科学状态。沿用暂停／检查点／配置变更流程。
- 云同步目录按普通文件根处理；同步由云盘软件完成，只支持声明的本机单写／封存用途，不承诺跨机锁。活动 PostgreSQL／SQLite 不进入同步目录。
- S3 为可选依赖，配置 endpoint、bucket、prefix 和加密凭据引用；复用现有 `SecretBox`，返回配置时仅显示是否设置密钥。保存配置与能力展示不自动连接云端；显示“已配置、尚未验证”。

### 4.2 事务、读取与保留

- 外部写入先暂存／分块上传并验证，再在短数据库事务重核权限、请求身份、目标版本及租约代数，提交完整引用。数据库失败只留下登记的未引用候选，不留下半条刺激或可见半份证据。
- 连续采集冻结配置、序号、转换器状态、原件引用及转换帧仍一起提交；网络上传移到占用运行锁的事务外，重验后提交。重试沿用同一编号，不跳块、不重置感官或改变模拟步长。
- 普通下载、媒体、笔记图片、报告来源／分享、分析工具、实验包打包与恢复都通过统一读取接口；已有科学权重可继续数据库。不能只改 UI 下载而遗漏包导出／恢复。
- 本地采用受根约束的相对键、暂存文件、校验和原子发布；S3 使用不可变键、有限并发／重试／超时、分块上传取消及 SHA-256 校验，不以 ETag 代替完整校验。
- 缓存有容量上限，缺失／损坏／不可用明确阻塞或报错，不返回空证据。新外部路径的慢网络不长期占用数据库事务或连接；保持现有过期 worker fence。
- 原报告、笔记修订、来源、分享、谱系、冻结实验与恢复链的不可变／引用保护延伸到对象。去重仅项目内；私人笔记继续按作者权限读取。
- 删除引用与外部删除请求先登记并提交，再复查引用执行对象回收；不在可回滚事务中先删外部原件。只处理登记的候选，不扫描整个桶前缀认定垃圾。
- 暂存记录区分接收中、处理中、完成且已引用、取消、过期及待清理；无活动租约、无引用并过期的记录才可进入清理计划。正式包的原上传字节继续是证据，不当暂存删。本期不据此清理真实旧数据。

## 5. 正式数据包、导出与导入

### 5.1 契约及维度

新增 `threemind.data-bundle/1` 和 `.tmdata` 入口，复用流式分块、路径／成员／预算检查和哈希工具。旧 `.tmexperiment`、报告证据 ZIP、语言／种群包保留原协议及能力；由类型注册表分派验证器，不静默升级旧包。新增扩展名及分卷一并进入 Git 数据防护。

| 包／导出用途 | 承诺 |
| --- | --- |
| CSV、图表、JSONL 等分析子集 | 可阅读／分析；不冒充可恢复完整实验 |
| 正式研究归档包 | 原始资料及版本／关系完整登记；可重新导入查询；已实现类型可还原原生记录 |
| 经对应恢复器验证的完整包 | 在匹配版本、依赖和外界条件下恢复完整主体／系统，默认暂停 |

- 导出选择入口支持实验、个体／种群、批次／数据集、项目、标签及时间范围；数据类型、后端和归档状态可组合筛选。时间子集不自动具备续跑资格。
- 导出计划冻结范围和一致提交边界，自动收集必要依赖及历史修订。默认包含所选对象完整历史；选择子集时明确覆盖／排除范围和丧失的恢复能力。
- 闭包覆盖 Core、外设权重与学习状态、映射、身体、随机状态、读出、输入、检查点锚点／增量依赖、协调器、报告固定来源与制品、笔记集合／修订／附件，以及实际使用的原件。
- 私人笔记只包含调用者有权查看的内容；其他作者私有记录、用户账号／凭据、设备授权及运行中的服务进程不属于默认研究包。不能因按项目导出越权。
- 通用包若不能恢复某种协调器或未知对象，完整保存原件与描述，标为只读资料；不能以空白外设／协调器补齐。历史孤立文件可作为资料附件，缺少的元数据明确列出，不补造。
- 包含逻辑对象／版本身份、来源、原始哈希、依赖、提交边界、包／对象 schema、内核／实现身份、恢复器及三种独立能力：可查看、可还原记录、可继续运行。SHA-256 是完整性校验，不称数字签名。
- 所有恢复必需字节随包携带；本地路径、S3 URL 或目标机器无法访问的引用不能替代它们。可选缺失资料列入限制，缺必需成员不能通过完整验证。
- 大包分卷采用总清单和每卷哈希，复用有界子包；默认沿用现有每卷 8 GiB 压缩／20 GiB 展开上限，所有卷齐全校验后才发布完整包。总预算可显式配置，不通过静默裁剪满足限制。

### 5.2 导入与恢复

流程为预检 → 原包只读登记 → 原生资料还原／恢复计划 → 显式提交；“导入”和“开始运行”分离。

- 预检重新验证清单、所有成员、版本、资源预算、完整依赖、恢复器能力及目标权限。仅有 `manifest.json` 不能获得执行资格，不导入任意 SQL／可执行序列化，不自动运行包内源码。
- 未知外层包 schema 拒绝作为正式包导入；已知 `data-bundle/1` 内尚未支持的对象 schema 可以保留原字节并只读登记，禁止原生还原／续跑。缺少恢复必需依赖的包不得声明完整恢复能力；仅缺可选资料时保留明确限制。
- 先保留原包字节及原 ID、作者、时间、哈希作为来源证据。目标使用新身份／命名空间和显式映射，不覆盖同 UUID，不按同名或相同哈希合并不同实验。
- 报告及本人笔记支持原生资料还原：保留全部历史版本、父版／引用／附件关系和原作者时间来源；新对象由当前权限管理，原始与导入投影哈希分别记录，不伪称重映射后仍是原对象。
- 报告固定捕获及来源证明／附件依赖必须随包还原。正文、元数据中的旧项目／制品／笔记图片／来源链接在导入投影中通过登记的身份映射解析，原文本另存不变；不能原生表达的来源挂接只读 origin 资料，不伪造运行对象、AI 调用或执行记录来满足外键。
- 源研究原始记录可作为只读研究数据集查询；支持的恢复器还原完整可运行对象。没有验证器的内容只读，不强行回灌为活动表。项目范围导入不冒充全库备份／角色恢复。
- 固定分享元数据及原导出可作为证据；原公开 URL、凭证、授权不自动生效，重新发布走当前 owner 的现有流程。
- 普通模型／已有专用包仍走其既有导入器；类型注册验证通过后可从统一入口调用，不能削弱原兼容条件。内核、科学时钟、输入游标、随机及学习状态不重置、不自动升级。
- 同一请求幂等、并发有冲突检查；未激活暂存不可见。数据库还原事务整体成功才发布；外部对象失败按暂存／回执恢复，不留下可用的半个主体。
- 恢复默认暂停；外界遥测、设备重连及目标运行条件变化单独说明，不因导入成功宣称现场输入相同。跨实验自动合并、任意版本转换和未知协调器整场续跑留待后续。

## 6. 统一数据管理与迁移接口

### 6.1 管理入口与操作边界

UI 新增“数据管理”菜单，整合存储检查、模型档案、包管理与版本查看；原入口保留导航兼容。提供资源列表／详情、导入导出、存储目标／迁移及任务回执页面，桌面与窄屏均可操作。

- 查询支持项目、实验、个体、批次、类型、后端、标签、时间及归档状态；详情显示大小、来源、版本、引用、位置、恢复能力和校验状态，默认不展开大型正文。
- 项目操作使用 `/api/v2/projects/{project}/data`；主机目标及迁移管理使用 `/api/v2/storage`。服务层复用现有事实、权限和任务服务，端点不允许任意 SQL 或主机目录扫描。
- CLI 提供 `threemind data`（查询、查看、导出计划／执行、导入预检／还原、`cleanup preview/execute`）与 `threemind storage`（目标、检查、迁移与状态）。清理执行必须提供预览 token 和对象名，重新检查引用；包上传下载命令兼容保留。
- API／UI／CLI／Agent 使用同一操作目录和服务；新增主机 scope、持久回执和真实回退说明，不能把文件迁移标成“检查点分叉撤销”。Agent 只接受已登记目标／资源／计划 ID。
- 根目录／密钥由管理员配置；项目资源操作继续按角色与私人笔记权限，管理员不自动绕过项目边界。迁移、打包、导入提供程序接口及请求编号。
- 永久清理沿用人工流程：UI／CLI 必须取得预览 token 并确认对象名称，后端提交前重核引用和范围；Agent 提供查询／预览，不开放绕过现有 `cleanup` 人工约束的万能删除。
- 删除区分归档、冗余副本移除、暂存回收和永久清理。运行中、报告／谱系／恢复／固定实验引用仍阻止删除；不能绕不可变触发器删报告和笔记历史。导出成功不自动授权删除。
- 风险提示展示真实范围、阻碍、空间需求、是否需暂停、源是否保留和能否回退，不只显示一句警告。确认不豁免引用约束。

### 6.2 迁移服务

同一服务提供 `inspect / plan / execute / status / resume / cancel / verify / activate / rollback`。项目资源任务复用现有 jobs 租约／代数与能力匹配；离线跨项目目录使用独立主机任务日志和 OS 锁，不能创建虚假项目。

- plan 固定资源清单、来源／目的地、配置修订、大小／哈希及请求身份；execute 只接受已保存 plan ID，重核路径、空间、源未变化及无活动 writer。
- 流程为复制暂存 → 校验 → 完整发布 → 单独 activate 位置映射。默认保留源，无自动双写、删源或迁移开机任务。
- 中断保存进度；同编号重试返回原任务，cancel 保留旧源及未激活目标。目标已存在不同内容、路径越界、符号链接／junction 逃逸、控制区嵌套迁移、空间不足或源发生变化时明确拒绝。
- 活动研究需先由操作者暂停／停止写入并取得实际锁；不能仅因一个新锁空闲推定旧脚本未写入。无法证明安全的历史 writer 明确拒绝。
- 物理位置通过登记映射，原科学注册路径／参数／种子／实现指纹保持原证据；位置变更不放宽恢复校验。孤立旧脚本不能宣称透明兼容。
- activate 以登记修订比对切换；之后若产生新写入，rollback 需反向计划，不能盲目切回旧源。删源和取消残片清理均为另一个明确操作。
- 本期只在临时目录、临时数据库和本地 S3 测试服务执行迁移；误提交归档是唯一获准实际文件搬移例外。

## 7. 容量、完整性及跨后端备份

- 容量页区分逻辑引用字节、实际对象字节、数据库／索引／WAL、暂存、可重建缓存及明确可回收量；未知项标未知，不能把估计当可释放空间。同一共享对象不重复算物理占用。
- 默认读元数据与有界分页；完整哈希扫描显式触发、可取消，有操作预算，不每次打开页面扫描所有文件或整桶。
- 审计显示缺失、损坏、后端不可达、未引用候选、陈旧上传及引用阻碍；统计、迁移和清理预览共用登记接口。保守检查不到引用不等于证明无引用。
- 备份工具产生数据库一致快照、该快照引用的不可变外部对象及哈希、实现版本、目标配置和密钥标识的总清单；密钥实际内容单独安全保管，不进公开包／Git。
- 备份期间固定快照所需对象的保留租约，避免并发回收。全库使用有足够权限的备份账号；角色／授权另行登记，不以应用 RLS 视角作全库备份。
- 恢复到隔离位置／新库，检查成员及依赖齐全、版本／权限和完整主体续跑一致；能打开 ZIP 不算恢复验收。研究包不替代数据库及密钥备份。
- 本期实现手动触发的备份／检查入口与恢复演练，不创建定时任务，不备份／恢复或清理真实用户数据。

## 8. 分阶段实施与验收

| 阶段 | 交付与通过条件 |
| --- | --- |
| P0 规划落地 | 双语计划、原始决定／审阅依据、backlog 与现代／文言史同步；状态只写已批准待实施 |
| P1 先完成 Git 清理 | 精确清单、原件复制校验、最小位置／报告修订支持、防护检查、旧仓库备份、隔离过滤／验证、本地切换与提交映射；不 push |
| P2 存储分离 | ResearchStorage／BlobStore、受限分类配置、身份／目标能力、全部关联读写路径和暂存生命周期；旧默认与读取不变 |
| P3 正式包往返 | 类型注册、维度筛选与闭包、分卷、只读登记、报告／笔记原生还原及已有恢复器；未知类型保持只读 |
| P4 管理与迁移 | UI／REST／CLI／Agent 的统一资源操作、风险预览、回执、迁移恢复／切换、容量完整性和备份工具 |
| P5 验收交付 | 隔离故障／往返／恢复与界面验收、使用文档、实际限制及仓库尺寸报告；不开始真实数据迁移 |

各阶段可本地提交，不 push。P1 只先实现清理必需的最小报告／位置能力，后续阶段补齐通用能力；不得因尚未完成完整数据管理就先删原件。

必须验证：

1. **证据与 Git**：原字节／旧报告／冻结夹具不变；活动历史不含清单产物；旧备份可恢复；再生成时检查能拦截；分别报告仓库 pack、工作区数据与备份量。
2. **后端与权限**：策略变更只影响新写；旧目标可读；三个后端在下载、分享、分析、打包和恢复中一致；项目／作者权限、路径边界、目标能力及配置冻结正确。
3. **故障与生命周期**：上传成功但数据库提交失败、租约过期、进程退出、取消、缺失／损坏对象、目标变化和预算不足不产生半条刺激／半个可运行主体；证据引用阻止暂存误删。
4. **正式包往返**：所有支持类型的对象数、历史版本数、原始字节哈希及原引用可追溯；新项目中各历史版本的图片、制品和固定来源可读；同名／同 UUID 不覆盖；缺卷／未知外层协议拒绝正式导入，未知对象只读，缺依赖／伪造声明拒绝完整恢复；分享不自动公开。
5. **完整主体与兼容**：相同模拟输入下保持 Core、外设／优化器、身体、映射、读出、随机、输入／队列及时间相位；旧包／旧内核不升级；未知类型不能续跑；恢复默认暂停。
6. **迁移**：使用临时完整主体与资料测试计划、并发、断点、幂等、取消、校验、激活及受控回退；活跃 writer／源改变／junction／控制区越界拒绝；实际迁移仅限 P1 清单。
7. **备份与成本**：隔离数据库加外部对象恢复完整；缺对象／密钥可明确诊断；分开测 Core、存储、压缩、导出和查询成本，不把减少数据重复保存宣称为动力学性能增益。
8. **文档与界面**：双语、报告版本、数据操作与任务回执可用，窄屏不会隐藏风险范围；历史目录／链接验证通过。

交付继续维护[研究总表](research-backlog.md)和双语现代史、两份文言改编，区分批准、实现、实测及未验证内容。原 E64／E65／E66、原 `/2`／`/3`／`/4` 证据及当时结论保留；位置修订不改变它们的证据能力。
