## 3. 工具耗时与内部模拟时间

| 已核查路径 | 事实与边界 |
|---|---|
| `Runtime.pace`、CLI、Lab 推进 | 物理时钟决定是否等待；推进目标由当前模拟时间和既定截止点决定，没有把一次查询耗时直接加到模拟时间。落后时减少等待，不跳过内部事件 |
| Lab 事件 observer、`ReadoutHost`、输出器 | 已读回调记录输入来源或读取截面，不调用刺激、重配置、干预或额外推进；检查点复制及等待也不调用额外推进 |
| 观察频率 | Lab 的 `next_observation`、读出和输出器截止点，以及 CLI `ReadoutSession` 会细分 `advance_to` 调用边界。因此仍须验证“分批不改变轨迹”，不能仅凭 callback 看起来只读就宣布正确 |
| 固定输入下 `/2` 小型实测 | Python、Rust 分别比较直接推进与 11,357／17,311／19,877 微秒非对齐观察间隔，到 1,001,337 微秒的完整状态分别精确相等；每组产生 90 条读出事件。重复 metrics、graph、节点／边读取、空间投影、强制只读读出及保存，完整状态字节不变 |
| 模拟物理等待 | 将宿主单调时钟虚拟增加 100 秒，再调用 pacing，Python、Rust 的模拟时间及完整状态均不变。这是受控时钟测试，没有实际等待 100 秒 |

**真实遥测存在另一条反馈路径，不能与只读工具混为一谈。** `src/threemind_lab/telemetry.py` 按物理时间采样；启用的宿主／进程／运行时遥测会把真实测量编码为输入，递送时刻为当时模拟时间加声明的反馈间隔。观察、保存和其他工具的物理开销可能改变 CPU、内存、调度时延、采样次数或采样时所处模拟位置。`run_cycle.py` 的运行时计量区间还包括 `advance_observed` 内部 Python observer 的耗时。

因此本次发现的风险是 **显式外部遥测输入可能受工具负载影响**，不是证实了“工具偷偷消耗模拟秒数”。已批准的真实遥测不能为了证明无干扰而擅自关闭或替换。需要严格控制输入的工程对照可用预录输入；真实环境反馈实验须如实记录工具负载，并由用户决定如何区分意识本体与工具开销。以上只是核查和建议，没有据此修改输入协议、采样规则或旧内核。

## 5. /5 开发期独立审查续记

在实现者自测之外，独立读取共享版本分支并运行新匿名工程见证，发现以下开发期缺陷。实现者补修并新增回归；这些不是既有正式实验的新结论。

| 已发现问题 | 原复现与修后复验 |
|---|---|
| 新颖增益为零的双后端分歧 | Python 仍建新颖窗口，Rust 不建；70ms 后期限数量不同。修后两端均不建立无效窗口，完整状态容差一致 |
| unified 研究选项外部输入被算作再入 | Rust 仍将 80ms 外部重复的 0.09 接受量记入新颖性，Python 不记。修后两端均只以内部联想记此奖励来源 |
| legacy-source + coincident 的混合到达冲量 | 110ms 内外混合时，Rust 因整组 direct=false 丢失外部冲量，Python 保留，出现边权 0.08324401549754097 对 0.081388。修后一致；该组合是明确标注的研究选项 |
| 已完成传播相位被同刻后入输入遗忘 | 先推进至100ms再在100ms注入合法当前输入，`/2` 权重由0.1085287384变为0.13551908159515785，初版 `/5` 误变为0.12083166376262104；同刻新边窗口误为110ms而非210ms。新增可恢复的“已完成发出相位”标记后，强化恢复原容差，新颖截止210ms，两后端当前状态与继续推进一致。该标记记录执行次序，不引入全图刷新或学习配额 |
| 已结束新颖窗口留下 Python 空索引键 | 全部节点删除后仍有旧节点ID指向空集合；清理后派生索引为空。属于内存管理修复，不赋予奖励或改变模拟时间 |

最新隔离原生扩展位于 `.work/memory5-validation/native`，上述三项选项复现及同刻相位见证已独立重跑通过；同一扩展的 `/2` 冻结回归再次49项通过。见证脚本和结果在 `.work/memory5-validation/provenance_review_parity.py`、`provenance_same_boundary.py`、`provenance-review-parity.json`。
