# 活动过程读出校准

状态：已实现并完成校准。2026-09-30。[工具说明](../v2-observation-tools.md) · [校准报告](../../../lab/validations/2026-09-30-process-readouts/report.zh.md)

## 问题与边界

近期实验暴露的并非单一阈值问题：短暂响应可能在收敛判定前结束，弱响应可能被阈值排除，背景可能占据最终排名，词语模板可能漏掉实际活动节点，设备来源也可能没有开启观察窗口。没有观察到、没有达到某项判据、完整观察中未测得变化，必须分别表述。

依据包括 `lab/explorations/2026-09-30-memory-transfer/report.zh.md`：736 个窗口的主要收敛判定没有读到任务响应，但过程轨迹及受控断连、恢复对照发现了响应。这里不重写旧结果，也不据此保证每个未读出的窗口都有记忆。

用户补充：工具不应只根据某个时刻判断。有价值的信息可能在一段变化中，而不在最终静态状态。记录发生次序、持续、转移、反复出现、增强与减弱；节点各自的峰值不能拼成一个从未存在过的同时状态。

## 本期实施

1. 活动过程分析新增 `/2`，旧 `/1` 和活动稳态判定保持可选、可恢复。只有新配置默认使用 `/2`。
2. `/2` 保存有界观察全程，默认 20 ms 采样；采样是观察节律，不改变内核节律。保留收敛时刻排名，并单独给出完整过程的原始活动、相对基线的增减、出现及消退时间、重复激活、累计变化和模式转移。最终无响应不抹掉中途活动。
3. 无需发送刺激即可打开观察窗口。实际输入关联和观察者的窗口标记分开，不向内核注入虚构刺激。
4. 完整轨迹比较工具比较对应节点的时间过程，不使用词语模板，不只比较前几名；明确时间对齐、缺失采样、采样误差及干预条件。基线差分与两条任意轨迹的差异本身不证明因果。
5. UI、API、CLI 和导出接通。显示预算不裁剪保存证据；超预算明确标记，不冒充没有响应。

## 验证与资源

固定短暂弱响应、持续背景、减弱、先后转移、再次激活、无响应、缺失采样等样例；回放已有完整证据。比较开启与关闭新观察器、恢复前后及 Python/Rust 内核状态哈希，排除观察干扰。新观察频率不得偷偷提高旧读出器频率。

不重跑已有训练，不修改旧实验。校准新增证据目标小于 256 MiB，单进程运行，测试和回放超过预算则收缩范围并报告。结果单独追加校准报告，完成前不标记已实现。
