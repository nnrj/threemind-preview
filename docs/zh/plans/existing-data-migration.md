## 边界与目标

数据库管理研究记录及高频查询数据，统一原件服务管理不可变文件；不要求独立文件服务器。默认根目录仍为项目 `data`，本次用户指定迁移到 `E:\ThreeMindData`。`THREEMIND_DATA_ROOT` 不移动 PostgreSQL 物理数据库目录。Core 动力学、个体身份、内核、结果、模拟时间及独立 Runtime 的可选 SQLite 保持不变。

运行／封存状态与物理位置分别管理。报告、笔记正文及修订、输入顺序、指标、恢复游标、节点／连接查询投影继续存数据库。媒体、原始采集、正式包及确认的历史实验原件使用统一文件存储。运行检查点默认 `database`，新增宿主配置 `filesystem`；已结束且封存、恢复依赖完整的检查点才可迁出数据库。完整系统包含 Core、外设学习状态、身体、映射、随机状态和读出历史。

## 实施顺序

1. 保存本双语计划；核对登记资源、数据库原件与历史引用，按正式原件、文档源码、固定夹具、临时数据、缺项分类。157 是实施前登记数，不直接等于实验数。
2. 补齐批量根目录变更、可版本化位置、数据库原件迁移、可选文件检查点和联合备份；UI、REST、CLI、Agent 共用服务。隔离验证后再写真实库。
3. 使用已配置本地管理员备份账号，备份当前数据库、登记原件及固定控制元数据，隔离恢复核验；旧备份保留，不使用付费服务。
4. 优先 E64～E66、保持对照及 /4，随后所有确认正式资料。只迁正式原件，不整体搬 `.work`、`lab`，Git 源码、协议、报告和冻结夹具原位保留。
5. 按媒体、笔记图片、包及合格封存检查点分批复制、校验、事务切换。暂停待续训、依赖不足、恢复失败的主体留数据库。
6. 验收新位置读取、恢复、导入导出和备份，再激活新根。未来写入遵守新策略；旧对象按已登记位置读取。失败对象保留原位，区分完成、部分完成、阻塞。

目录变更提供预览、执行、状态、继续、取消、校验和回退。直接修改配置不偷偷迁移或把旧位置误当空库；固定控制区及密钥不随根移动。位置改变不改原哈希或来源。文件检查点先持久化校验，再与输入／观察／恢复引用事务提交；失败不确认成功，不跳过输入。源副本默认保留，清理另作精确预览。运行写入需协作锁或确认暂停，不接管用户服务。

## 验收与交付

核验查询仍走数据库、模拟轨迹一致、完整系统及增量链恢复、SQLite 独立运行、故障与重试、权限、原件字节与引用。新位置验收禁止用旧副本掩盖遗漏。分开报告数据库、原件、副本、备份占用与查询、编码、保存、I/O、恢复成本。详细清单和回执存受管理数据区，公开报告只保存聚合结果。

更新 T10／T11、双语使用说明及现代史书、两份文言改编。原报告保留，追加有迁移原因的位置修订。分阶段本地提交，不 push。
