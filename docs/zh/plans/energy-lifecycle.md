# 缺能损伤与统一活动死亡

[English](../../en/plans/energy-lifecycle.md)

2026-09-09。用户已确认：保留缺能结构损伤，撤去独立强制判死，由连续无激活达到宽限期统一判死。本项承接 [V3 恢复记录](v3-restoration.md) 中的唯一实施冲突。

## 实现边界

- 原 `irreversible_energy_death_enabled` 同时控制维护、侵蚀和饥饿倒计时。原倒计时到期会清空激活、抑制、痕迹及在途事件，关闭输入并直接判死。这与活动定义冲突，已从 Python 和 Rust 删除。
- 新参数 `energy_starvation_damage_enabled=false` 仅控制可选维护与缺能侵蚀，还须同时启用 `energy_simulation_enabled`。删除 `energy_starvation_death_us`；新配置、JSON 校验和保存拒绝这两个旧字段，不把旧名称悄悄解释成新机制。
- 维护收费与侵蚀公式保持原样：未付维护比例为 $d$，节点支持度、连接权重和稳定度乘以 $\exp(-\lambda d\Delta t)$。维护成本为 0 时不产生相应欠费；侵蚀速率为 0 时关闭侵蚀；关闭缺能损伤开关同时关闭维护及侵蚀。自然衰减、学习和旧联合修剪仍各按自身规则执行。
- 零储备不能直接抹掉现有激活。激活只按自身动力学变化；因此有激活时，即使长期缺能也不能被饥饿倒计时判死。
- 首次激活前继续待接入；首次激活后，全部节点连续无激活满 `quiescence_death_us` 才死亡，默认 1,000,000 μs。供能自身、未能激活节点的刺激、在途但尚未引起激活的信号，均不能重置这个计时。
- 同刻先递送事件，再判定活动期限。已付费的在途兴奋可以在零储备时激活接收节点；接收不再次收取发送成本。纯供能在截止时刻到达也不能冒充激活。
- 死亡保留结构及剩余队列作为证据，停止继续计算；原意识不能通过供能或新输入自动复活。显式继承仍产生新的意识。

## 版本、记账与界面

这次改动使用 `threemind.causal/9`，状态仍为 `threemind.state/6`：状态字段结构没有变化，改变的是配置及生命周期语义。旧 causal/8 的小型原始模型已冻结在 `tests_v2/fixtures/causal8-energy-before-unification.json`，保留来源提交 `304ef25` 和摘要。旧模型只读，JSON／`.tmind` 转换保留原字段及摘要，不自动更换版本续跑或继承。

`starved_since_us` 只是零储备状态的观察记录，没有死亡期限；`death_us` 在 causal/9 中记录统一活动规则判定的死亡时刻，不是死亡原因或额外控制量。能量守恒账本与供给时间戳协议不变。

图形参数组为“能量与缺能损伤”，开关为“启用缺能结构损伤”，不再出现不可逆饥饿时长输入。能量页面说明缺能不直接判死。查看旧证据时仍注明历史机制，不能将旧强制判死伪称为新版活动判死；CSV 保留旧参数列，JSONL 保留原记录。

无需数据库迁移，Lab schema 保持 48，不扫描或转换 `data/`。服务停止后更新所有原生扩展、CLI 和前端，再用新建意识验收。
