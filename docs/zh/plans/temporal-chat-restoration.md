# 时序读出与聊天复刻实施记录

[English](../../en/plans/temporal-chat-restoration.md)

2026-09-10。状态：本轮已实现并完成下述验收。

## 已确认的交付边界

- 同时接通聊天、实验记录／报告、独立 Runtime 与校准命令行的时序读出。
- 旧聊天以 `0c5e64a` 的界面和 `97d8592` 的读出格式为依据；源码摘要及实际旧函数输出冻结于 [基线](../../benchmarks/chat-restoration-reference.json)。
- 时序正文按现有综合排名默认展示前 7 项；完整节点可在同一消息展开。被动标签恢复激活排序及关闭选项。文字去重仅为显示，不删除节点。
- 复刻连续气泡、媒体与器官工具栏、输入区、滚动行为；保留有界加载、准确来源、发送幂等、错误恢复和输入法保护。
- 内核、感官映射、时间架构及读出分类／评分公式保持不变。普通意识不会因观察窗口结束而停止。
- 验收使用独立新项目。旧数据不回填、不重新分析、不转换、不清理；不存在升级前清库要求。

## 当前版本的取舍和需要纠正的偏差

`db4e0a4` 的代码及此前文档能确认：消息界面复用了分页证据查询，以游标、每页 20 条和每条 128 节点预览控制开销；强调原始证据、来源及传输状态。精确关联、完整原始活动、事务索引、故障恢复有保留价值。

但查询界面直接替代了连续聊天。类别下拉框虽然提供“全部”，仍占据主操作路径；连续读出很快替换最新 20 条中的输入；元信息挤占正文；节点编号顺序代替了旧读出排序。此前测试覆盖按钮与接口存在，不能证明已忠实复刻体验。“聊天复刻已完成”的结项范围过大，本次予以纠正。

这些交互退化不是科研严谨性所必需。历史中无法确认的作者动机不作推断。新版全量采集不退回旧版子集；恢复呈现不改变原始活动或候选计算。

## 保留与未做的事项

本轮保留准确输入关联、完整证据、事务索引、有界浏览、幂等发送与错误恢复；修复分类浏览器替代聊天、正文排序丢失和元信息挤占正文的问题。验收时另修正独立页宽度和窄屏工具栏溢出，不能只以按钮存在作为验收标准。

Core、感官映射、时序采样、候选、评分和收敛公式均无改动，未进行新的训练实验。旧实验不回填、不修复、不重算、不清理；历史 chat/1 按原证据展示，新的 chat/2 才使用本次呈现协议。纯 Rust 最小 CLI 不新增 Python 主机的读出参数。各节点原始采样值、外部注释和有限窗指标保留各自含义，不能从缺失记录补造回答。

用户操作见[时序观察与聊天指南](../v2-temporal-research.md)；数据库备份、试恢复和按项目／批次整理见[备份与清理指引](backup-and-cleanup.md)，清理由用户决定和执行。正式工作站未替用户启动新的研究作业。
