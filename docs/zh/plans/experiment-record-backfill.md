# 实验记录补全与统一研究总览计划

[English](../../en/plans/experiment-record-backfill.md)

批准日期：2026-10-10。用户明确要求实施；此前规划阶段的“仅规划”边界已由本次实施授权替代。本次不重跑历史实验，不改变 Core、旧个体、协议和原始结论，不推送 Git。

## 1. 目标与原则

覆盖项目全部历史正式研究实验，并统一后续 AI、人工实验的记录入口。数据库和 UI 提供全局索引、报告、笔记及证据关联；完整原始数据保留，通过引用访问，避免重复存储大文件。

采用已确认的方案：**统一记录＋原件引用，保留现有 AI 实验的额外科研记录。** 不要求所有历史明细转换成平台运行表，不新增内核内部事件追踪，不改变 Core 动力学、历史个体或实验结果。

## 2. 历史盘点与补全

- 建立逐实验台账，交叉核对数据库、实验目录、早期实验笔记、史书来源、发布回执和归档清单。当前发现的 69 个探索目录只是盘点入口，不直接等同于 69 个已执行实验。
- 保留原实验编号和项目归属。已发布的实验复用现有记录；缺登记的正式实验建立索引。未启动草案、失败、中断、阴性结果、校准和对照分别标明，不凭目录名虚构执行过程。
- 每项登记研究问题、协议与版本、执行者、实验日期、内核及配置、条件、个体与分支关系、实际阶段、结论、报告、笔记和证据位置。未知内容明确为空或待核查。
- 对原始文件登记逻辑资源标识、格式、大小、哈希、所属实验和阶段、依赖及可查看方式。复用数据库附件和现有归档位置；已有原件不搬、不删，不重复上传完整证据包。
- 报告、协议和科研笔记等小体量正文入库。原版与修订版保留完整关系；补录日期和原实验日期分开记录。后来整理的说明明确标为补录说明。
- 无法解析的格式仍登记并保留原字节；缺少文件、检查点、身份或时间信息则列入缺项清单。补录不重跑实验，不补造未采集的数据。

优先补全 E64～E66 的关联，以及原 `/3`、修复 `/3`、文字遥测与 `/2` 对照、`/4`；随后按年代处理其余历史实验。范围始终覆盖全部历史，不以近期完成代替全部完成。

## 3. 数据与平台实现

**新增统一实验索引，关联现有科学记录，不替代现有运行系统。**

- 增加实验、个体／条件／阶段关联、证据引用和补录批次记录。原身份与平台索引身份分开；连续成长、恢复、独立对照和实验副本依据原证据建立关系。
- 将“实验执行状态”和“资料整理状态”分开。实验完成但资料缺失时，两种状态同时显示；不能把原件已登记标成所有数据完整。
- 增加“实验总览”入口，默认展示当前用户有权访问的全部正式实验。支持按项目、编号、日期、内核、执行者、状态和资料完整性检索；开发临时测试默认不列入正式研究总览。
- 实验详情集中展示协议、条件与阶段、结果、报告修订链、笔记、检查点和原件入口。复用已有回放；已支持的过程格式分页查看，其他格式提供清单与下载，不一次加载巨量数组。
- 当前项目的记录、报告和笔记页面保留，并提供全局总览入口，明确显示筛选范围，避免某个项目为空被误认为全库没有实验。
- 所有引用接入现有统一存储和数据管理服务，支持按实验导出。权限、私人笔记保护及原件引用保护继续有效；失效引用明确提示，不返回貌似完整的空内容。

## 4. AI、脚本与人工共用的录入工具

同一后台保存服务由人工 UI、CLI、MCP／Agent 和实验脚本调用。

| 接口 | 本期能力 |
| --- | --- |
| REST | 全局／项目实验查询，实验登记，阶段及过程条目追加，证据关联，报告／笔记保存，完整性核验，补录预览与执行 |
| CLI：`threemind records` | `list`、`register`、`append`、`attach`、`finalize`、`verify`、`backfill-plan`、`backfill-apply`、`receipt` |
| MCP／Agent | 现有操作目录中暴露同一操作、请求结构、前置条件和回执 |
| Python 记录器 | 登记、阶段记录、原件关联、同步和结项检查，不要求脚本模拟人工界面 |

- AI 与人工采用相同必要信息、保存服务和核验标准；执行来源只作为元数据。
- 保留脚本原有科研格式，统一必要索引字段，扩展内容保留原件，不因不适配表单而丢弃。
- 稳定请求 ID 和内容哈希保证幂等；重试不重复生成，冲突明确报错。
- 新正式实验开始前登记；原件持续保存，阶段结束同步，结项核验关联；人工入口自动登记。
- 数据库不可用时保留持久化待同步记录；原件无法可靠保存时停止宿主继续推进并报错，不清空个体或跳过输入。
- 工具只记录事实，不触发刺激、学习、恢复或重执行。临时开发测试、凭据、无关工具日志和 Agent 内部推理不自动录入。
- 历史冻结脚本保持原样，补录用外部适配器；维护中的后续实验脚本接入统一记录器。

## 5. 实施、验收与交付

1. 盘点与保护：保存现状清单、缺项台账和补录预览；写库前备份本地数据库并核验恢复。
2. 实现与隔离验证：索引、API、CLI、MCP、记录器与 UI；迁移显式执行。
3. 正式补录：固定来源逐批执行、核验回执和可见性；失败可重试，不重复创建或覆盖已发布版本。
4. 入口统一与收尾：全量盘点、结果、缺项、手册及存储增量；同步研究进度与历史。

验收涵盖全部已识别实验登记／缺项；全局查找近期和早期实验；原版本、哈希和身份保留；跨接口一致、幂等与续录；缺失／未知／权限准确；不推进模拟或改状态；正式包往返；分别报告索引、小正文、原件及记录开销。

无法恢复的资料交付具体缺失、影响和可查找来源，需要用户备份时明确内容。**索引补全不等于原本缺失的科研数据已经恢复。**
