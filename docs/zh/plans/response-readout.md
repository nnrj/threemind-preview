# 短暂响应与持续稳定分开读出

决策日期：2026-10-02。新工具 `threemind.response-readout/1`；旧 `target-observation/1`、活动监视器及 Core 身份保持原义。

## 为什么改

用户指出：“我们要找的收敛就是这种清楚的响应啊，不管有多短。”本轮按此用途将“响应收敛”解释为一次响应形成的可读结果，不要求它成为持续稳态。响应可能短暂、并列、随后转移；持续稳定另作分析。检测到响应不自动意味着答案正确，也不声称仅凭轨迹就已定位竞争原因。

800 毫秒不是用户提出的假设，也没有已找到的生理验证依据。可追溯链条为：Git `97d8592` 的 `adapters/threemind_adapters/temporal.py` 使用 `settle_ticks: 8`；`4e43349` 的时间化配置使用 `settle_us=800000`；`ce311d6` 的目标分析又沿用了这一默认，并要求局部活动连续存在。最早八周期为何这样取，现有史料无法确定。把该工程窗口当成短暂响应的必要条件不适合当前研究用途。

## 固定本轮规则

- 从已有完整激活向量读取，全节点为默认范围；可指定目标节点。未知节点报错，不能当作零响应。
- 不设最小持续时长。响应进入、总激活先升后降的峰值（平台取最早峰点）、领先节点或并列集合变化均留记录；每段即使只有一个采样点也保留。
- 每条记录按**同一个真实采样时刻**的激活强度排序；零激活节点隐含为零；不拼接不同时刻的节点峰值。领先差值用于描述，不设置“正确答案”门槛。
- 默认详情展示窗内总激活最大的一条响应（并列取最早），同时列出其他响应。这是固定展示规则，不是语义正确率或必须唯一获胜的规则。
- 数值容差默认 `1e-12`，只处理活动与并列标识，可设为 0；所有原始数值仍保留。没有活动、没有采样、窗口截断、缺口分开记录。
- 单点可读出排序，但持续时间未知；缺口两侧不能连成一次已证实的连续过程。先升后降说明采样到幅度变化，不等于已经证明具体竞争机制。
- 旧工具仍使用自己的 800 毫秒及分布/幅度条件，可独立调用；历史记录不改判。本轮工具变化不反馈给模型、总线、采样计划或动力学。

UI 在“刺激与输出”的完整时序记录内默认打开“响应读出”，可切换“持续稳定（旧版）”。API `/readouts/{record_id}/response`、CLI `python -m threemind_runtime.observation_cli response`、批处理 `response` 使用同一实现。实时采集窗口和聊天中已经保存的原判定不被悄悄改写。

## 验收与既有证据重读

先验证单点、短脉冲、多峰、恒定总量下的领先变化、并列、零活动、缺口、截断及标签无关性，再重读 E23/E24 已存轨迹。不重新训练，不从结果挑选“好看”的窗口；目标沿用原 A/B 匿名通道身份。输出新旧判据并列及每条源文件摘要，原证据保持只读。

预算：零新模拟、最多 400 个既有记录文件、单进程离线计算 10 分钟上限、新增文件 512 MiB 上限；保留至少 2 GiB 可用内存及 C 盘 5 GiB、E 盘 15 GiB。只有记录不足才提出新的采样需求，不用调内核补造结果。

状态与验证证据见后续交付报告。采样点之间未记录的活动无法靠新算法复原。
