# 机器人实用验证与双向语言适配

[English](../../en/plans/robotics-and-language.md) · [研究进度总表](research-backlog.md)

记录日期：2026-10-02。状态：用户已批准实施；逐项验收以前不表示功能已完成。

## 目标与边界

先回答 ThreeMind 能否在具体环境中发挥作用，再扩大具身和语言能力。先做机械臂，接通人形和移动机器人，随后做受限语言场景。三个类别共用适配器、研究操作目录、快照、实验记录和可视化，不建设三个独立产品。Core、历史身份、旧数据和旧映射保持原义；机器人动力学、控制器和语言模型均在外设侧。环境评分只参与外部选择，不能直接改写 Core 连接。

用户决定默认使用**原始力矩控制**。关节位置／速度伺服、已有技能策略另列选项，记录控制器参数和外部贡献；不支持的模式明确拒绝，不自动代换。真实的质量、惯性、摩擦、碰撞、关节和电机限值保留。模拟躯体不受现有商品机器人控制器限制：自定义三关节机械臂与单自由度夹爪、差速移动底盘先提供可编辑机械描述，供将来实体设计参考，不能称为已完成可制造 CAD。

## 技术和任务

- MuJoCo 为主引擎；Menagerie 提供逐模型核查许可证、固定版本与哈希的真实型号资产；Playground 提供不改原义的公开任务参照。robosuite、ManiSkill、Isaac Lab、Webots／ROS 2 留作需要时的独立适配，不同时重建多套引擎。
- 机械臂先验证接近、接触和推动，再研究抓取；自定义躯体为默认，PiPER、SO-101 为可选真实型号。SO-101 的位置伺服不能宣称原始力矩。G1 先验装载、感官、执行器、观察及恢复；平衡和行走另做实验。移动底盘同理，TurtleBot3 属可选对应型号。
- 新自定义环境物理步长 2 ms，动作／本体感官周期 10 ms；Core 传播周期不随之更改。官方任务保留其周期，修改过的任务另起身份。现有固定匿名输出投影作为明确声明的接线基线，不能称为已涌现的脑区。
- 关节、本体、接触和测距进入匿名输入总线；模型视觉可选，人类三维观察始终可用。任务答案、奖励、隐藏位置只留在评分侧；可感测的环境后果经已声明感官进入。
- 环境任务适配器包含装载、复位、步进、感官采样、动作、只读观察、快照及恢复。复位世界不等于清空意识；死亡不自动复活。完整快照保留 Core、物理积分、适配器、随机状态和在途输入。
- 环境选择增加任务完成、耗时、距离和接触指标，沿用独立出生副本评估与未见环境验证。分清训练成绩、筛选成绩和最终验证成绩。

## 语言路线

使用 Hugging Face Transformers 与 PEFT，复用隔离计算任务；候选输入模型为 Qwen3-Embedding-0.6B，输出为 Qwen3-0.6B。初期冻结基础模型，只训练必要的映射头；需要 LoRA 时单独登记，正式对照前冻结转换器。现有 tiny-transformer 数字序列工具继续保留，不能冒称已具备自然语言能力。

三个独立配置：① ThreeMind 原文本感官／时序读出；② 严格双向转换，解码器只读取声明的 Core 活动过程，不能偷看教学记录、原问题或答案；③ 语言知识辅助，明确记录外部模型可见的信息和贡献。无法读出时显示真实活动或无法解读，不编造回答。

先在受限命名、经历和交互中测试；再模仿婴儿学习，将对象、说话人、共同注意、轮流交互、动作后果及疏密变化的重复联系起来。更远期通过环境演化和种群交互形成可遗传的 ThreeMind 语言结构，逐步减少或移除 Transformer。后两阶段是路线，不是本期已达成结果。

## 操作和界面

在「世界与躯体」增加机器人任务，在「实验与训练」复用课程、分支、选择和报告；增加「对话实验」，保留意识图像旁原有聊天。宽屏同时呈现三维世界、控制和读出，窄屏标签切换。普通流程提供图形表单，JSON 为等价高级入口。相机移动是只读观察，外力施加有明确干预入口与收据。

UI、REST、CLI、MCP 调同一服务及操作目录。独立 Runtime 不依赖 Lab 数据库；部署包携带模型、感官映射、物理单位、控制模式和校准版本。训练器与运行时不能因可视化而相互耦合。

## 验收与实验

工程先验：三个躯体类别实际装载运行，三类控制的明确例子，观察不改变固定输入结果，暂停／步进／分支／恢复、版本拒绝、背压和错误恢复，1440／390 像素界面。真实机器人迁移不能由模拟成功代替验证。

机械臂比较空白、训练后、环境选择后、冻结学习、随机动作；外部伺服／技能结果单列。评估成功率、距离改善、未见目标位置、成本和失败。语言使用转换器训练后才生成的新对应，比较正确、空白、交换、打乱和固定的 Core 活动及 Transformer 单独结果；干预后恢复，并去掉辅助复测。响应受 Core 影响与经验存于 Core 分开判定。

每轮初始探索最多 4 小时、512 回合；单计算任务，8 GiB RAM，GPU 预算 3 GiB 并保留至少 512 MiB。新增证据 8 GiB 停扩、10 GiB 停止并保存；保留内存 2 GiB、C 盘 8 GiB、E 盘 30 GiB。模型／依赖缓存放 E 盘。开始模拟前重取共享额度基线，增加 5 个百分点停扩、8 个百分点停止新模拟；工程验证与实验预算分别记录。Windows 先运行 CPU MuJoCo；Playground JAX GPU 作为 Linux worker 能力，不搭建复杂集群。

## 2026-10-02 补充：真实接口与仿真选择分开

用户澄清原话：

> 补充：你说“SO-101 的原始力矩入口会明确拒绝，避免把它的伺服能力混淆为力矩控制”，这个是完全无法接入，还是说作为可选项，默认拒绝？我希望提供选择，而不是只能拒绝。如果我理解有误的话，你可以纠正我。

据此调整：SO-101 可以通过伺服模式接入；仿真中还可显式选择 `control.actuator_variant=ideal-torque`，保留结构、惯性与力矩限值，以理想力矩执行器替换伺服。默认 `profile` 仍不把不支持的硬件接口伪装为存在；用户的选择、替换方式和控制模式进入协议哈希、动作记录及快照，恢复不能静默换回。仿真实验不受商品固件限制，实体迁移另验。这里取代前文“不支持的模式拒绝”对仿真选择过宽的限制，不表示接通了真实设备。
