# 输入来源、竞争筛选与可恢复边界

当前版本说明（2026-09-08）：新建意识使用 causal/8、state/6；旧版本只读导出，不再原版本续跑。下文版本引入与升级说明属于历史记录，当前默认值和局部公式以[V3 恢复记录](plans/v3-restoration.md)为准。

“感官与输入 → 来源与竞争”显示 17 类来源的配置和有效策略。“调整来源策略”进入共用的图形／JSON 参数编辑器，设置中的项目默认参数也包含这一分组。来源开关属于科学协议；消息是否显示属于当前浏览器的观察偏好，两者独立。

## 准入规则

三类总开关是人工载体、外部 AI、环境与设备。每类另有绕过竞争开关；每个具体来源也有这两个字段，共 40 项。默认所有来源允许准入，所有绕过关闭。

对来源 $s$，类别为 $c(s)$：

$$
E(s)=E_{c(s)}\land E_s,\qquad B(s)=B_{c(s)}\lor B_s.
$$

`E` 决定是否允许接收和排队新载体；`B` 只决定该帧是否绕过通道竞争。具体来源覆盖界面文本、命令行文本、人工匿名帧、重放、AI 环境、AI 调试、音频／图片／视频文件、麦克风、摄像头、网络设备、物理／合成环境、宿主遥测、进程遥测、实例反馈及模拟内感受。未知扩展来源仍受其类别总开关约束；完整标识映射定义在 Runtime 的 `source_policies.py`，API 返回可查询目录。

来源是逻辑身份，不是安全凭据。账户、项目角色、设备令牌及其权限仍须单独满足。设备这一项只控制感官刺激；其匿名输出和标量端口继续遵守独立权限。AI 两项预留给外部工具，不能据此认定已经安装供应商或自动调用模型；ThreeMind 内部活动不属于外部 AI 来源。

## 内核中的逐帧规则

Core 的 `Stimulus` 增加可选布尔 `bypass_attention`。它是作用于单个时间戳事件的数值控制，不包含来源名称、文本或解释。Runtime 从可信配置解析标记，输入载体不能自行携带一个开关来覆盖来源策略。

设正常竞争预算为 $K$，帧的有效通道集合为 $C$，外部标量增益乘积为 $G(t)$：

$$
C_{pass}=\begin{cases} C,& B(s)=1\\\operatorname{TopK}(C),& B(s)=0\end{cases},\qquad I_{pass}=I\,G(t).
$$

实际排序、阈值及计数定义沿用[输入注意](v2-attention.md)。绕过不修改其他同一时刻的帧，也不关闭全局竞争；外部增益为零仍会阻止刺激生效。感官编码、躯体过滤、实验阶段、来源永久关闭、生命周期、能量与计算预算照常执行。不同机制的过滤不可混称为“注意关闭”。

新建模型使用 `causal/7`，仍采用 `state/5` 的账本布局。普通假值在 Core 载荷中省略，使旧事件的序列化保持原样；旧 `causal/6` 可以按冻结状态继续其空间机制。向旧模型显式注入带绕过标记的帧时才升级动力学，先结算旧状态，保留数值格点与原队列。独立 Python、Rust 和本机扩展执行相同规则。

## 改参、采样与证据

暂停并生成检查点后可以修改来源策略，保存时校验协议和版本。边界分为三层：

1. 尚未接收的载体：来源关闭则拒绝，媒体在暂存／解码前拒绝，实时采集在打开设备前由 UI 检查并由服务端复核。
2. 已接收但尚未排队：worker 重新检查当前策略；关闭的帧记录 `source_disabled` 或 `source_category_disabled`，保存原件与过滤原因。
3. 已进入 Core 队列：每帧保留其冻结标记。之后关闭来源不会抹掉在途因果承诺；恢复或分叉也不重新编码这些帧。

相同请求编号的同内容重试返回原回执，即使策略随后关闭；新编号继续按当前策略校验。界面／命令行标识不同的请求不被当作同一重试。

关闭遥测来源会停止对应探针采样，重新开启时重建物理计数基线。模拟世界的运动与躯体过程仍按模拟时间推进，关闭环境传入不等于冻结外界：已形成的采样载体以过滤证据记录，不进入神经网络。显示偏好不会改变任一行为。

数据库 schema 14 仅增加 `input_frames.source_policy`，包括解析后的来源／类别／开关／绕过及解析模拟时间，与输入、检查点、配置版本同事务提交。准入时的策略另存于载体配置；旧帧该列为 NULL，表示未记录，不能补造旧策略。逐帧详情、CSV／JSONL 及历史检查点证据包均携带这项记录。

## 模型与命令行

`runtime-profile/5` 在模型中携带来源策略。旧 profile/1～4 保留其原字段及哈希；未声明策略时沿用默认值。JSON、二进制 `.tmind`、独立 SQLite 恢复存储可往返保存新配置。Lab 仍以 PostgreSQL 为主存储，运行时不反复覆写模型文件。

Lab 文本入口通过 HTTP API，不要求客户端连接数据库：

```powershell
threemind input-text --project <项目UUID> --run <意识UUID> --file .\stimulus.txt --intensity 0.9
```

服务地址可用 `--url` 指定；在线服务器可用 `--username` 并在本机隐藏输入密码。命令先打印请求编号，若响应不确定，用相同 `--request-id`、原载体和原强度重试。不同文本或强度必须使用新编号。回执返回实际保存的来源 `manual-cli-text`。

`--intensity` 可省略，保持原接口的默认强度1；独立运行时对应参数为 `--text-intensity`，省略同样保持1。两者接受0至100的有限数值，0保留零强度对照意义，不会被当作未传参。强度只改变本次输入，不修改模型的感官映射或默认参数。新版意识图像右侧聊天框也有“刺激强度”滑块。

独立 Python Runtime 可直接加载模型并塑造它：

```powershell
threemind-runtime --model model.tmind --text-input stimulus.txt --text-intensity 0.5 --clock unbounded --until-us 1000000 --export result.tmind
```

此入口使用模型中的文本感官和命令行来源策略；Python／Rust 的 `--input` JSONL 均使用人工匿名帧策略。额外输入依据其时间戳递送；已经存在于模型中的在途事件保持不变。
