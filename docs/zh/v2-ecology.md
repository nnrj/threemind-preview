# 生态训练、种群恢复与研究证据

生态训练已接通真实的意识实例、环境选择、数据库原子恢复及图形界面。入口是「实验与训练 → 生态演化」。它与「多代定向训练」并列：定向训练按显式评价指标选择父本；生态训练由声明的身体资源、损伤和繁殖条件决定哪些个体产生后代。两者使用同一个出生规则，不增加预制的语义连接。

容量测量、当前串行执行与累计历史成本见[性能与限制](v2-ecology-capacity.md)。

## 创建与配置

新建时填写训练名称与观察目标，选择空白脑或已登记的先天版本。基本参数包括复制哪一个根躯体、初始个体数和生态调度种子。高级区域默认折叠，覆盖以下配置：

- 共享物理世界或独立栖息环境、资源分配策略，以及资源和损伤区域。
- 摄取、身体维持、动作控制消耗、接触损伤和身体失效条件。
- 繁殖年龄、资源门槛、父本留存、给后代的储备、额外支出、冷却、种群容量及累计后代预算。
- 身体失效后关闭全部外部输入，或只断开身体输入。
- 储备、损伤、附近资源三种身体状态感官，默认分别启用；可单独关闭，配置端口、尺度、增益与刺激强度。
- 出生位置，以及原有的全部 Core、感官、输出器官、输入总线、读出器、能量供应、阶段和记录参数。

页面右上角可切换完整协议的 JSON 编辑，支持行号、高亮、格式化和校验。图形与 JSON 双向同步；格式化不接受重复键，创建时始终进行服务端校验。继承来源的身份参数保持固定，环境规则不通过改变已学习的通道编号实现。世界内所有感官和执行器必须属于选定躯体树，遗漏、端口冲突或不完整的物理区间会报错。

人工、媒体和远程输入默认关闭。需要研究外部干预时，在创建协议中明确开启，再经过已有的来源策略、总线和审计机制递送。环境刺激和身体状态感官不受此人工入口开关替代；它们有自己的开关与来源策略。

创建后整个研究协议冻结，避免中途调整资源和繁殖门槛而仍将结果视为同一实验。个体参数页可通过图形或 JSON 查看，修改需建立新的独立继承个体或新的训练。名称与说明属于档案，和科学协议分开。

## Core、Runtime 与 Lab 分工

`threemind_runtime.ecology.EcologyCoordinator` 负责全局时钟、物理环境、外部资源账本和多个独立脑实例。它可在没有 Lab、数据库和浏览器的 Python 进程中运行，使用参考或原生 Core。传入工厂和观察回调可以接入其他宿主工具。Core 仍只接收匿名刺激，不知道资源、繁殖、个体姓名、身体标签和研究目标。

`CoreParticipant` 管理已有输入总线、身体过滤、内感受、能量供应、被动读出和输出器官。原有读出宿主移至 Runtime 后由 Lab 复用，未重新定义读出算法。开启、关闭观察器或更改观察编号，在刺激相同的条件下不改变 Core 状态。

`LabParticipant` 接入实际输入证据、命令、阶段和宿主遥测；`PopulationWriter` 负责数据库事务；worker 执行整个人口任务。UI 只查询已经提交的数据和发出明确命令，不参与物理求解。关闭页面不会停止训练，显示性能档位也不改变科学参数。

## 时间与出生顺序

全局生态时间记为 \(T\)，个体出生时间为 \(b_i\)。未死亡个体的 Core 时间是 \(t_i=T-b_i\)；已死亡 Core 停留在实际观察到死亡的时间，不能为了与世界时钟对齐而继续演算或复活。

一个物理区间 \([T,T+\Delta]\) 按如下顺序执行：

1. 汇集区间开始时所有活动躯体的实际输出；共享模式只步进一次共同物理世界。
2. 结算区间末端的物理测量、资源和损伤；繁殖暂不执行。
3. 形成完整的物理及身体状态样本，使用 \(T+\Delta-b_i\) 作为该个体的递送时间。保留原始量、归一化量、编码值及输入审计。
4. 每个 Core 完成该时间边界的递送与演算；阶段关闭来源、身体失效和已观察到的 Core 状态落实后，才判断父本是否符合繁殖条件。
5. 对实际符合条件的父本调用 `threemind.birth/1`。后代保留被刺激塑形后的持久网络，清空活动和待处理事件；身体使用声明的出生布局，资源从父本转移。

`birth_due` 是规则层意向；只有实际生成脑状态后才记录 `individual_born` 与 `model_born: true`。每个后代保存父本恢复点、源状态哈希、出生哈希和代数。出生恢复点必须在后代第一次受刺激之前提交，不能把已有经验的状态冒充出生模型。

数值边界可能落在尚未递送完整的物理区间内。例如世界已求解到 20 ms，Core 只推进到 17 ms。恢复点会明确保存 `pending_end_us=20000`、已结算账本和等待递送的刺激；页面同时展示两个时间，不能把身体的未来测量说成意识已经感知到的数据。

尚未被刺激的 Core 为 `waiting`，不是已经死亡。当前默认繁殖条件为身体有效且 Core 未死亡，所以它包含这种等待状态；研究者可配置身体条件对照，但这里没有隐含的认知质量或适应性评分。

## 整体保存、暂停和恢复

schema 39 使用同一个 PostgreSQL 数据库，新增种群、成员、种群恢复点、成员恢复点映射及生态事件表。没有新增另一套数据库。一个事务同时提交世界积分状态、资源账本、全部个体状态、出生谱系、原始输入变化、读出、采样和生态事件。原有脑状态增量行存储继续复用；不会把完整世界重复写到每个个体的恢复点里。

事务失败时整组回滚；旧 worker 的租约失效后无法写入。提交结果丢失时，同一个操作编号可进行内容一致的重试，不重复出生或输入证据。恢复只能按一个固定种群清单读取所有成员，不能拼接各个体的任意「最新状态」。

暂停、继续、重试和取消均在种群页面操作。普通观察提交不会使控制修订过期；相互冲突的控制仍会要求刷新。已接受的暂停／取消与最终提交使用同一把数据库锁，避免被完成请求覆盖。worker 异常标记为执行阻塞，不能作为环境淘汰或意识死亡。

个体页面保留网络、感官、读出、数据查询、模型本体、恢复点和研究入口，并提供返回所属种群的链接。单独精确恢复一个生态成员会缺少共同物理状态，因此被拒绝；可以明确创建独立继承个体，这属于一次新出生。

身体失效且 Core 确实死亡后，宿主在成功提交恢复点之后释放该个体的可变脑实例和展开的增量比较基线。`StateReference` 只持有固定哈希和宿主提供的读取函数；`FrozenCore` 保留已经观测到的时间与指标，需要完整节点、连接或模型时再加载并校验哈希。尚在活动的脑、等待刺激的脑，以及身体仍有效的个体不适用这个优化。被动读出窗口与工具状态保持原样，不能为了节省内存删除原始激活记录。

后续种群提交复用未变化的死亡个体恢复点，不重复加载或复制其模型；如最终读出产生新证据，则仍正常提交。进程重启后逐个校验历史脑状态并释放，避免同时恢复全部死亡个体的可变脑。这里只减少历史脑的常驻开销，没有把工作站改成依赖模型文件的自动读写路径。

## 观察与导出

种群观察提供实际物理姿态、独立栖息环境选择、资源／损伤范围、身体存活和 Core 状态、出生数与代数、繁殖暂缓原因、历史恢复点、个体筛选以及完整原始事件。失效、未繁殖和已死亡个体保留在档案中。窄屏使用个体卡片，桌面使用表格。

每次导出固定一个种群恢复点，随后发生的训练不改变该证据包。ZIP 包括完整协议、种群恢复状态、物理观察、全部个体 JSONL、截至该点的完整生态事件 JSONL、完整提交采样 CSV 及 SVG／PNG 图表；可选包含全部个体的 `.tmind` 模型本体。模型仍可直接交给兼容 Runtime 塑形运行，无须依赖 Lab 数据库。

页面轨迹每段最多 1000 个提交点，事件每页 100 条，个体每页 30 条。导出图表可能按明确记录的提交步长抽样，以控制图形大小；CSV 保留完整提交序列。它们都不是每一微秒的连续物理或神经记录。个体全部输入、读出和轨迹证据通过各自现有导出入口获取，种群包不会声称已经包含这些独立的大型历史。

同一共享环境中的个体相互影响，不能将其数量当作独立重复实验数。存活与繁殖也不能直接证明意识存在、合作意图或道德品质；观察期结束不是已观察到死亡。用于推断的实验仍需独立环境重复和明确比较条件。

## 后续工作与限制

当前实现完成可运行的种群协调、事务、GUI 和证据包。[独立生态训练器](v2-ecology-runtime.md)提供无界面 CLI、可选 SQLite 原子存储及可移植整组恢复包。独立协议和 Lab 研究协议的宿主能力不同，不会静默转换为缺少阶段或命令的部分恢复。[整组记录与报告](v2-ecology-reports.md)已支持固定人口轨迹及全部个体分布，并复用 AI 草案与四种格式导出。

历史死亡脑已支持按需读取，但谱系、账本和读出工具状态仍会随历史增长，不能把「同时存活上限」误当成总内存上限。一个 66 个累计个体、最多 8 个存活躯体的合成探针中，最终 RSS 从 260.32 MiB 降到 104.75 MiB，减少约 59.8%，全部 66 个最终模型哈希一致。该探针使用独立 SQLite 归档宿主验证 Runtime 的内存释放，Lab 的 PostgreSQL 归档另有事务与恢复测试；它不是完整工作站吞吐或任意规模的内存保证。复现脚本为 `scripts/benchmark-ecology-retention.py`，分别运行默认模式与 `--cold`。

尚未完成大种群吞吐验收，也未建设跨进程分布式物理求解器。独立环境在没有存活身体后不继续资源再生，已有库存保留；这是当前环境规则，需要在比较条件中注明。

演化观察播报、运行预警、目标评估和统一适配器扩展继续按[待议方案](v2-observation-and-adapter-plan.md)评估，不会在本阶段暗中加入干预或外部 AI 调用。公式细节见[生态基础](v2-ecology-foundation.md)，遗传语义见[发育与先天版本](v2-development.md)，验收结果见[冻结工程记录](../benchmarks/2026-09-07-ecology-validation.json)。
