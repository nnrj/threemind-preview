# 存储、模型本体与任务队列

本版只有 PostgreSQL 是 Lab 的权威数据库。Arrow、Parquet、Zstd 不是三套数据库；DuckDB 没有作为运行依赖引入。独立 Runtime 的可选 SQLite 只负责设备恢复，不与 Lab 双向同步。

2026-10-10 补充：原件外置、离线位置登记、正式数据包、显式迁移与人工备份工具见[数据管理使用指南](data-management.md)。PostgreSQL 仍为科学状态的权威来源；新策略只影响未来原件写入。本次只在隔离数据库验收 060/061，真实环境尚未升级，通用迁移尚未执行。以下原有设计论述保留。

## 为什么选择 PostgreSQL

研究平台既要保存关系明确的项目、角色、运行和谱系，也要在事务中同时提交节点/边投影、观察记录、输入事件、检查点和作业进度。PostgreSQL 的事务、MVCC、行级安全、批量 COPY、索引和作业领取机制适合这些需求，而且用户可完全在本地部署。

MySQL 同样可靠，但为它再维护一套批量写入、隔离策略、租约语义和迁移测试，目前收益小于成本。SQLite 适合本机单写入者的设备恢复，无法直接提供多机共享工作站所需的并发服务边界。MongoDB 不会自动解决不断替换巨大 JSON 的问题。Neo4j 适合关系遍历分析，但内核每步仍必须使用内存邻接结构；本版没有足够收益将它增加为第二个权威存储。ES/Redis 分别更适合检索/缓存，不能替代主状态事务。

## 数据分工

| 数据 | 形式 | 用途 |
| --- | --- | --- |
| 正在学习的模型 | Rust 内存连续节点/边行与稀疏索引 | 每个数值步的真实演化 |
| 最新可查询状态 | PostgreSQL `nodes`、`edges` 类型化表 | 条件筛选、分页、可视化 |
| 恢复点 | PostgreSQL 不可变版本与分块 BYTEA | 状态、时间相位、完整队列与模拟环境恢复 |
| 输入、命令、观察 | PostgreSQL 有序事件和采样记录 | 研究追溯与图表 |
| 用户请求的导出 | PostgreSQL 分块产物，用户下载后是文件 | 模型交换、证据与外部分析 |

内核不查询数据库，也不在每条边变化后读写文件。worker 周期性提交恢复点和当前投影；运行结束提交最终状态。没有自动维护另一份磁盘 JSON 模型文件。事务采用版本比较和租约代次保护；过期 worker 的写入会被拒绝。

恢复点采用完整锚点与有界行增量。先通过少量确定性抽样识别明显密集变化并直接走完整路径；抽样只决定是否放弃优化，从不决定忽略哪些行。其余情况逐行精确比较，变化／删除行数不超过当前总行数的 25% 且链深度小于 8 时保存增量，超过上限时写入完整 `.tmind` 锚点。完整状态的时间相位、待递送事件、配置等元数据仍随每个版本保存；队列较大时这部分也会占据显著空间。增量投影只 COPY 新增和变化行、显式删除消失行；首次提交及密集回退建立／校正完整投影。

增量是 PostgreSQL 内部的 `row-delta/1` 恢复表示：带长度的压缩 JSON，使用标准 zlib，校验基础状态与结果的规范哈希，包括浮点正负零和表行顺序。它不会成为第二个公开模型格式，也不引入新服务或自建 WAL。每个链最多读取一个完整锚点和 8 个增量，基础版本有同项目／同运行外键保护；不能单独删除仍被引用的锚点。导出始终还原成独立的 `.tmind` 或等价 JSON。数据库升级使用 `002_checkpoint_deltas.sql`，旧完整恢复点直接可读，无需迁移旧 `data/`。

每个运行有一个后台写入线程和至多一个待写快照。内核线程捕获不可变字节后继续推进，写入线程编码并按版本顺序提交。下一次捕获前若写入未完成，则等待它，避免无界堆积。结束、暂停、强制检查点和导出屏障须等提交成功；过期租约或提交失败停止推进并传播错误。此机制不是零复制，不能消除全状态捕获、哈希和密集变化的成本。`trace` 模式逐数值边界同步确认，会显著增加开销。

输入与采样记录始终标注采集范围；相邻检查点的连接变化是区间差异，不会伪装成每次内部传播的完整逐事件轨迹。

## Arrow、Parquet 和 Zstd 的具体理由

Arrow 定义跨语言的有类型列式内存与二进制交换格式。相同列的数值连续存放，整数身份、浮点状态、时间字符串均有明确类型；Rust 与 Python 可互读，避免自行发明一个没有工具生态的二进制布局。`RecordBatch` 是一批有相同 schema 的列，不是一个数据库。当前主要用于模型状态块，前端显示使用专用 TypedArray 缓冲，不宣称已经全链路零复制。

Parquet 是适合列选择、压缩和外部统计的文件格式，本版只在用户主动导出筛选数据时使用。Zstd 是压缩算法，用于 Arrow IPC 状态块与 Parquet 列块，减少数值表体积。它们不会创建额外常驻服务或另一份自动更新的数据源。

DuckDB 是可嵌入的分析 SQL 引擎，适合研究者直接查询下载的 Parquet 文件。它不是本版必须安装的第三个数据库；用户可以使用自己熟悉的 Python、R、PostgreSQL 或其他统计工具。

## 标准模型本体 `.tmind`

`.tmind` 是带明确版本的 ZIP 容器，包含 `manifest.json`、`state.json`、`nodes.arrow` 和 `edges.arrow`。Arrow 文件中的数值批次使用 Zstd 压缩；小型 JSON 保存规则、时间相位、生命周期和待处理队列。每个成员有长度和 SHA-256 校验，另有逻辑状态哈希；导入检查成员名单、版本、类型、空值、重复字段、图引用和压缩展开预算，不执行模型中的代码。

`state/3` 还保存容量与计算预算的周期账本和 128 位累计计数；它属于模型因果状态，放在 `state.json` 元数据中，节点／边 Arrow 列不变。数据库恢复点及 SQLite 保存同一状态；Lab 的历史观测从同一数据库按需查询／导出，没有增加另一套计数文件或数据库。

`state/4` 增加[可选能量账本](v2-energy.md)和时间戳资源事件，节点／边 Arrow 列仍不变。外部储库额度、周期与在途承诺放在同库检查点的宿主上下文中；它不是模型偷偷自带的无限电源。数据库 schema 9 只增加幂等供给命令索引。账本、命令进度、实际供给事件与模型同事务提交，失败回滚；独立 Runtime 的最终 SQLite 检查点也覆盖在目标时间之前发生的不可逆死亡。

JSON 模型是该状态的等价转换。浮点值使用 IEEE-754 位模式参与规范化状态哈希，保证格式转换没有悄悄降低精度。标准模型包含核心继续演化所需的全部状态；要重放原模拟环境，应使用研究证据包中保存的环境恢复上下文和输入协议。

筛选导出的 CSV/JSONL/Parquet 是研究数据子集，不是可运行模型。导出包附带 `selection.json`，说明过滤条件、行数、时间、版本和来源哈希。两个独立学习的分支不能被当作普通数据库记录静默合并。

## SQLite WAL 和数据库可靠性

WAL 是 SQLite 的一种写前日志模式，仍然是 SQLite。同一时间仍只有一个写入者，但读取可以与写入并行。日志随后通过 checkpoint 合并到主数据库；开启 WAL 不是取消文件 I/O，也不是备份方案。设备库使用 `synchronous=FULL` 和版本比较，保留有界恢复窗口。

原生 Runtime 随 Rust 依赖构建维护中的 SQLite；Python 版本的恢复辅助库使用 Python 自带 SQLite，部署者应随 Python/系统更新其 SQLite。Lab 不依赖这一辅助库的 SQLite 版本，它使用 PostgreSQL。不要把 SQLite 数据库文件放在网络共享盘上让多台 worker 同时写入。

PostgreSQL WAL 负责数据库崩溃恢复，研究事件表负责可解释的刺激/干预证据，两者不可互相代替。恢复点、数据表和导出仍需备份验证。当前版本使用顺序 SQL migration 与独占迁移锁，没有为了跨数据库假设增加 ORM。

## 为什么暂不引入独立 MQ

当前作业包含运行、配对实验准备、统计分析和导出。它们在 PostgreSQL 中持久化，以 `FOR UPDATE SKIP LOCKED` 领取，使用租约、心跳、失败状态与不可变结果。导出屏障也以数据库命令序号为准。任务状态与数据提交共享事务，比第一版同时维护一个消息代理更容易验证。

如果未来需要多种实时消费者、跨区域路由或高吞吐事件流，再引入 MQ；它只负责交付，不获得模型状态的权威地位。MQ 本身不能保证端到端只执行一次，应用仍需幂等和过期写入保护。

原始资料：[PostgreSQL MVCC](https://www.postgresql.org/docs/current/mvcc-intro.html)、[PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)、[Arrow 列式格式](https://arrow.apache.org/docs/format/Columnar.html)、[Parquet](https://parquet.apache.org/docs/)、[SQLite WAL](https://sqlite.org/wal.html)。

## 输入记录与可复用感官配置（B1）

`004_sensory_inputs.sql` 增加载体表和帧表，仍使用同一个 PostgreSQL 数据库与项目 RLS。人工载体接收与命令同事务保存；运行时递送证据与对应检查点同事务保存。来源信息独立于纯刺激事件载荷，事件另有提交版本，避免历史检查点混入后来在同一模拟时刻产生的事件。升级前的事件没有提交版本，历史导出对这部分仍只能按模拟时间筛选，不能补造精度。

标准模型清单增加可选运行时感官配置和独立校验值。B1 包括感官种子与文本编码配置；B2 的 profile/2 进一步携带音视频感官与输出器官配置，保证导入复用相同接线。SQLite 设备恢复也按状态版本保存该配置。详细数据流、预算、导出范围与限制见[输入说明](v2-inputs.md)。本次没有读取或迁移旧 `data/`。


## 媒体原件与器官记录（B2）

`005_media_carriers.sql` 增加项目内按 SHA-256 去重的媒体原件与 1 MiB BYTEA 分块，以及接收时冻结的转换帧。原件、信封、转换帧及命令在同一事务提交。没有增加文件数据库、MQ 或自动更新的模型 JSON；媒体原件与运行模型按需分开导出。

执行使用冻结匿名帧并校验哈希；实际递送结果与 Core 检查点原子保存。零刺激载体同样有处理提交版本，避免漏出历史证据。器官输出记录带配置、完整像素／振荡器值和提交版本，随检查点保存，并支持分页查询和 JSONL／PNG／WAV 导出。流程与模型互操作见[媒体说明](v2-media.md)。
## 物理遥测补充（006）

遥测原始测量与转换审计保存在检查点事务中的 `events.telemetry_sample`，与对应 `input_envelopes`／`input_frames` 同时提交。006 只增加按运行与 ID 查询的部分索引；不新增数据库产品。按需导出 CSV／JSONL，模型 profile/3 保留遥测配置。详见[物理遥测](v2-telemetry.md)。

## 读出状态与证据（007）

截面／时序读出写入同库事件，未完成窗口、累计指标、基线和下次采样时间随检查点恢复上下文原子保存。007 增加部分查询索引。历史列表在数据库侧移除大数组，节点／连接／轨迹分别分页；只有用户显式导出时返回完整记录。图表以全部已保存轨迹生成。证据包的提交版本边界同样约束读出事件，避免旧检查点混入后来在同一模拟时刻结束的窗口。

读出配置是研究观察协议，不额外升级模型 profile。JSON／CSV／JSONL／图表是数据库记录的按需导出，不是新主存储或自动覆写的模型文件。完整范围和采样限制见[读出说明](v2-readouts.md)。

## 连续物理采集（008）

`capture_sessions` 保存会话绑定、冻结感官配置、源时钟声明、转换器恢复状态和固定模拟时间原点；`capture_packets` 保存序号、原件哈希及输入信封引用。二进制原件复用 005 的同库分块 BYTEA，感官帧复用冻结转换表。原件、连续编码状态和输入命令在同一个事务确认；相同序号的原件重试幂等。worker 的递送与队列仍由检查点事务确认，不能将 HTTP 接收凭据当作内核已经递送。

会话与媒体表共享项目行级隔离。暂停、结束、错误和超时释放采集占用，不删除旧证据，也不修改在途刺激。浏览器队列有界，未确认块不宣称已入库。没有新增数据库或 MQ，也没有自动写模型文件。协议、音画时钟边界与查询／导出范围见[连续采集说明](v2-live-capture.md)。

## 连续器官与模型 profile/4（B6）

发声器／投影器的下次采样时刻保存在检查点恢复上下文；输出通过 OutputBus 的证据订阅写入同一个检查点事务。浏览器 SSE 只查询各器官最新的已提交输出，不另存一份流数据库。完整记录仍可分页、按条件查询和导出，显示跳帧不影响研究证据。

模型 profile/4 新增输出间隔、频率范围与增益，Python／Rust／SQLite 均保留往返。旧 profile/1～3 使用旧字段契约校验，保留原始配置形状及哈希，在执行时补用旧等价默认值。本批没有数据库迁移，schema 仍为 8。详见[连续器官说明](v2-continuous-output.md)。

## 可选核心机制与模型规则版本（C1）

新模型的核心规则为 `causal/2`，独立于感官 profile/4；节点／边的数值列和同库表结构没有改变。新规则增加 11 项可选参数，包含可大于 1 的抑制势上限，导入校验按模型配置约束该列。旧 `causal/1` 模型按其原版本继续，使用新机制时由显式参数干预升级并记录版本前后值。旧检查点不修改，默认没有旧数据扫描或迁移。

模型状态省略新增字段的规范默认值以保留旧模型表示；运行协议与图形配置展示完整值。所有模型由版本确定相同默认值，不让不同设备自行猜测。具体默认值、哈希控制和升级规则见[可选内核说明](v2-optional-core.md)。本批仍使用数据库 schema 8。

`state/5` 保存[注意账本、有效来源期限和在途调制](v2-attention.md)，Arrow 节点／边列不变。schema 10 的逐帧 `input_gate` 与原始 `stimulus` 分列，和递送检查点一起提交；用户导出时可同时核对输入与实际选择。全程仍使用同一个 Lab PostgreSQL。

C5 的 causal/6 沿用 state/5：空间坐标由固定种子、节点身份和坐标轴确定性推导，模型只持久化配置与已有节点／连接，不重复存储可推导坐标。检查点统计记录该版本真实的空间邻域摘要；页面及导出从选定检查点重建全维距离，包含状态哈希、观察时间与状态结算时间。此只读查询有全图成本，不能当作常规实时渲染轮询。
