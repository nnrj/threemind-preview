# 实验笔记：写作、草稿与笔记本

2026-10-10 浏览入口修订：菜单现在先显示全部授权项目中本人可见的笔记／草稿，资料行显示所属项目。打开笔记进入其原项目的写作页；新建先明确选择项目。下述写作、笔记本和修订说明仍适用于该所属项目工作区。见[全局浏览指南](global-resource-browsing.md)。

本模块是研究者的个人写作工具，不改变意识内核、科学参数、刺激总线或原始测量。入口是“实验笔记”，包含写作、草稿、笔记本。内容存入当前部署的 PostgreSQL；本地工作站无需账号或云端服务，在线模式按账号和项目隔离。

## 使用方式

写作默认打开 Markdown，提供行号、语法高亮、查找替换和撤销。切换“文档”进入类似 Word 的所见即所得编辑，包括标题、字体、字号、颜色、对齐、清单、引用、代码、链接、图片、公式、表格及单元格合并、拆分。全屏编辑适合长文；不依赖 Microsoft Word。

草稿默认无分类，也可以在写作页创建分类。选择“笔记”后默认保存到默认笔记本，可以新建其他笔记本。正文和保存位置一起提交；草稿转笔记、重新分类和移动笔记本不复制正文。默认笔记本由数据库事务按账号和项目唯一创建，可改名但不能归档。

草稿默认列表，笔记本默认封面书架，两者可切换列表或卡片。支持标题／正文搜索、排序、分类筛选和分页。笔记可归档、恢复；笔记本或分类需要先移动或归档其中的活动笔记，再归档容器。归档视图中的“全部已归档笔记”也能找到仍位于活动笔记本里的旧笔记。若笔记本已经归档，先恢复笔记本再恢复其笔记。

## 保存与冲突

停止输入约 1.2 秒后自动保存，也可点击“保存”或使用 Ctrl / ⌘ + S。保存显示等待、进行中、成功修订号或失败。每次只有一个写入请求；保存期间继续输入的内容随后提交，不用前一个请求的响应覆盖后续文字。

每个请求携带随机操作编号和预期修订号。网络中断后的原请求使用同一编号重试，数据库返回原修订，避免重复写入。服务端已有较新修订时拒绝覆盖，当前内容保留，可另存副本或明确放弃本地修改后载入最新修订。正文、元数据、修订与附件引用在一个事务中提交。

修订记录可以查看旧稿，再载入写作区保存为新修订。归档／恢复也形成修订。数据库触发器拒绝更新、删除既有正文修订及其附件引用；这里的不可变性约束应用角色，数据库所有者仍承担备份和管理责任。

浏览器标签页以 `sessionStorage` 暂存尚未确认的写作内容，按账号、项目隔离。这是断网恢复缓冲，不是权威存储；退出登录或换账号会清理。切换项目不会把另一个项目的草稿显示过来；返回原项目可以明确恢复。浏览器存储失败时给出提示，关闭带未保存内容的页面会触发离开提示。缓存合并写入，避免每次按键同步复制整篇正文；发送前立即登记待确认请求。

## 两种正文格式的边界

每个修订只保存一种权威正文：`{format: "markdown", text: "原文"}` 或 `{format: "document", content: 文档树}`，不会保存两份各自更新的正文。这个选择根据编辑器原型确定，替代最初“所有正文都先转成统一树”的设想，从而保留用户实际书写的 Markdown 源码。

文档转 Markdown 时，普通标题、表格、清单、代码、公式尽量使用 Markdown。字体、颜色、对齐、合并单元格和列宽在必要的块中使用 HTML。转换结果会重新解析并比较语义结构；已知会丢失结构或样式的转换被拒绝，保留当前文档。颜色的等价 CSS 写法和空默认属性被规范化后比较。

Markdown 转文档前保存原稿。文档模式支持编辑器定义的节点和样式，不能承诺任意 HTML、嵌入网页、自定义插件语法均可编辑；未识别内容仍能在旧修订中取回。正文上限为 1 MiB，文档树同时限制层数、节点数、表格布局规模和属性。公式使用 KaTeX 的非信任模式，不执行正文中的脚本。

React 界面采用固定版本 Tiptap 3.31.3 / ProseMirror，Markdown 源码使用项目原有 CodeMirror 的共用编辑基础。工具栏参考了 PoemHaven 的富文本编辑器，未改变 PoemHaven 文件。编辑器随笔记路由加载，不随每次图谱轮询创建；界面换语言不替换文档、科学文字或撤销历史。Tiptap 的 Markdown 能力仍应按实际用例验证，不能仅凭库名承诺保真，参见[官方 Markdown 文档](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage)。

## 图片、隐私与数据库

图片使用 PNG、JPEG、WebP，单张不超过 8 MiB、1600 万像素，仅支持静态图片。上传流按字节限制，复用媒体解码并发槽；服务端检查实际图片格式和校验结构，不信任文件扩展名。图片直接保存为数据库 `bytea`，登记 SHA-256；当前每人每项目图片总额为 1 GiB。这个小型私有附件路径不替代大规模科学证据的分块产物机制。

“图片附件”列出当前账号的图片及引用状态。未被任何修订引用的图片可以删除；从当前正文移除图片并不会删除旧修订引用。图片 URL 的项目、所有者和规范路径均受校验；读取按当前会话鉴权，响应不缓存。后续记录／报告公开分享不能直接公开这些私有图片 URL，需形成明确授权的固定资源包。

schema 25 在同一数据库增加 `note_collections`、`notes`、`note_versions`、`note_assets`、`note_asset_refs`。五张表强制启用项目和作者双重 RLS。接口在事务内再次检查成员角色与账号状态；项目 owner / researcher 可写自己的笔记，viewer 只读已有自己的内容。平台管理员身份不会赋予读取其他人的私人笔记权限。

旧 `data/` 未扫描或迁移。Core `causal/7`、模型 `state/5` / `profile/5` 和 419 项科学参数没有变化。新“实验记录／报告”的事实数据引用、AI 生成、DOCX / PDF 等导出以及公开分享仍在[后续模块方案](v2-notebooks-and-reports.md)中推进，不能把个人写作模块视作这些能力已经完成。
