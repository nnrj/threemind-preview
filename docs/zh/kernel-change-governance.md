# 内核改动授权、版本保真与工具时间隔离

2026-10-13，依据用户本轮明确要求生效。[English](../en/kernel-change-governance.md)

## 用户要求

> 除临时实验外，内核开发中，任何未经我明确授权的内核改动，都必须询问我，与我确认。任何内核改动，必须明确输出改动的内容和影响让我看到。任何内核改动都必须给出理由。

用户同时要求：工具的物理耗时或暂停不应影响意识内部的模拟时间；不能以工具只改变很少模拟时间为理由接受干涉。选择版本2必须执行真实的版本2。

## 执行规则

1. 实施前列明版本、原行为、新行为、理由、授权出处及预期影响。用户已经明确批准的范围直接完成，不逐行重复索取许可；新机制、新默认或超出范围的修复先问用户。助手写入文档的“已批准”不是独立授权证据。
2. 区分动力学变化、数值语义变化、实现优化和只读工具。改变学习机会、门槛、顺序、裁限、时间积分、信号分组，都可能改变动力学，不能只凭函数名/系数没变称等价。
3. 临时实验必须是明确隔离的新工程样本或已批准的对照副本，结果标明范围；不能借此改动正式个体、默认配置、已发布内核或原始研究证据。
4. 披露交付的实际改动、理由、验证、未验证影响和残余问题。未经证明的优化不能宣称全系统等价；Core不读取某值，不代表表达器或保存恢复不依赖它。
5. 历史内核按自身身份创建、执行和恢复。新版本不覆盖旧版定义、冻结夹具或旧实验；即便共享源码，也须验证旧路径行为。发现历史版本问题不能悄悄以原身份改正。

## 工具与内部时间

观察、统计、绘图、保存、导出、性能探针、认证和宿主等待不属于意识的内部经历。它们不得隐式调用刺激、恢复、学习、参数干预或推进接口；不得依墙钟延误直接给模拟时间补量、丢弃内部事件或改变事件次序。

内部推进由显式输入/协议及执行器的模拟时间目标决定。实时、缩放、暂停等宿主控制需遵循声明的时钟语义；实验工具阻塞或用户暂停时，恢复仍从完整当前内部状态接续。真实外界输入及明确授权的推进可以影响个体，但必须作为实验输入/执行记录呈现，不能藏在观察操作中。

验证至少包括：有/无观察、频繁/稀疏观察、不同advance_to分批、宿主等待或虚拟墙钟跳变、完整保存恢复、同刻输入及到期边界。检查内部时间、事件顺序、完整状态和下一输入响应；不能只比较图像或末态节点数。

本约束不意味着模拟无需时钟，也不允许省略必要的遗忘/失效事件。它要求工具耗时与模型时间解耦，不向模型偷加经历。
