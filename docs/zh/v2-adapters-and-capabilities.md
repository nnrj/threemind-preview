# 适配器目录、设备能力与配置边界

ThreeMind Core 只执行匿名状态、因果连接和事件规则。适配器在 Runtime 边界产生刺激、过滤外部载体、提供显式标量或观察已提交的输出。目录用于找到实际工具及其配置，不会因为浏览此页而执行输入、申请媒体权限或改变模型。

## 入口与配置

“设置 → 设备与适配器”包含能力检测、适配器目录和接入验收；每个意识的“感官与输入 → 适配器目录”显示本意识的绑定。可按名称、参数名称／键、输入／输出方向和配置启用状态筛选。展开条目能查看总线端口、版本、实际参数、单位与不可变规则，再直接打开对应工具或参数分类。公共声明、兼容性核对和独立开发工具见[适配器 SDK](v2-adapter-sdk.md)。

`threemind_runtime.registry.AdapterRegistry` 注册 22 个内置契约，包含文本、匿名帧、物理／合成环境、躯体过滤、内感受、重放、三类遥测、音视频感官、浏览器连续采集、发声／图像器官、两类读出、能量与调制端口、网络设备。默认值和类型校验来自执行这些功能的实际配置类；Lab 从同一份参数目录补充图形说明。注册表拒绝重复身份、非法方向和未知参数，不通过页面动态加载或执行任意插件。

不另建适配器配置库。模型及 Runtime 配置仍在 `runs.spec`，设备权限和限额在 `device_bindings`。默认目录是契约默认值，选择意识后才是该意识的实际配置。379 项统一参数、60 项核心参数及创建后不可变规则保持一致。暂停编辑仍需要完成检查点，保存必验、版本冲突检查、历史追踪和 JSON 双向配置均沿用已有编辑器。

“配置已启用”不表示正在采集。目录单独显示依赖条件，例如躯体过滤需要物理或合成环境，连续设备与真实遥测需要实时时钟；网络输入需要尚未过期、未撤销且签发者仍有研究权限的设备绑定。显式关闭外部来源、暂停、结束、权限变化等执行边界仍由对应 Runtime／API 验证。

## 三种检测范围

| 范围 | 检查方式 | 结果的含义 |
| --- | --- | --- |
| 接口服务 | 内存中单样本 WAV／单像素 PNG 往返、压缩音视频解码器注册查询、WebSocket 依赖导入 | 只描述该 API 进程；视频帧还必须具备图像转换依赖。不能证明所有文件均可解码或满足预算 |
| 工作进程 | 独立空内核推进 1,000 微秒、独立平面躯体物理步进、宿主与进程计数可用性 | 不使用研究模型。只保存逐项可用性及缺失原因，不保存探测中的物理读数。速率项首次检测可能尚无基线 |
| 当前浏览器 | 查询既有权限、枚举可见设备数量、检查 Web Audio、建立并释放 WebGL2 上下文 | 不调用 `getUserMedia`，不开始采集、不弹授权询问；结果只保留在当前页面。支持 WebGL2 不等于帧率保证 |

状态区分可用、部分可用、不可用、尚未检测、尚未授权、权限已拒绝。无权限或无读数不伪造零值。API 的安装情况不能替代浏览器权限或远程 worker 的依赖。实际媒体仍须经过原件存储、解码、预算及时间校验。

工作进程启动时生成自己的能力报告，并持续更新心跳；页面把最近 90 秒有心跳视为在线，报告时间另列。依赖变更后须重启该进程重新检测。内核探测失败时，进程报告原因但不领取任务，也不默默切到另一种内核。当前领取事务已经按任务实际所需能力匹配，详情见[执行节点调度](v2-worker-scheduling.md)。部署者仍需安装实际依赖；能力声明不是所有驱动和长期吞吐的保证。

全局进程目录限管理员读取。项目成员可以在有权限的意识内读取最近分配的工作进程报告；该报告可能来自历史执行，因此仍须结合运行状态和心跳判断。公开平台中的项目隔离继续由访问校验和 PostgreSQL 行级权限执行。

## API 与版本

- `GET /api/v2/adapters`：已认证用户可读取默认契约。
- `GET /api/v2/capabilities`：API 能力及管理员可见的 worker 目录；API 检测缓存最多 30 秒。
- `GET /api/v2/projects/{project}/runs/{run}/adapters`：实际配置、依赖状态、有效设备绑定、来源开关、API 和最近 worker 报告。
- 原 `/sensory` 接口使用同一注册表，避免两套目录漂移；既有媒体预算字段继续兼容。

目录与能力检测不改变 Core、模型状态和时间规则。当前为 state/5、causal/7、profile/5；公共契约沿用 Lab schema 46。[大媒体续传](v2-media-uploads.md)、读出及其余工具的具体交付和验证边界见[恢复清单](v2-capability-restoration.md)。
