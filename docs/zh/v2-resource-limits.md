# 模型容量与计算预算

C2 恢复四项核心约束。它们是可选的科学条件：改变节点出生、连接出生、适应或传播的机会。显示性能档位只控制观察与绘制，不自动修改这些参数。入口在新建／暂停编辑／项目默认配置的高级分类“模型容量与计算预算”；图形与 JSON 双向同步，保存必校验。

## 参数与默认值

| 参数 | 默认 | 语义 |
| --- | --- | --- |
| `max_nodes` | null | 同时存在的节点容量；满额时拒绝新受体出生 |
| `max_edges` | null | 同时存在的有向连接容量；满额时拒绝新边出生 |
| `propagation_limit` | null | 每次传播周期最多实际发出的合格正兴奋边操作数 |
| `edge_adaptation_limit` | null | 每个固定模拟时间周期共享的连接适应次数 |

空白／`null` 表示不限制；`0` 明确禁止该类操作。合法整数范围是 0～2⁵³−1。容量调低不删除已有结构；既有连接可以继续适应，自然遗忘／修剪仍依原规则发生。拒绝新受体不是输入传输丢失：原始输入仍在证据中，内核另计出生拒绝。已有受体不因为容量满额而停止接受刺激。

这些设置不是保证 CPU 调用耗时的实时调度器。候选筛选仍须访问符合条件的节点／边；特别是时窗关联，最坏情况下仍需枚举二次数量的候选对。有限预算使用有界候选集合，不额外保存完整的二次候选数组。默认不限时保留原有迭代路径。

## 周期与选择顺序

causal/8 的预算周期独立于数值步长。设传播周期 `propagation_interval_us` 为 $h$ 微秒（默认 100,000），当前模拟时间为 $t$，适应周期起点为：

$$p(t)=\lfloor t/h\rfloor h$$

显式修改传播周期会从生效时刻重置本周期用量，并记录配置变更。周期是 $[p,p+h)$，与宿主速度、页面刷新和调用 `advance_to` 的次数无关。设限额为 $L$、同周期已经使用 $U$ 次，则剩余额度为：

$$R(t)=\max(0,L-U)$$

共同触达／时窗关联引起的适应，与兴奋传播引起的可塑更新，共享这份额度。时间戳相同的已排队事件先按既有因果顺序递送，再进行该格点传播。一个事件内的候选按激活乘积降序，源身份和目标身份升序消除并列；仅保留剩余额度允许的候选。所选候选即使因连接容量不足而不能出生，也已占用一次适应检查。它同时产生出生拒绝计数；这两类计数不能简单相加解释为丢失输入数。

传播预算先按源激活降序／身份升序选择源，再按出边权重降序／目标身份升序选择正兴奋操作。没有额度的正兴奋边不发出新信号；已经排队的信号不被删除。抑制扩散不受此兴奋预算限制。允许传播但适应额度用完时，信号仍能传播，只跳过该次连接可塑更新。可塑性关闭时不会消耗连接适应预算。

相同配置重存是精确空操作。暂停、恢复、观察、模型导出和同周期修改限额都不会重置已使用额度。额度只在启用适应限额时记账；显式暂时关闭该约束的操作不计入有限预算，重新启用仍保留该周期之前记录的使用量。跨周期的账本在实际使用时才推进；查询剩余额度是纯读取。降低限额至已使用量以下，剩余额度为零。

## 可查询的客观记录

“意识详情 → 动力学 → 容量与预算”显示最新检查点计数，以及按模拟微秒筛选、分页的历史观测。四个累计字段分别是：

| 字段 | 一次计数代表什么 |
| --- | --- |
| `node_capacity_rejections` | 正直接刺激需要新受体，但节点容量已满 |
| `edge_capacity_rejections` | 已选中的合法出生候选因连接容量已满而拒绝 |
| `adaptation_budget_skips` | 合法候选或传播可塑更新因当前周期额度不足而跳过 |
| `propagation_budget_skips` | 正兴奋边操作因当前步传播额度不足而跳过 |

计数保存在 `threemind.resources/1` 账本，使用 128 位无符号十进制字符串；不通过浮点数存储或显示。超出上限后饱和并置 `counter_overflowed=true`，此后相应饱和值是下界。`since_us` 标明统计起点；不补造升级前的数据。观测之间的累计差不是每次操作的精确时间戳。

API 路径为 `/api/v2/projects/{project}/runs/{run}/resources`，支持 `after`、`until`（包含两端）和 `limit`；`/resources/export` 支持 `format=jsonl|csv`，筛选范围相同。导出读取同一 PostgreSQL 可重复读事务，流式生成全部所选观测，不受页面分页限制。JSONL 首行包含筛选范围、运行 ID、导出时的数据版本和状态校验；CSV 同时附带版本、参数和质量字段。统计与检查点在同库事务提交，没有新建第二套计数数据库。

## 版本、恢复与独立运行

新建使用 `threemind.causal/3`、`threemind.state/3`，必须携带账本。默认四项不限时，除版本和零账本外，与同源旧控制的演化相同。旧 `causal/1`、`causal/2` 使用 `state/2`，继续运行和导出保留旧哈希；旧模型第一次启用任一限额时升到 3，从明确的当前时间开始记账，不修改旧检查点。只编辑 C1 机制的旧模型仍可从 1 升到 2。

`.tmind` 的元数据保存账本，Arrow 节点／边块无需新增列。等价 JSON、Python Runtime、独立 Rust Runtime 和可选 SQLite 恢复均保留相位、使用量、计数与在途队列。独立运行仍可接受刺激并改变结构，不依赖 PostgreSQL 或反复改写来源模型文件。继承出生显式重置时间与计数；普通继续或同状态分叉保留账本。

这次交付恢复容量与适应／传播预算，不代表注意选择、能量或空间机制已经完成；各项见[功能完整性清单](v2-capability-restoration.md)。
