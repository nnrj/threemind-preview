## 菜单与职责

建议保留两个独立菜单：

| 菜单 | 子页 | 用途 |
| --- | --- | --- |
| 实验笔记 | 写作、草稿、笔记本 | 自由写作、假说、过程注记、整理；可以关联意识/实验但不强制 |
| 记录与报告 | 实验记录、实验报告 | 从真实数据形成结构化图表、事实摘要、解释与可导出的研究材料 |

“实验与训练”继续负责执行协议，“数据查询”负责取数，“模型与证据”负责模型和不可变产物。这些服务被记录/报告复用，不再另做一套统计引擎。旧版曾有实验执行记录和 Markdown 报告，因此恢复执行审计是既有工作，新模块重点增加写作、引用、组织和排版能力。文档中的历史记录不会自动变成新数据库中的实验事实。

## 笔记

写作页包含标题、Markdown / 文档模式、内容类型和保存位置。“文档模式”指类似 Word 的所见即所得编辑，不表示运行 Microsoft Word。草稿默认无分类；可在选择器中新增分类。笔记默认选中当前用户在当前项目下的“默认笔记本”；可以选择或新建其他笔记本。

草稿页默认列表，支持分类、搜索、排序及列表/卡片切换。笔记本页默认书架式封面卡片，从左到右、从上到下排列，封面下方显示标题及笔记数量，也支持列表。进入笔记本后查看其笔记；草稿转笔记、移动笔记本、改分类是元数据操作，不复制或丢失正文。默认笔记本首次使用时由事务创建，不依赖预先联网。

正文自动保存到数据库并显示保存状态，使用版本号防止两个窗口覆盖；提供手动保存、撤销与修订记录。浏览器可保留明确标注的未提交恢复草稿，它只是断网缓冲，不成为另一套权威存储。账号、项目切换时清理隔离缓存，不能把 A 项目的草稿展示给 B。

## 编辑器选择与参考

已经查看 PoemHaven 的 `poemhaven-web/app/components/VditorEditor.client.vue`、`RichTextEditor.client.vue`。前者是 Vditor 的 Vue 封装，底层不是只能在 Vue 使用的算法；后者使用 Tiptap 的 Vue 绑定。可借鉴工具栏、全屏、表格、图片、保存状态与字体布局，ThreeMind 使用 React 绑定并保持当前主题。

实施候选优先采用 Tiptap / ProseMirror 的 React 文档编辑，配合 Markdown 编辑面板；正式确定前用包含表格、公式、图片、引用和图表的真实样例验证双向转换。Tiptap 的 Markdown 扩展提供文档树与 Markdown 转换基础，不能据此推断所有富文本样式都能无损转换，参见[官方 Markdown 文档](https://tiptap.dev/docs/editor/markdown)。Vditor 的 React 封装也是可行备选，不为了“React 版本”而引入维护状态不明的二次包装。

富文本中的字体、颜色、合并单元格等没有标准 Markdown 等价表示，不能承诺任意格式完全无损转换。原型确定每个修订只保存一种权威正文：原始 Markdown 或文档树；文档转 Markdown 必要时保留 HTML 块，并重新解析、比较结构后才接受转换。切换前保存原稿，避免丢失不受支持的源码。这个选择替代最初统一正文树的候选方案；版本化资源引用仍由数据库维护。

## 实验记录：可核对的证据视图

创建记录时选择意识实例、实验、具体运行/条件、时间区间和数据版本。运行中的对象先获取一个明确的数据库水位/检查点；之后继续运行不会让已保存记录里的图表悄悄改变。

默认给出与所选数据相适应的候选内容：协议和种子、时间轴、节点/连接规模、激活/饱和曲线、权重分布、输入与干预事件、阶段指标和已完成的配对统计表。未采集的数据不提供虚构图表；显示采样间隔、覆盖范围、缺失/删失信息和统计单位。用户勾选模块后可调整指标、分组、范围、图形类型和文字说明。

同一次实验可以建立多份记录，每份有自己的分析关注点、过滤条件和修订历史。后台数据结构的唯一键是记录 ID，不以实验 ID 限制为一条。

手工操作与 AI 生成构造同一种版本化 `record_spec`。示意结构如下，标识仅表示引用占位符：

```json
{
  "schema": "threemind.record/1",
  "title": "刺激撤除后的活动变化",
  "sources": [{
    "id": "source-1",
    "run_id": "已授权的运行 ID",
    "checkpoint_id": "固定检查点 ID",
    "time_range_us": ["0", "24000000"],
    "dataset_hash": "服务端生成的证据哈希"
  }],
  "blocks": [
    {"id": "figure-1", "type": "chart", "source": "source-1",
     "metric": "mean_activation", "chart": "line", "aggregation": "none"},
    {"id": "text-1", "type": "commentary", "markdown": "对现象的解释与待验证假说。"}
  ]
}
```

客户端编辑的是图表意图，后端校验引用权限、指标、过滤条件和聚合方法，再查询原始数据/既有分析结果生成图表。此 JSON 不允许自己填一组冒充原始测量的 `values`，不允许 SQL、JavaScript 或任意路径。确有手工数据需要导入时，应走单独的来源登记流程，不混成 ThreeMind 测量。

## 实验报告：跨记录组织与新分析

报告可以引用多个已保存记录的图表/表格/文字，也可以直接选择原始数据生成新图表。引用固定到记录修订号和块 ID，保留来源跳转。报告草稿可以更新引用，但更新应明确显示数据版本变化；已导出的报告和历史修订保持不变。

编辑布局采用左侧内容大纲、中间文档/图表画布、右侧数据或样式属性。记录页更偏向取数和配置，报告页更偏向章节组织。提供目的、方法、结果、讨论、局限等模板，但不强制每份记录写成论文。

图表、表格和统计数值从同一证据快照解析。配对统计仍复用当前分析服务及其独立单位、置信区间、多重校正和缺失语义，不能在报告层自行重新算一套更“好看”的显著性。

## AI 生成

在记录与报告子页右上角提供“AI 生成”。用户选定范围/关注点与供应商后，服务只发送该范围的证据摘要、指标定义、来源、缺失情况和受限 JSON schema。大数据由本地查询/统计服务整理，不能把整个模型或 data 目录塞入提示词。AI 的结果默认是新的未审核草稿，可以反复生成，不覆盖原记录。

AI 只生成章节、图表规格、数据引用和解释，不能改原始节点、连接、观察、事件、统计产物，也不能执行运行命令。数值事实优先通过服务端解析的指标引用填入，而不是让 AI 重写。生成后校验来源、指标/方法、时间范围、图表配置和可核对的数值引用；不可用字段、错误证据引用或擅填的测量数组直接拒绝。

这能保护原始数据并校验结构，不能保证自然语言解释绝无幻觉。解释应标明 AI 生成、保留证据链接和人工审核状态，明确区分测量事实、推断、局限和后续假说。阴性结果、失败样本、删失和缺失不能被生成器自动省略。

保存供应商/模型、生成参数、提示模板版本、发送的证据清单、响应、耗时和用量。响应文本是未经信任的内容，禁止通过其中的指令调用额外工具或扩大访问范围。没有配置供应商时，人工写作与生成图表仍然完整可用。

## 供应商配置

已参考 PoemHaven `poemhaven-admin/src/views/Security.vue` 的供应商模式及 `api.ts` 的字段。ThreeMind 放在“设置 → AI 供应商”，共用于将来恢复的解释器/调试器及新报告生成；各工具仍有独立的供应商选择与启用状态。

字段包括名称、协议类型、Base URL、模型、API Key、启停、连接测试、超时、最大输出 token、并发/请求预算、价格和费用估计，以及可选 HTTP 代理主机/端口/用户名/密码。工作站应支持本地兼容服务与无需密钥的本地模型。托管部署明确区分平台供应商与项目授权，不把个人密钥暴露给其他项目。

列表显示模型/接口、启用状态、密钥是否已配置、最近测试结果/延迟和用量。编辑密钥留空表示保留，清除是独立动作；API 不回传密钥。使用部署密钥保护数据库中的秘密，日志脱敏。引用过的供应商保留历史身份，停用不破坏旧记录。测试请求和生成请求都有超时及取消反馈。自动故障切换不能悄悄改变模型，必须留下实际供应商和失败尝试记录。

本模块接入 AI 服务不改变 ThreeMind 默认物理刺激原则；AI 解释器不成为意识内核，AI 生成的报告也不自动进入意识输入总线。

## 存储和导出

在同一个 PostgreSQL 实例增加笔记本、草稿分类、笔记/草稿、正文修订、实验记录及修订、报告及修订、数据引用和 AI 作业表。复用项目 RLS、后台任务、证据产物及内容哈希。不增加一个“笔记数据库”、不建设独立 MQ，不自动把每次编辑写成项目 Markdown 文件。

正文树与图表规格体量适合有版本的 JSONB；科学测量继续来自现有规范数据表和不可变证据。媒体/导出资源使用已有分块产物机制并登记哈希。引用检查点和图表的记录会成为存储清理的引用约束，不能清理后只留断链报告。

导出 Markdown、DOCX、PDF、HTML：Markdown 需要图片时提供 `.md + assets` 包；HTML 可生成离线自包含文档；DOCX 生成真正的 Office 文档；PDF 固定页码/字体/图表。复用图表数据及渲染规格，优先输出 SVG、必要时 PNG；不截整个网页代替研究图。文档转换器只接受服务生成的受控输入，公式、中文字体、跨页表格、图表编号和引用都需实际渲染验收。

E2b 采用共享内容模型及 python-docx、ReportLab、Matplotlib 直接生成，公式转为 OMML／SVG；不需要在运行节点安装 Pandoc、Word 或 LibreOffice。Windows 的中文、公式和跨页表格已实际渲染验收，其他部署的边界见[导出说明](v2-research-exports.md)。

每份导出含来源清单、协议/数据/分析版本、生成时间与必要的校验信息。重新生成会产生新产物，旧文件保持可核对。默认不公开，平台分享单独管理。

E2e 已提供[固定修订分享](v2-research-sharing.md)：所有者预览后明确发布，正文默认开放、完整证据包单独选择，链接支持到期及永久撤销，匿名页面只访问已发布文件。它与本地工作站共用实现，本地生成链接不会把数据上传到云端。

## 实施前仍需验证的设计点

编辑器双模式对表格、公式和特殊排版的保真程度；报告自由布局的首期范围；超大数据图表的查询预算；部署下的中文字体与 DOCX/PDF 一致性。先用真实记录做一个纵向原型验证这些问题，再确定细节，不要求现在就让用户预先回答所有实现选择。
