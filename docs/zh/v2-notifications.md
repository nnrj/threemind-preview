# 通知与邮件

通知是 Lab 的研究工具，不是模型刺激或内核参数。设置中的“通知与邮件”包含个人通知记录和项目通知规则；页面右上角的铃铛显示当前项目的个人未读数。规则由项目所有者维护，项目成员可以阅读及标记自己的通知，互不影响已读状态。

## 配置与使用

通知总开关、邮件开关默认都关闭。启用通知后，按照所选事件保存通知；只启用站内通知不需要配置邮箱或外部服务。基础图形表单与 JSON 可以双向切换，提供行号、高亮、格式化和校验，保存始终执行服务端校验。高级限制默认折叠。

支持以下来源：

| 事件 | 依据 |
| --- | --- |
| 结构复现 | 截面读出器实际提交的 `recurrence_notice`，遵守该意识的复现次数、跨度和冷却参数 |
| 时长完成、运行失败、活动耗尽、运行需处理 | 已提交的对应运行状态变更；实验停止与模型活动耗尽分开 |
| 导出完成 | 模型、证据或查询工件成功提交后的任务结果；默认不提醒 |
| 分析完成 | 已完成的统计分析任务 |
| 导出或分析失败 | 上述工具任务失败，不把邮件或 AI 调用失败当作意识死亡 |

通知保存事件编号、模拟时间、提交修订、哈希等可用的标量事实，界面可展开并定位来源。结构复现不等于意识或理解能力证明；通知摘要不能替代原始证据。规则关闭期间不补造通知，之后开启也不扫描全部旧历史重发。

规则使用独立版本号；两个页面同时编辑时拒绝覆盖新版本。完全相同的保存不产生新版本，也不取消已排队邮件。修改规则或凭据会使尚未发送的旧版本邮件取消，避免悄悄改投其他收件人。历史通知保留，配置历史不包含秘密。

## 邮件服务

可选择 Resend 或 SMTP。

Resend 使用固定的 HTTPS API，填写 API Key、发件人和收件人。示例发件人只是初始配置，生产使用需遵守服务商的域名和收件范围规则；真实账户是否可发送，应由明确的“发送测试邮件”操作检查。[官方发送接口](https://resend.com/docs/api-reference/emails/send-email)定义请求与服务接收回执。

SMTP 填写主机、端口、加密方式及可选用户名／密码。默认端口 587 和 STARTTLS；也支持直接 TLS。证书使用系统信任链验证。无加密模式仅允许本地工作站的回环地址，便于本地邮件接收器验收。

密码和 API Key 位于独立凭据输入区，不进入 JSON 配置。留空保留已有值，清除有单独开关；服务端不回填秘密。凭据复用 AI 工具的加密设施，数据库与 `THREEMIND_SECRET_KEYS` 应分别安全备份。配置中最多 20 个收件地址，多个地址在邮件收件人列表中可见。

邮件语言支持中文、英文，或使用配置中保存的 `ui_language`。后者在图形界面显示为“使用规则的参考语言”，并提供“后台参考语言”字段和“使用当前界面语言”填入按钮。这个保存值用于没有浏览器在线时的后台发送；个人[界面语言](v2-interface-language.md)切换不会自动改写项目规则，图形／JSON 往返也不会覆盖它。

## 事务、队列与不确定结果

数据库触发器只写入同一 PostgreSQL 的通知和作业表。运行状态／来源事件与通知在同一事务内提交，回滚不会发出假通知。触发器不访问网络、不执行内核计算。邮件由独立 `notification` worker 领取，不占用模拟或 AI 队列的并发名额；不新增 MQ 或数据库。

来源键和测试请求 UUID 用于去重。投递读取实际待处理作业，不依赖“已处理最大事件编号”推断完成，因此后提交的较小编号不会漏发。测试按钮使用已保存的配置，重试同一请求不创建第二封邮件。

发出网络请求前先提交发送标记。若连接中断、回执未知或 worker 在发送后被接管，结果标为“不确定”，不会自动重发。同一封 Resend 请求附带稳定的幂等键，但本系统不依赖服务商无限期保存幂等状态来保证恰好一次。SMTP 部分收件人拒绝有独立状态；已收到 DATA 接收确认后，退出连接失败不会把确认抹掉。

“邮件服务已接收”只表示服务商或 SMTP 服务器确认接收，不表示邮件已抵达最终收件箱。提供者错误仅记录受控原因，不把响应正文、连接串或凭据写入用户可见错误。

发送前重新检查配置版本、保存者仍具有项目所有者权限、账号启用状态及部署允许的端点。已经开始的外部请求无法通过后来的停用撤回。冷却默认 60 秒，滚动 24 小时上限默认 50 次邮件请求；一次请求可以包含多个收件人。限流时保留站内事实，邮件标为跳过，不在冷却结束后回放积压邮件。

## 部署

schema 21 增加四个项目隔离表及来源触发器。升级前停旧 worker，执行迁移，更新 API 和所有 worker 后再启动。它不扫描旧 `data/`，不改变 causal/7、state/5、profile/5 或 419 项科学配置。

工作站启动器自动启动通知 worker。独立服务使用：

```powershell
.\.venv\Scripts\python.exe -m threemind_lab.cli worker --queue notification
```

`THREEMIND_MAX_NOTIFICATION_JOBS` 默认 1，是通知队列的部署并发限制。所有相关服务需要相同的凭据加密钥。服务器模式必须通过部署配置明确允许邮件端点，例如：

```dotenv
THREEMIND_NOTIFICATION_ALLOWED_ENDPOINTS=api.resend.com:443,smtp.example.org:587
THREEMIND_MAX_NOTIFICATION_JOBS=1
```

SMTP IPv6 字面地址使用 `[地址]:端口`。允许名单由部署者维护，不接受客户端自行放宽；工作站可使用自己的本地或远程邮件服务。Compose 已包含独立 `notification-worker`，已有 Compose 环境缺少加密钥时先运行 `python scripts/init-compose.py --ensure-ai-key`。不要输出含秘密的 Compose 完整展开配置。

通知可以在原模型档案合法清理后保留摘要，此时不再显示已删除对象的来源入口；它不代替研究记录对原始恢复点的长期引用保护。当前历史分页有界，未读计数仍是实时数据库计数；尚未声称完成百万通知历史的容量验收。
