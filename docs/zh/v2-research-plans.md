# 受控实验计划、命令与模板

意识详情“人工实验 → 受控实验计划”提供可保存的多步协议。计划固定到一个真实起点，保留命令、边界、哈希、发起者及逐步回执。它和配对研究协议互补：配对研究管理共同培养、独立区组及统计比较；受控计划管理具体刺激顺序和人工探索，不自动把一次轨迹当作因果证据。

## 图形与 JSON

默认是图形编辑，逐步选择命令、填写实际参数，支持添加、复制、移动和删除，十步一页。高级参数默认折叠，规定本次步骤数、刺激数、文本总量及累计模拟时间。右上角切换 JSON，使用相同的行号、高亮、格式化、重复键检测与校验；切回图形和保存都重新校验。未知命令、额外参数、类型错误和预算超出不会被忽略或截断。

保存只冻结协议，不立即执行。计划状态、起点及完整步骤可在详情查看；“以此计划再设计”建立新草案，原计划及哈希保持不变。初始条件来自明确恢复点及其科学协议，背景来源遵守意识配置。

## 模式与执行边界

- 人工逐步：每次明确执行一个已冻结步骤，然后暂停计划。
- 确认后执行：用户明确开始后，按顺序执行剩余步骤，遇到暂停步骤或停止请求时停下。
- 受限自动：只允许在有明确分叉来源的沙箱上执行。仍须开始操作；“自动”不表示 AI 可以自行创建或启动任意任务。

默认边界为 100 步、20 次刺激、20,000 字文本及累计 60 模拟秒，可在高级配置中收紧或调整。当前协议上限分别为 200 步、100 次刺激、200,000 字和 24 模拟小时。它们是工具请求边界，不是暗中截断 Core 的连接、激活或记录。整份计划推进量还必须处于意识已经配置的运行终点之内。

计划开始、继续都检查冻结的科学修订及命令边界；暂停期间有计划外改参、输入或推进时，需要从新状态再设计，而不是悄悄沿用旧起点。执行期间保护目标，拒绝计划外的新人工载体、标量端口和参数修改。显式意识暂停／终止仍可用于打断。背景环境是否保留是明确来源配置，不能把运行中关闭页面视为撤除刺激。

计划“当前步骤结束后暂停”和“取消剩余步骤”在步骤边界生效。立即打断长时间推进可用意识暂停按钮。部分完成的等待保留原目标和已发生的事实，下一次继续会记录新的尝试；不重放已经确认的刺激。

## 命令契约

| 命令 | 实际行为 |
| --- | --- |
| `observe.summary` | 计算已提交状态的实际指标；前后验证 Core 哈希不变 |
| `observe.output` | 保存截至该点的真实截面／时序／器官证据引用 |
| `observe.graph` | 保存固定点的节点和连接查询引用 |
| `history.tail` | 引用此前操作，默认 20 条，可选 1～100 条 |
| `stimulus.send` | 将 1～20,000 字文本通过文本感官及 InputBus 接收；实际递送另有证据 |
| `runtime.wait` | 推进明确微秒数，经普通 Runtime 执行，保留时间戳队列和数值格点 |
| `snapshot.capture` | 为当前已提交恢复点留下命名引用；不伪造一个新时间点 |
| `runtime.pause` | 在当前步骤边界暂停计划，等待用户继续 |
| `experiment.note` | 保存研究注记，不向 Core 注入文字或语义 |
| `runtime.resume` | 用户控制入口继续已暂停计划；不允许在计划内部递归启动任务 |

旧 `runtime.wait` 的 tick 参数已由明确模拟时间替换。命名状态不自动导出模型文件；实际模型和证据仍由用户按需导出。命令不接受 SQL、脚本、路径、任意 HTTP 或凭据配置。

文本接收与递送不同。发送后如果没有推进或帧持续时间超过当前等待量，载体可能仍在队列中；页面提供原始载体和递送证据链接，不把接收成功冒充已经感知。人工设计使用普通人工文本来源；将来 AI 生成的计划以独立 `ai-debug` 来源接入，不能借此绕过来源策略或感官预算。

## 恢复与一致性

一份计划使用一个 worker 作业。等待步骤直接调用现有运行循环，不占着一个 worker 等另一个 worker，因此部署只有一个执行槽时也能完成。

首次接收等待步骤时冻结绝对目标：

$$t_{目标}=t_{首次接受该步}+\Delta t$$

中途停机后，新尝试推进剩余量 $t_{目标}-t_{最新确认}$；目标不随着重试后移。每个步骤及尝试都有稳定请求编号。刺激接收和该步骤回执在同一个事务提交；等待终点和回执与核心检查点一起提交。进程在提交之后、更新计划游标之前消失，重试先复用该步骤回执，然后移动游标，不重复执行。

继续计划的控制请求也有幂等编号。浏览器丢失确认时显示“重试同一计划控制”，已完成计划不会重新发送载体或多推进一段。worker 在每步检查发起者当前项目权限，权限撤销会停止执行；租约过期的旧 worker 不能提交。真正的步骤拒绝与失去租约分别处理，失败不会伪装成待恢复而无限等待。

## 模板与同源比较

提供自由协议、重复刺激、联想／迁移、遗忘／巩固和输入顺序模板。可调整 A／B 文本、重复次数与等待时间，应用模板会替换步骤，并提供一次撤销。

顺序比较应从同一恢复点建立独立沙箱，分别冻结 A→B 与 B→A。模板不是已经验证有效的认知训练；时间安排、输入持续量、背景重叠、独立重复和读出窗都需按研究设计检查。遗忘模板的较长等待只是一种可编辑的测量安排。

创建暂停沙箱时可保留来源配置，或明确暂停新背景载体。选择写入新沙箱的来源策略，原意识和已进入 Core 的在途事件保持其原含义。这保证模型起点可核对，不把人为擦除已发生输入称作环境撤除。

## 存储、权限与导出

schema 17 在同一 PostgreSQL 增加 `research_plans`，逐步回执复用 `research_operations` 并关联计划、步骤及尝试。两者都处于项目行权限下；原始恢复点有外键保护，档案整体清理纳入这些记录。没有新增 MQ、模型文件自动覆写或另一个数据库。

列表分页读取摘要；详情首次读取冻结协议，进度使用独立轻量状态查询，不反复传输整份长协议。回执使用稳定游标，停止状态不持续轮询完整回执。JSONL 导出包含冻结计划、哈希及完整控制／步骤记录，在同一可重复读快照中流式读取，不限于当前页。原始输入、图谱和输出沿其引用查询。

接口位于项目意识的 `research/commands`、`research/templates`、`research/plans/validate`、`research/plans`、`research/plans/{id}/control` 和 `research/plans/{id}/export`。升级停旧 worker，执行 `threemind migrate` 后重启；Core causal/7、state/5、profile/5、419 项科学参数不变。
