# ThreeMind 实验与调试工作台

[中文](experiment-debugger.md) | [English](../en/experiment-debugger.md)

## 目的

实验与调试工作台是供人工研究者与可选 AI 计划器共用的宿主侧研究层。它不是新的认知机制，也不属于联想 Core。它负责让实验协议、命令轨迹、输出和解释可以被检查。

React UI 中的入口为 **实验与调试**，API 协议为 `threemind-experiment/1`。

## 边界

```text
研究者或外部 AI
  -> 仅产生实验计划 JSON
  -> 宿主验证器与显式命令注册表
  -> 普通 InputBus / OutputBus / 存档接口
  -> 联想 Core
```

AI 供应商不拥有任意 HTTP、文件系统、凭据、持久化、网络配置、删除或直接修改图结构的权限。它只能提议已注册的步骤；宿主会校验每个参数、应用本次实验显式给出的范围、记录执行过程，并拒绝注册表外的一切行为。

因此 AI 调试桥是一个 **宿主侧双向适配器**，不是意识内部的感官器官，也不会自动形成自反馈。它提交的载体使用普通的 `ai-debug` 来源策略和文本感官；它的观测来自 OutputBus 投影。

## 实时观测传输

工作台通过独立于 `GET` 查询的 WebSocket 端点
`/api/ws/consciousnesses/{consciousness_id}` 观测其选中的目标（包括未被设为当前活动实例的隔离沙箱）。它复用主观测台的已确认、分块图快照协议。浏览器较慢时，可能在丢弃一个纯可视化 delta 后收到新的完整快照；这一过程不会阻塞 Core tick、改变目标实例或悄悄删去图元素。

## 可见的创建与 AI 规划生命周期

创建隔离实验、请求外部供应商生成计划，都是可能长于普通界面请求的宿主侧操作。因此工作台将它们作为单向 Server-Sent Event（SSE）流暴露：

- `POST /api/experiments/stream` 会依次报告校验、解析目标、克隆沙箱、初始化、历史检查点和最终实验记录；
- `POST /api/experiments/{run_id}/ai-plan/stream` 会报告规划阶段，并在供应商生成过程中把原始文本增量转发到界面。

流式显示的规划文本明确属于**未受信任、尚未执行的草案**。只有完整响应到达后，宿主才会解析它、根据注册命令表与本次运行的显式边界校验每一步，并保存规范化计划。流式传输只用于可见性，不会向供应商授予任何新的命令权限。

创建实验时可以选择一个已保存的供应商。工作台也提供供应商列表刷新入口，因此在设置中保存供应商后无需刷新整个浏览器页面即可选择它。

## 已注册命令

当前注册表刻意保持很小：

- `observe.summary`、`observe.output`、`observe.graph`、`history.tail` 为只读观测；
- `stimulus.send` 通过普通文本感官与 InputBus，以 `ai-debug` 来源提交一个外界载体；
- `runtime.wait` 等待真实运行时 tick，不伪造全图状态转变；
- `snapshot.capture`、`runtime.pause`、`runtime.resume`、`experiment.note` 是范围严格且可审计的操作。

任何实验命令都不能删除模型包、覆盖当前意识、修改凭据、切换持久化、改变适配器拓扑，或调用任意 Core 路由。

## 实验运行与隔离

默认情况下，新实验会从选定意识创建一个命名克隆。克隆是独立运行的实例，并记录其源意识作为谱系信息。它的背景刺激可以明确选择保留或暂停；后者适合控制文本载体实验的变量。

支持三种模式：

- **人工逐步**：研究者加入并逐步执行已校验的命令；
- **需确认**：计划可以生成，但执行完整计划前必须明确确认；
- **受限自动**：仅允许在克隆沙箱中使用；AI 提议的计划通过注册表校验后才会执行，且受可见的步骤数、刺激数、文本长度和等待 tick 限制。

这些默认项是配置，而不是隐藏的 Core 截断。`ai-debug-duplex` 适配器通过普通适配器注册表暴露这些设置。
单次实验只能将这些边界收紧，不能通过工作台或 HTTP 请求扩大它们。
人工命令编辑器用带类型的控件暴露全部已注册命令；它不是可执行任意 JSON 或 Shell 的通道。

## 证据、持久化与报告

实验运行记录使用 ThreeMind 已选择的持久化后端（文件、SQLite、MySQL 或 D1）保存，并维护实验索引。记录包括目标身份、初始观测、已校验的计划、实际执行步骤、参数、结果、耗时、错误、产物和外部分析。

可选的外部 AI 分析只是对已记录证据的解释，不是 Core 输出，也不是意识存在的结论。研究者可添加一个范围明确的分析重点，该指令会与分析条目一同持久化。导出的 Markdown 报告位于 `lab/ai-debug/`，并标注为 **自动生成，未审核**；持久化实验记录才是规范的审计轨迹。

## 初始模板

第一版提供重复性、联想/迁移、遗忘/巩固、输入顺序和自由协议模板。它们只是起点，不代表结论。任何有意义的结果都需要明确对照、独立克隆下的重复、在必要时比较不同编码或来源策略，并记录阴性结果。

## 与 AI 环境刺激器的区别

AI 环境刺激器产生开放式的外界刺激；工作台则用于控制变量和保留完整轨迹。两者可以共用供应商配置和文本感官，但必须保持独立的调度、提示词、来源 ID、记录和权限边界。
