# 6.0：固定函数寻址内核

[English](../en/v2-kernel60.md)

2026-11-12，依据用户本轮授权实现。用户要求先只改变刺激到节点的寻址方式，其余机制保持5.3；6.0应有独立实现，能够在不加载5.3内核代码时运行。此处的地址是网络中的**虚拟节点编号**，不是操作系统的内存地址。

## 刺激如何找到节点

现有刺激接口接受32位无符号整数编码。6.0采用固定函数：

\[
F(c)=c,\qquad c\in\{0,\ldots,2^{32}-1\}.
\]

输入适配器负责把外界信号编码为接口接受的数值；内核计算地址，查找该地址上的节点。节点存在时向它传入刺激；节点不存在时，按原有出生和容量规则创建节点。相同编码始终得到相同地址，不受编码首次到达的先后顺序影响。零幅值输入和已满容量的处理沿用5.3。

内核不再保存`receptors[刺激编码] = 按出生顺序分配的节点编号`。节点容器直接以固定地址为键，保留存活节点及其状态。容器的存储索引属于对象存储，不再承担编码到另一套节点编号的分配。编码范围很大也只按实际创建的节点数量分配存储。

节点行仍保留`channel`字段，便于现有观察和外设读取；6.0要求它严格等于`id`，恢复时拒绝不一致的记录。`birth_count`仅统计累计出生次数，不参与寻址。旧版的`next_node`不属于6.0存档。

节点被删除后，同一编码可在同一地址重新创建节点；支持度、疲劳、衰减年龄和连接等状态按出生规则初始化，不从已删除对象恢复。

## 节点重建后的在途信号

2026-11-12，作者再次明确：两种处理方式都实现，默认采用第二种，即仍按地址送达。创建6.0个体时，通过`inflight_delivery`选择：

| 选项 | 配置值 | 行为 |
| --- | --- | --- |
| 1：丢弃重建前旧信号 | `same-birth` | 接收节点必须在信号发送时已经存在，且此后没有被删除、重建 |
| 2：仍按地址送达（默认） | `address` | 信号到达时，交给该地址上当时存在的节点，包括重建的节点 |

两种方式都不会凭在途信号创建节点；到达时该地址没有节点，信号就不被接收。已经发出的激活、抑制信号不因发送节点被删除而撤回，仍可到达没有被删除的接收节点。唤醒事件针对一条连接：选项1要求它的两个端点都没有被删除、重建；选项2则按现有端点地址和既有唤醒规则处理。

实现只增加节点的出生序号`birth_serial`；选项1还在内部事件中保存发送时的累计出生数`birth_limit`。重建节点的出生序号大于这个上限，因此可直接排除旧信号，无需保存被删除节点的历史或恢复编号分配表。出生序号只用于判断是否重建，地址仍由`F(c)=c`确定。序号、事件上限和配置随完整存档保存；配置在创建个体时选定，运行中不可切换。

## 保持的机制及地址变化的实际影响

6.0与5.3共有参数的默认值保持本轮开始时的设定：逆对数衰减，强化继续累计年龄，保持尺度增长与回落默认关闭。指数、幂律和先幂律后指数仍可选。激活、抑制、疲劳、不应期、连接形成、强化、短时增强、突触资源、能量记账、结构检查、休眠及唤醒规则均从该基线保留。

资格迹仍参与连接稳定度更新；节点稳定度仍影响局部可塑性，相关状态也供观察与存档使用。本轮保留这些字段，未因它们不直接决定当前权重衰减而删除。

地址身份改变有明确后果。空间位置和能量区仍由原来的编号函数计算；同刻处理仍沿用编号排序。编号由出生序号变为刺激编码后，同一输入课程在两个版本中可能得到不同的具体位置、能量区和同刻处理顺序。固定函数寻址保证同一编码的地址稳定，并不保证任意旧课程在6.0中逐值复现。工程对照专门使用两版节点编号一致的材料，核验其余规则。

## 独立实现与版本边界

- Python：`src/threemind_kernels/local60.py`、`local60_config.py`、`decay60.py`，拥有本版本的状态转换、参数校验和衰减计算；不继承或导入5.3内核。
- Rust：`crates/threemind-core/src/local60.rs`、`local60_transitions.rs`、`local60-defaults.json`，独立执行相同规则，并提供原生绑定和独立运行时。
- 共用组件限于已有协议类型、时间戳、对象容器、基础数值机制和能量记账等基础设施。观察、保存、宿主等待不会推进内部时间。
- 版本身份为`threemind.continuous-memory/6.0`，存档格式为`threemind.continuous-memory-state/6.0`。5.3存档不能直接改名作为6.0恢复，反向亦然。
- API、命令行和工作台可明确选择6.0。全局新建默认仍为5.3，历史个体继续按自己的版本和保存配置恢复。

2026-11-12初版尚未定义衰减年龄的代际结构继承规则，当时调用该继承操作明确拒绝；完整状态保存、恢复与研究副本不受限制。2026-11-13依据作者批准的全面复验计划v2补齐规则，见下节。

## 2026-11-13：6.0的繁殖规则

新规则编号为`threemind.birth/2`。后代继承父体在保存时刻的节点和连接持久状态，包括权重、支持度、稳定度、局部可塑性、使用次数、保持尺度、能量区、休眠状态及累计衰减年龄。默认保留衰减年龄；另设`reset`对照，把继承结构的衰减年龄归零，其他持久状态保持相同。

后代的内部时钟从零开始，激活、抑制、疲劳、近期痕迹、短时增强、突触资源使用状态和待执行事件重新初始化。父体的干预屏蔽不传给后代。虚拟地址保持原值，出生序号重新分配；新个体能量按出生配置初始化，身体的繁殖支出继续由生态账本记录。普通暂停恢复及完整研究副本仍使用完整存档，不调用出生操作。

Python接口为`birth(image)`或`birth(image, decay_age="reset")`。6.0生态协议使用`inheritance_rule="threemind.birth/2"`，`inheritance_decay_age`可选`preserve`（默认）或`reset`。运行API在`inherit=true`时接受同名选项。协议、出生事件和分支记录保存所用规则；历史`birth/1`仍按原行为执行。

Python和Rust的6.0恢复校验允许继承衰减年龄大于后代自身寿命，因为年龄来自父体，后代时钟仍为零。年龄仍必须有限且非负。此改动支持已授权的代际初始状态，没有改变衰减公式、寻址、传导或默认参数。5.2、5.3未定义的代际规则仍明确拒绝。
