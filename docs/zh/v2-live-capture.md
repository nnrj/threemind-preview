# 连续设备采集：麦克风、摄像头与音画会话

连续采集属于感官适配器，不改变 ThreeMind 的核心动力学。浏览器采集物理设备信号，转换器产生匿名刺激，InputBus 按时间递送。原始采集块、转换参数、冻结刺激、递送结果与恢复状态都保存在同一 PostgreSQL 数据库中；不会不断覆写模型文件。

## 使用入口与默认值

在意识详情的「感官与输入 → 连续设备」中选择麦克风、摄像头或音画联合采集。先暂停意识，在「配置连续感官」中开启听觉／视觉感官及相应连续设备开关，再继续实时运行。点击开始后才申请浏览器设备权限；可刷新并选择输入设备。加速训练、暂停状态和冻结实验不接收现场设备采集。

同一意识同时拥有一个会话，联合会话同时处理声音和画面。停止会释放设备，保留已确认的采集块与在途刺激。离开页面会尝试停止；浏览器被强制关闭或网络断开时，worker 的下一次检查点提交会将 30 秒没有新块的会话标记为中断。新建会话也会释放超时占用。页面可手动结束遗留会话；这不删除证据。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `microphone_enabled` | false | 允许此意识绑定浏览器麦克风 |
| `camera_enabled` | false | 允许此意识绑定浏览器摄像头 |
| `audio_packet_us` | 200,000 µs | 按实际采样数量划分传输块，停止时发送真实短尾段 |
| `delivery_buffer_us` | 1,000,000 µs | 首次绑定源时钟时预留的递送缓冲 |
| `max_packet_bytes` | 1 MiB | 单个二进制包的上限 |
| `max_pending_packets` | 16 | 浏览器待确认队列上限，包含正在发送的包 |
| `max_session_bytes` | 256 MiB | 会话累计原始字节上限 |
| `max_session_s` | 3,600 s | 会话物理时长和声明的采集时长上限 |

这些配置与其他意识参数共享图形／JSON 编辑、保存校验、暂停编辑和项目默认值机制。听觉窗长、采样率、频带、适应与视觉分辨率、patch、阈值、采样间隔继续由[媒体感官配置](v2-media.md)控制。连续会话使用自己的字节／时长预算，不套用文件的最大解码时长。

## 时钟、缓冲和因果边界

源会话使用相对微秒时间 $t_c$。worker 第一次处理该会话的采集块时，建立固定模拟时间原点：

$$t_0=\max(0,\ t_{\mathrm{core}}+b-t_{c,\mathrm{first}}),\qquad t_{\mathrm{delivery},i}=t_0+t_{c,i}.$$

其中 $b$ 为配置的缓冲，$t_{c,i}$ 是转换后帧的采集时刻，包括听觉窗口结束和视觉 patch 扫描偏移。后续包沿用同一个 $t_0$；声音与画面不会分别按 HTTP 到达时刻重新对齐。模拟原点与队列在检查点事务中提交。

浏览器的时钟精度有明确边界：

- 音频由 AudioWorklet 的实际输入数组采集；按源帧计数和实际采样率计算连续时间，不假设回调永远是 128 帧。它是 Web Audio 渲染帧时钟，近似映射到浏览器时间；ADC 采集延迟未知。
- 画面使用 `requestVideoFrameCallback`，优先使用可用的 `captureTime`，否则记录 `presentationTime`。这通常是呈现时间，不能伪称硬件曝光时间。每包记录来源、画面编号和此前跳过的画面数。
- 两种输入共用浏览器会话时间线，便于分析相对时序，但不宣称经过校准的硬件音画同步。客户端声明的时钟信息不是真实性认证。
- 音频的时间和源帧编号必须连续。缺失采样不得补零或仅改写时间戳。画面采用显式采样间隔，浏览器未提供或被采样策略跳过的帧不被伪造。

首包绑定并不保证任意主机都能跟上实时输入。如果一个已接收包的刺激已经落后于内核时间，worker 拒绝整个包并中断会话，保存拒绝原因和原始证据；不会把过去的刺激强行挪到当前时间。可以提高缓冲或降低显式感官采样量，也可以解决计算／数据库瓶颈。性能档位不会暗中改变科学参数。

暂停、正常完成、显式结束和 worker 失败都会结束现场会话。恢复模型后应重新开启物理采集；已排入内核的刺激及其原时间保持不变。此前已接收但尚未处理的包仍受原会话边界和因果校验约束。

## 原件与事务

声音原件是浏览器提供的单声道 Float32 PCM。浮点信号可能略超出 ±1：原件完整保留有限幅度，感官端按与文件音频一致的归一化范围饱和处理，记录原件峰值与饱和样本数；非有限值会拒绝。画面原件是浏览器按视网膜目标尺寸缩放并转换的灰度像素；它不是摄像头全分辨率原始传感器数据。数据库保存具体处理方式、尺寸和设备返回的设置。停止音频时，即使正好落在整包边界，也会发送 final 块；没有确认完整尾段的正常停止将被标记为 `incomplete_audio_tail`。

音频优先使用浏览器支持的 `sinkId: {type: "none"}` 纯处理模式，不连接实际扬声器；其他浏览器使用静音输出兼容路径。`latencyHint: "playback"` 请求较宽松的输出调度，实际 `baseLatency` 被记录，它不是麦克风采集延迟。此选型用于减少输出设备调度对采集的干扰，不能保证所有浏览器／设备都没有采样中断。[AudioContext 参数说明](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/AudioContext)

每个包都有严格递增的会话序号和 SHA-256。原始二进制块、感官编码状态、输入信封、冻结刺激和接收凭据在同一事务中写入。相同序号与相同字节的重试返回原凭据；相同序号的不同内容被拒绝。因此网络超时不会导致重复递送。

**接收确认与递送完成是两个状态。** 前者说明字节与输入命令已入库；后者在 worker 检查点提交后才能确认。页面分别展示原件字节、已确认／待确认数、采集时刻、模拟原点、编码帧数、递送帧数和拒绝原因。未确认的浏览器队列不声称已经保存在数据库；队列超限会中断采集。

输入原件可逐包下载，也可从媒体原件 ZIP 导出。会话包查询保留 SHA、时钟、序号和关联信封；完整输入审计与检查点证据导出保留原始载体引用、冻结刺激和递送结果。媒体原件 ZIP 是导出时的数据库快照；某个检查点的因果证据以该检查点提交版本为界，两者范围不同。

## 二进制协议与 API

传输版本 `threemind.live-media/2`，所有数值采用小端。头部固定 27 字节；采集微秒值与源编号限制在 JavaScript 安全整数范围内。

| 字节偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | 4 bytes | `TMV2` |
| 4 | uint8 | 1 音频，2 画面 |
| 5 | uint8 | 0 普通，1 音频 final；画面不支持 final |
| 6 | uint32 | 会话全局序号，音画交错使用同一序列 |
| 10 | uint64 | 相对采集微秒 |
| 18 | uint64 | 音频源帧编号或画面编号 |
| 26 | uint8 | 0 源自声明，1 音频渲染帧，2 视频 capture，3 视频 presentation |
| 27（音频） | uint32 + uint16 | 采样率 Hz、声道数，之后从 33 开始为交错 Float32 PCM |
| 27（画面） | uint16 + uint16 + uint8 + uint32 | 宽、高、组件数、此前跳帧数，之后从 36 开始为像素字节 |

以 `/api/v2/projects/{project}/runs/{run}/capture` 为根：`GET` 分页查会话；`POST` 建立会话；`/{session}/packets` 的 `POST` 接收二进制块、`GET` 分页查询凭据；`/{session}/stop` 结束。所有调用继承平台项目权限。单请求有字节上限、10 秒接收超时和共享媒体处理并发限制；原始字节不经过 Base64 JSON。当前设备入口使用有界、幂等 HTTP 传输；远程设备独立令牌、匿名帧 WebSocket 和远端输出仍在 B 阶段恢复清单中，不能拿浏览器登录会话充当共享设备密钥。

## 实现与验证

2026-09-09 已修复连续采集逐包强制检查点及数据库锁竞争，聊天区增加实时确认／积压状态。原因、事务保证与验收范围见[修复记录](plans/capture-backlog.md)。

纯 Runtime 编码在 `threemind_runtime.live_media`，可在无数据库程序中直接消费二进制包并保存感官状态；Lab 的 `live_capture` 负责授权、事务和管理，`input_cycle` 负责模拟时间绑定。浏览器 `capture-worklet.js` 只采样，`captureClient.ts` 维护有界队列与设备生命周期。

验证使用合成 PCM、像素及浏览器虚拟音画设备，不采集用户实际麦克风或摄像头。覆盖分包恢复、真实短尾段、重采样边界、时钟／帧编号缺口、非法幅度、事务中途失败、重试去重、暂停后的在途刺激恢复、原件导出、项目隔离、遗留会话超时和 worker 失败。最新通过情况见[验证记录](v2-validation.md)。

浏览器行为依据：[AudioWorklet process](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletProcessor/process)、[currentFrame](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletGlobalScope/currentFrame)、[requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)。这些接口没有提供通用的 ADC／曝光延迟校准保证。
