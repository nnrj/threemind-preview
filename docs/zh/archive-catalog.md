# 归档目录与非阻塞持久化

[中文](archive-catalog.md) | [English](../en/archive-catalog.md)

## 为什么需要归档目录

ThreeMind 将模型包（`.tmind`）保留为可移植、完整的实验工件。它包含某一时刻重新打开或审计所需的 manifest、运行时状态、日志、快照与遗照；数据库行不能替代模型包。

但管理界面不应为了显示名称、tick、快照数量或谱系，就反序列化每一份历史图。那会使列出档案的成本随所有历史实验总大小增长，并可能挤占刺激与控制请求。

因此，Core 维护 `data/archive-index.sqlite3` 作为本地、可重建的归档目录。它只保存小型元数据：工件路径、意识 ID 与名称、模型/内核声明、来源、时间、tick、节点/连接数、生命周期状态及父意识 ID。

## 数据边界

```text
联想运行时
  -> 不可变模型包捕获
  -> 后台归档写入器
  -> 可移植 .tmind 工件
  -> SQLite 归档元数据索引

管理 / 模型包 / 快照 API
  -> SQLite 元数据查询
  -> 小型目录响应
```

归档写入器在运行时 tick 之外完成 ZIP 压缩、文件写入和 SQLite 更新。因此自动快照不会让 Core 等待归档 I/O。手动快照只在 HTTP/CLI 调用边界等待写入结果；开始压缩前，联想运行时已经释放自己的锁。

## 新包与旧包

新写入的 `.tmind` 会包含紧凑的 `metadata.json` ZIP 成员。目录可直接索引它，而无需读取完整图状态。

较早创建、没有该头部的模型包同样受支持。Core 启动后会由低优先级后台任务逐个建立索引，并在文件之间主动让出执行时间。一次性迁移期间，历史意识和快照会逐渐出现在 UI 中；实时图、刺激和控制 API 始终只查询目录，而不会扫描模型包文件。

## 操作说明

- `GET /api/archive-index` 返回本地目录、迁移任务和写入器状态。
- 在 ThreeMind 外部向 `data/` 复制模型包后，可通过 `POST /api/archive-index/reindex?force=true` 重新安排后台目录扫描。
- 删除 `archive-index.sqlite3` 及其 `-wal` / `-shm` 伴随文件，不会删除意识数据；下一次启动 Core 会根据 `.tmind` 文件重建目录。
- 长期研究记录应备份或导出 `.tmind` 文件。SQLite 目录是可丢弃的运行元数据，而不是实验的唯一副本。

此前的 file / SQLite / MySQL / D1 通用持久化适配器仍是独立的应用层扩展点。它不替代本地归档目录，也不改变联想动力学。未来若需要远端目录后端，应以显式同步器或镜像实现，并拥有独立的失败与迁移语义；不应让 Core 的实时运行依赖网络数据库可用性。
