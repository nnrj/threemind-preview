# 大媒体分块上传、续传与原件证据

媒体文件是外部载体，不是模型本体。浏览器默认把文件切成 1 MiB 的分块，逐块确认并保存到当前项目的 PostgreSQL。服务器按需读取分块解码；不会把完整原件拼成内存字节数组，也不写本地临时模型文件。独立 Runtime 仍可脱离数据库运行模型，Lab 的媒体上传服务不成为 Core 的依赖。

## 使用流程

在“感官与输入 → 媒体输入”选择文件，展开递送选项可调整强度、模拟起点延迟并查看接收预算。点击“接收媒体并排队”后依次进行分块传输、完整原件校验、解码与感官转换、输入预算校验和事务提交。页面区分这些阶段；只有最后提交成功才会建立输入账本。

网络中断、停止本页传输或离页后，已经确认的分块继续保留。下方“媒体传输与暂存”列出未完成项，点击“继续／重试”，重新选择原文件后继续。浏览器会校验每个已存分块的 SHA-256，只发送缺少的分块。文件名和大小相同不代表内容相同；任意已有分块不一致会拒绝续传，不把两份文件拼接成原件。

“停止本页传输／等待”停止当前浏览器请求，服务器已经开始的解码可继续；“取消暂存”则明确请求取消。正在解码时通过读取和转换边界协作取消，不强杀线程。分块清理完成后标记为已取消。已经接收的载体不能用这个入口删除：原件、转换帧和研究证据仍能查询与导出。

处理失败的原件保留至暂存期限，可以调整适当的感官／输入预算后重试解码，无需重新上传。服务进程重启会释放该上传的数据库解码锁；重试可接续使用原件，重新解码，避免依赖丢失的进程内状态。这里没有新增 MQ，也不宣称解码中间状态已经支持跨进程精确恢复。

## 长度、哈希与接收边界

设原件长度为 $L$，块大小 $C=2^{20}$ 字节，块数和第 $i$ 块的有效长度为：

$$N=\lceil L/C\rceil,\qquad \ell_i=\min(C,L-iC),\quad 0\le i<N.$$

服务器要求顺序连续、长度恰好为 $\ell_i$，并核对 $h_i=\operatorname{SHA256}(b_i)$。相同块重试返回已有确认；序号跳跃、内容冲突和超长请求均拒绝。传输完整后再以流式方式核对整份原件 $H=\operatorname{SHA256}(b_0\Vert\cdots\Vert b_{N-1})$，随后解码同一组不可修改的分块。

原始媒体时间和感官算法沿用[媒体感官说明](v2-media.md)：音频按真实样本时长分窗、尾段不补零；视频按实际 PTS 采样，画面与音轨不混成同一路刺激。分块边界不重置感官基线，不改变输入顺序或相对时间。每个独立原件仍独立建立感官基线。

提交时再次检查操作者是否仍有项目写权限、意识是否可接收、来源是否已关闭、感官配置是否改变，以及当前队列是否容得下完整载体。原件加入媒体资产、冻结转换帧、输入记录和命令、清理暂存分块、保存上传回执处于同一数据库事务。任一步失败都不会留下半条刺激或重复递送。

## 容量与性能边界

| 预算 | 默认或范围 | 所属位置 |
| --- | --- | --- |
| 音频／视觉原件上限 | 默认分别 32／128 MiB，可设 1～8192 MiB | 意识参数；图形与 JSON 同步 |
| 未完成上传数量 | 每项目默认 4 个 | `THREEMIND_MAX_MEDIA_UPLOADS` |
| 暂存预约总量 | 每项目默认 16384 MiB，按声明原件长度预约 | `THREEMIND_MAX_STAGED_MEDIA_MB` |
| 接口解码并发 | 每个 API 进程默认 2 个，文件与连续媒体共用 | `THREEMIND_MAX_MEDIA_DECODERS` |
| 分块请求 | 最多 1 MiB；接收超时 60 秒 | 上传传输协议 |
| 暂存有效期 | 创建后 24 小时 | 数据库暂存管理 |
| 解码器单次读取 | 最多 8 MiB；常驻一块数据库读取缓存 | 大媒体读取器 |

暂存预约不因传输间断而自动增加；取消、完成或清理过期项后释放。进入上传列表或创建新上传时，清理当前项目已过期且没有活跃解码锁的暂存分块。过期上传元数据和已接收研究证据不在该清理路径删除。平台的跨项目总存储配额仍属于部署管理工作。

整文件兼容接口保留 256 MiB 硬上限，大文件必须使用分块路径。图像单帧像素、解码时长和视频总帧数预算保持现有规则；转换结果也受输入总线预算限制。不能把允许 8 GiB 原件理解为允许无限时长、分辨率或感官帧数。

读取器不会随原件长度保留全部原始字节，但解码库仍有自身缓冲，感官转换帧也需在输入预算内暂存至原子提交。页面分页或分块传输不能证明所有解码任务均为常量内存。解码器请求超过单次读取预算时会明确失败，不悄悄截断。只读进度以阶段、原件字节和已形成感官帧展示；视频 seek 位置不冒充可信的百分比。

## API、版本与导出

所有接口在 `/api/v2/projects/{project}/runs/{run}/media-uploads` 下，并继承认证和项目权限：

- `POST /`：声明 `request_id`、`kind`、`filename`、`byte_length`、`intensity`、`delay_us`，返回可重试会话。
- `GET /`：未完成／全部列表和游标；`GET /{id}`：当前阶段、进度、期限和回执。
- `GET /{id}/chunks`：分页读取块序号、长度与哈希，不返回原始块内容。
- `PUT /{id}/chunks/{index}?sha256=...`：有界二进制请求体，顺序写入或返回重复确认。
- `POST /{id}/finalize`：持有该上传的跨进程解码锁，校验、转换并原子接收；断开客户端不会提前释放解码槽位。
- `DELETE /{id}`：取消未接收的暂存；处理中的请求协作取消。

模型参数总数仍为 379，核心 60 项，state/5、causal/6、profile/4 不变。Rust 当前模型契约同步扩大原件上限；不改 Core 的时间、连接或塑性规则。schema 12 仅在同一数据库增加两个受项目行级权限保护的暂存表，不扫描或迁移旧 data。

已接收原件仍通过原有下载与 ZIP 清单导出，SHA-256 可独立核对；实际帧与递送状态仍在输入记录中筛选、分页和完整导出。上传进度不是递送证据。
