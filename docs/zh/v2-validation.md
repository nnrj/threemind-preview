## 性能验证

`python scripts/benchmark-v2.py` 构造标明为合成测试的固定拓扑，比较参考/原生推进、低开销记录、捕获、序列化、数据库提交和查询，并运行 60 秒固定规模内存检查。合成图不会存入工作站，也不用于认知推断。

本机实测配置为 Ryzen 7 **4800H**、**23.37 GiB** 可见物理内存、NVIDIA **GTX 1650**，与最初估计的 1050 Ti 不同。以下是固定出度 10、可塑性关闭、10 ms 模拟时间推进的中位数；每种推进测 5 次，捕获与编码测 3 次。CPU 有其他桌面进程，数字是工程诊断，不是标准实验室评分。

| 节点 / 边 | Python 参考推进 | Rust 推进 | 状态捕获 | 标准模型编码 |
| --- | ---: | ---: | ---: | ---: |
| 1,000 / 10,000 | 35.96 ms | 6.62 ms | 8.51 ms | 103.28 ms |
| 5,000 / 50,000 | 188.27 ms | 36.44 ms | 40.53 ms | 496.10 ms |
| 10,000 / 100,000 | 387.63 ms | 72.45 ms | 78.19 ms | 1,079.38 ms |

在此合成负载下，Rust 推进约快 5.2～5.4 倍。10,000 / 100,000 的完整 PostgreSQL 提交中位数为 **2.66 s**（3 次，最大 4.59 s，包含首次建立投影），200 条连接查询中位数 **3.31 ms**。三次完整检查点后专用测试数据库约 44.24 MiB，测试期间集群 WAL 增量约 73.14 MiB。WAL 是集群计量，若其他测试并发运行，会包含它们的写入。

编码优化采用规范字节流哈希、不可变状态的哈希缓存、复用已解码状态；数据库跳过无变化行的实际更新。60 秒固定规模检查为 **1,000 节点 / 10,000 边**，整个基准进程 RSS 约 140.11～140.24 MiB，事件队列稳定后为 1,002 条。RSS 包含 Python、Arrow 等已加载库和基准对象，不能解释为 Core 单独内存，更不能推断长期拓扑增长时的容量。

初始前端入口约 320 kB（gzip 102 kB），网络、图表和 Markdown/流程图按使用加载。网络投影使用批量点线、可复用缓冲区和一次只保留最新数据；完成的运行停止轮询，不累计图形历史。大依赖仍有超过 500 kB 的按需分块，构建会明确提示。

**60 秒检查不等价于 24 小时稳定性验收。** 10,000 节点 / 100,000 边、30 FPS 和交互 p95 小于 100 ms 仍需在明确标准机、真实浏览器和并发负载下验收，不能从一次编译成功或内核微基准推断。

上述表格是最初完整检查点实现的基线。新增的增量与后台写入仍保留全状态捕获、哈希和密集投影成本；其收益见下一节。调低显示档位不会偷偷更改科学参数，选高档位也不会被设备评分阻止。

## 增量写入与物理读取复测

完整记录见[检查点流水线基准](../benchmarks/2026-09-05-checkpoint-pipeline.json)。同机、10,000 节点／100,000 边，读取测 5 次，提交测 3 次。提交对比预先生成相同状态并预计算哈希，不含捕获，因此不能直接与上一张表的端到端提交数值相比。

| 路径 | 完整路径中位数 | 优化路径中位数 | 解释 |
| --- | ---: | ---: | --- |
| 执行器读取 | 618.81 ms | 1.36 ms | 仅取身份与激活，避免全部边和历史字段序列化；不是整个模拟器的提速倍数 |
| 稀疏变化提交 | 1,728.15 ms | 923.04 ms | 每次改变 10 个节点和 50 条边，约减少 47% |
| 密集变化提交 | 3,899.63 ms | 4,163.85 ms | 两者均保存完整状态，本次顺序采样优化路径略慢，不宣称有稳定提速 |

稀疏恢复块由每次 667,988 字节减至约 1,050 字节；三次提交期间的集群 WAL 增量从约 20.84 MB 降至 0.156 MB。密集负载没有同等体积收益。WAL 包括数据库自身后台写入，顺序微基准受缓存、检查点和桌面负载影响；三次采样不是严格的性能置信区间。

后台写入压力测试为固定 **1,000 节点／10,000 边**、关闭可塑性、300.22 秒宿主时间，提交 **238 个恢复点**，进程 RSS 在约 **186.7–202.5 MiB** 范围内，末状态从数据库恢复后哈希相同。RSS 包含 Python、Arrow、工作集与线程；不能据此承诺持续生长的大模型内存恒定。5 分钟不等价于 24 小时验收，也不代表高密度持续学习已经达到实时速度。

## 发布门槛

面向公众开放托管计算之前，仍需长时间负载、磁盘增长/备份恢复、资源配额与滥用测试、Linux/ARM64 验证以及部署者的 HTTPS 和备份配置。当前 worker 是受信任的私网计算进程，不接收用户任意代码；没有宣称支持不可信第三方机器或匿名免费算力。

小规模备份还原已经验证；生产数据量、备份保留策略、故障恢复时间及备份介质仍需部署验收。差量检查点与后台持久化已经实现，密集学习的完整捕获与行写入仍昂贵，后续需要原生状态增量、长期生长负载和更大模型的恢复预算验证。

研究上的泛化、长期记忆、与简单基线的优势、主观意识或 AGI 都未由这次工程重构得到证明。这些结论需要在工作台上进一步设计并实施可证伪实验。
