# 能量记账、外部供给与缺能损伤

当前版本（2026-09-09）：新建意识使用 causal/9、state/6。已按用户确认撤去独立能量强制判死，保留缺能结构损伤；详见[统一活动死亡](plans/energy-lifecycle.md)。旧版本只读导出，不自动转换续跑。

能量组提供 10 项核心参数，并接入资源端口、有限外部储库、共同培养／实验分支、参数界面和证据导出。能量是可选的实验资源约束，没有物理标定，不代表焦耳。它不生成感官刺激、语义节点或连接，也不由 CPU 占用率凭空换算出补给。默认关闭，不能作为已实现意识或生物代谢的证据。

Python 参考实现与 Rust 原生内核共享下述契约。旧 causal/1–8 保留原始数据和动力学标识，只读导出，不使用新规则续跑。

## 配置入口与默认值

新建、暂停后的参数编辑和项目默认参数均提供图形／JSON 双模式。高级分类分别是“能量与缺能损伤”和“外部能量供给适配器”。保存必校验；`energy_initial_reserve` 在创建后只读，JSON 修改同样被拒绝。

| 核心参数 | 默认值 | 定义 |
| --- | --- | --- |
| `energy_simulation_enabled` | false | 直接响应、联想传播及抑制转移的资源约束 |
| `energy_initial_reserve` | 1 | 出生时的初始实验资源；超过容量部分记为舍弃 |
| `energy_capacity` | 1 | 当前可保存的储备，严格大于 0 |
| `energy_direct_cost` | 0.035 | 每单位可负担直接到达成本（抑制／饱和之前） |
| `energy_associative_cost` | 0.020 | 每单位实际发出兴奋传播成本 |
| `energy_inhibition_cost` | 0.010 | 每单位实际抑制转移成本 |
| `energy_starvation_damage_enabled` | false | 与能量开关同时开启，才启用维护及缺能结构侵蚀；不直接判死 |
| `energy_maintenance_cost_per_node` | 0.0002 | 每节点、每模拟秒的维护成本 |
| `energy_maintenance_cost_per_edge` | 0.00004 | 每连接、每模拟秒的维护成本 |
| `energy_starvation_structural_decay` | 0.06 s⁻¹ | 未付维护导致的结构消退速率 |

资源数量及成本为 0～10¹² 的有限浮点数；独立饥饿死亡时长已经删除。这是数值支持范围，不能解读为已通过任意极端组合的稳定性研究。显示性能档位不会改动这些科学参数。

## 响应、传播和守恒账本

causal/9 直接到达先按抑制及饱和之前的请求记账；传播按源节点实际发射记账，不读取目标状态。设可用储备为 $E$，请求量为 $q$，单位成本为 $c$。当 $c>0$ 时：

$$q_{\mathrm{paid}}=\min(q,E/c),\quad C=\min(E,cq_{\mathrm{paid}}),\quad E'=\max(0,E-C)$$

未满足需求累计增加 $\max(0,cq-C)$。成本为零时请求量不受储备限制，也不扣费。直接到达按抑制和饱和之前可负担的量收费；联想在发出时收费，抵达不再收第二次；抑制只转移已付费的量，余量留在源节点。容量／预算先拒绝的操作不扣费。生边、学习和自然遗忘沿用其他已声明规则，能量组不暗增“生成概念”的操作。

显式供给提出数量 $S$，模型只接受容量允许的部分：

$$S_{\mathrm{accepted}}=\min(S,\max(0,E_{\max}-E)),\quad E'=E+S_{\mathrm{accepted}}$$

关闭能量时，之前已排队的供给仍按时递送，但接受量为零，状态记为 `disabled`。未接受的外部资源不计入模型储备，也不计入模型“容量舍弃”；舍弃仅描述已经分配的初始／已有储备因容量不足而被去掉的部分。

在浮点舍入误差内，账本满足：

$$E=I+S_{\mathrm{total}}-C_{\mathrm{direct}}-C_{\mathrm{associative}}-C_{\mathrm{inhibition}}-C_{\mathrm{maintenance}}-D$$

其中 $I$ 是初始化分配，$D$ 是容量舍弃。账本另存提出供给量、未满足需求、结算边界及饥饿时间。它是数值资源模型的审计式，不证明物理能量守恒。

## 维护、缺能损伤与活动死亡

在相邻的实际因果／数值边界之间，按节点及连接真正存在的时长积分。设区间时长为 $\Delta t$ 秒，原有节点、连接数为 $N,M$：

$$C_{\mathrm{required}}=\Delta t(Nc_N+Mc_M),\quad d=\begin{cases}1-C_{\mathrm{paid}}/C_{\mathrm{required}},&C_{\mathrm{required}}>0\\0,&C_{\mathrm{required}}=0\end{cases}$$

在右侧边界、递送新事件之前扣维护费。此边界新生的节点不会被追收此前尚不存在时的费用。未付比例 $d$ 使节点支持度、连接权重和稳定度额外乘以：

$$\exp(-\lambda d\Delta t)$$

该损伤来自明确启用的缺能损伤对照，独立于学习可塑性开关；达到原有修剪条件的结构可被移除。只开启能量记账时，没有维护收费或缺能侵蚀。任何配置下都没有独立饥饿判死。

若有结构且储备为零，只记录当前因果结算边界为零储备起点，不启动独立判死倒计时。现有激活继续按自身规则变化。首次激活之后，全部节点连续无激活满 `quiescence_death_us` 才死亡；同刻先递送事件再判定。纯供能不能重置活动计时，已付费在途兴奋仍可激活节点。死亡保留结构和剩余事件作为证据，不清空模型，不接受原意识自动复活；显式继承仍产生新的出生实例及新账本。

维护是边界结算的数值机制。储备在一个区间内的物理耗尽时刻没有被连续求根，饥饿起点不能宣称为精确生理时刻。改变数值步长可能影响结果，应作为单独的时间分辨率收敛实验。读取指标、任意观察分段和按原配置恢复不会增加结算边界。修改科学参数则显式按旧参数结算到修改时刻，再应用新值。

## 外部储库与资源端口

| 适配器参数 | 默认 | 行为 |
| --- | --- | --- |
| `energy_supply.enabled` | false | 显式启用模拟外部资源源 |
| `rate_per_s` | 0.04 | 每模拟秒提出的数量，与宿主执行速度分离 |
| `interval_us` | 100000 | 供给事件间隔，1000～10000000 微秒 |
| `total_supply_limit` | null | 外部储库总接受额度；null 不限，0 禁止 |

每次计划数量为速率乘间隔秒数，再受剩余总额度限制。总额度只计模型实际接受量；满容量拒绝的数量仍保留原始提出记录。第一次供给发生在启动后一个间隔，不在出生时偷偷加一笔。

适配器最多提前排队一个承诺事件。检查点同时保存额度、序号、下次时刻以及与内核队列对应的事件身份；暂停恢复保留相位。关闭／调参不撤销已排队的承诺，接受量与已用额度不重置。关闭所有输入来源会停止新的自动供给及人工请求，已排队事件仍依因果顺序递送。阶段仅关闭感官门 `input_enabled` 不等于资源断供；`close_sources` 才同时关闭后续外部资源源。

人工入口位于“意识详情 → 动力学 → 能量与供给”。请求携带 UUID，同一 UUID、同一载荷的重试返回原命令；变更载荷会冲突。worker 在处理命令后的至少一个核心正传播延迟递送，可请求更长延迟。原始请求、实际排队时刻和实际接受量分别记录，不能把接收成功当作已供给成功。冻结实验拒绝人工插入供给；在实验臂的 `energy_supply` 中明确声明适配器差异。

共同培养使用相同的外部储库机制。各实验分支继承共同培养后的资源账本、在途承诺和已使用的外部额度；改变供给条件不会补回培养消耗。若共同培养中死亡，保存终点证据并报告任务失败，不继续生成活的实验分支。

核心 SDK 提供 `engine.supply_energy(amount, time_us=..., source=...)`，不依赖数据库。Python 外部适配器 `EnergySupplier` 可自行捕获宿主状态；Rust／Python 独立 CLI 都可使用 `--energy-input` 读取用户显式指定的 JSONL 时序供给：

```json
{"time_us":"100000","amount":0.01,"source":"robot-resource-port"}
```

模型文件保存核心账本与已排队事件。`profile/4` 不安装外部自动供给器；用户将模型部署到机器人后，应由机器资源端口实际提供供给或显式连接模拟储库。Lab 的供给适配器配置／状态随数据库运行协议与检查点保存。独立 Runtime 的运行模型仍驻内存并可塑，SQLite 仅作为可选检查点存储，导出由用户触发。

## 查询、图表、统计与导出

能量页面展示最新已提交检查点的储备／消耗／接受量／未满足需求，以及外部储库状态。最新检查点与历史观测分开：没有新采样的配置提交仍展示新的实际账本，旧观测不重写。历史按模拟时间包含端点筛选，支持分页、CSV 和 JSONL 全量筛选导出；供给日志独立导出实际请求、调度和递送事件。

API 均在 `/api/v2/projects/{project}/runs/{run}` 下：

- `POST /energy/supply`：写入经授权的幂等供给命令。
- `GET /energy`：最新账本、同版本储库状态及历史分页。
- `GET /energy/export?format=csv|jsonl`：完整筛选观测，保留原始微秒、参数、版本及状态哈希。
- `GET /energy/events/export`：所选区间的供给日志 JSONL。

数据、因果日志和适配器状态与核心检查点同库提交，失败整体回滚。读取／导出采用一致事务；项目与用户权限沿用平台授权，浏览器不能跨项目读取或注入。

研究比较页增加储备、累计消耗、累计接受供给、累计未满足需求四个指标。曲线仍先按运行分箱再对独立运行等权平均；配对推断的单位仍是独立实验区组。累计值从账本 `since_us` 起算，包含共同培养，不能将它误称为某一显示时间窗的增量。能量关闭、旧版无账本、累计量饱和时保留缺失／不适用，不补零参与效应估计。

账本是 64 位浮点；累计到浮点上限会标 `counter_overflowed`，原始账本仍可导出，但排除精确守恒和统计估计。页面舍入只为阅读，导出保留存储值。曲线连接是采样间的示意，不是完整连续轨迹；供给日志能给出供给事件时刻，不能反推每次内部资源操作的完整轨迹。

## 旧版本与边界

当前模型的开关、恢复和重新导出均不补发初始储备；普通参数编辑不能修改出生储备。旧版本只读，保留原账本、参数和摘要，不补造能量历史或自动改变生命周期语义。

旧 `energy_starvation_death_ticks` 曾转换为 `energy_starvation_death_us`；这条独立死亡期限现已按确认决定删除。维护与侵蚀保留其每秒单位，默认值是实验初值，不主张生物能量等价。旧证据仍可导出，旧数据无需迁移。
