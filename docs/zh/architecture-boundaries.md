# ThreeMind 架构边界

[中文](architecture-boundaries.md) | [English](../en/architecture-boundaries.md)

## 目的

ThreeMind 是一个连续、可塑的联想动力学实验，最终目标是实现人工意识；当前图网络不宣称已经达成该目标。实验将变化中的网络，与其周围的载体、观察器和应用分开，使观察结果不会通过节点状态暗中引入人类意义。

## 输入边界

```text
世界 / 工具 / 远端设备
  → 感官或躯体适配器
  → 匿名 SensoryFrame
  → 输入总线队列
  → 透明门（或显式启用的环境选择器）
  → 联想运行时
```

`SensoryFrame` 是最终输入协议，只包含匿名数值通道、强度和来源元数据。文字、像素、声音、工具反馈以及未来的气味编码都属于适配器；可读载体可以保存在外部日志，但匿名 Core 节点绝不保存它。

适配器本身已通过采样、编码和遗漏过滤了绝大多数信息。这与 Core 的门不同：默认门是透明的，所有已由适配器编码的通道都会进入联想运行时；Core 不会再用相关性、新颖度或固定通道偏置作预排序。原始帧强度仍是刺激强度；后续由网络内部形成的固化量不应被改称为刺激强度。

如实验需要有限吞吐的躯体条件，可以显式启用环境选择器。它不是默认认知倾向；其通道容量也与运行时的局部边适应计算上限分离。

### V3 创建时确定的感官模式

V3 在创建意识包时确定感官编码与注释策略；运行中的实例、恢复的快照和克隆都不能切换。所有 V3 图节点始终匿名；模型包记录 `sensory_encoding` 与外部注释表：

- `anonymous-distributed` 是标准 V3 模式；
- `labeled-observation` 产生与匿名模式完全相同的分布式数值帧，只给既有通道附加仅供显示的标签。在随机种子和输入帧相同的条件下，其图动力学必须一致；
- `literal-character` 将每个规范化文本字符映射到稳定、可读的感官通道。它是刻意不同的、可解释的实验基线，可用于验证刺激—反应与读出机制，并非标准匿名意识模式。

标签保存在模型包的外部注释表中，并由字符驱动器读出；它们绝不参与激活、传播、连接形成、固化、遗忘或注意选择。

## 躯体适配器

内置模拟躯体位于背景环境与输入总线之间。它先进行采样、阈值判断、感官适应和噪声处理，再排入匿名背景帧；它不拥有语义偏好。

## 物理遥测感官边界

`host-telemetry-field` 是默认开启的应用层感官适配器。一个共享采集器按单调真实时间只读观测宿主 CPU、内存、磁盘、网络汇总计数和供电状态，再由每个意识使用自己的感官种子映射同一采样。`process-telemetry-field` 观测整个 ThreeMind 服务进程；`runtime-telemetry-field` 则只读测量单意识实例执行 Core epoch 的真实线程 CPU 与墙钟时序，并至少延迟到后续输入 epoch 才反馈。后二者默认关闭，以免形成未经选择的自反馈。三者都只能通过 `SensoryFrame` 与 InputBus 进入网络；既不是 Core 能量，也不能修改图状态或回灌 OutputBus。不可用计数器始终明确标记为不可用。详见[物理遥测感官适配器](physical-telemetry-sensory-adapters.md)。

## 多模态感官与输出器官边界

`auditory-sensor` 与 `visual-sensor` 在 Core 外把上传载体或浏览器实时采集的 PCM、图像和视频像素编码为分帧、匿名、非负的 `SensoryFrame`。它们可以执行重采样、频带能量、灰度、边缘、阈值与局部视网膜 patch 等确定性物理过滤，但不使用 ASR、OCR、目标识别、预训练 embedding 或大模型。短音频块先在适配器内组成完整感官窗；视觉 patch 依次排队，避免一次全图共激活变成意外的密集连接指令。

`acoustic-output-organ` 与 `activation-image-projector` 只订阅匿名 OutputBus，并把节点身份与激活投影成振荡器控制或灰度像素。它们不读取明文标签，也不会自动把输出回灌为输入。上传原始载体使用内容寻址保存；实时麦克风和摄像头原始内容默认不落盘。协议、配置、审计与解释边界见[多模态感官与输出器官](multimodal-sensory-and-output-adapters.md)。

## 注意与竞争插件

运行时提供中性插件协议。插件必须显式请求竞争，才能对匿名通道排序或截断；仅有一个乘数不会暗中开启选择。插件只能约束匿名通道的增益，或约束已启用竞争的容量，不能写节点/边状态、注入文字或发出目标命令。

`energy-budget` 现在是独立的外部资源供应适配器，而不是注意调制器。只有模型显式开启能量模拟时，直接激活、联想传播和可选抑制扩散才会消耗一个实验性标量；Core 不会自动恢复能量。供应适配器默认关闭，只能按配置向资源端口供应有限能量，不排序、不筛选刺激，也不改变注意预算。该标量尚不等同于现实物理能量，不能据此引入求生、奖励或内容偏好。

## 局部抑制、能量与动力学观察

运行时默认开启拓扑局部抑制，同时保留显式关闭开关以进行对照实验。兴奋边仍有向；抑制仅把任一方向的边视为物理邻接，并以有限、衰减、延迟的势在邻居之间扩散。它没有因果波 ID、全局赢家扫描或语义目标。旧式全局稳态钳制默认关闭，只有模型包显式声明时才缩放总激活量；缺能结构损伤、物理遥测感官与详细动力学追踪也都是彼此独立的可选能力。完整规则和解释边界见[局部抑制、可选能量记账与动力学追踪](local-inhibition-energy-and-dynamics.md)。

## 局部新颖、联想与固化

新颖度不再是输入排序特征。新边形成时，只有它触及已有连接的邻域，并且由局部传播获得非零联想触达，运行时才会施加一个很小、可配置的局部新颖加成。在该正值范围内，联想触达越弱，视为越新颖；孤立边或联想触达为零的连接不获得该加成。重复直接触达与重复联想遍历会分别增强稳定度和支持度。这些都是与载体无关的图动力学规则，不是语义识别规则。

## 输出边界

```text
联想运行时
  → 匿名 OutputFrame
  → 输出总线
  → 结构观察器 / 字符驱动器 / 可视化器 / 工具输出端
```

`OutputFrame` 是活跃节点、内部连接、指标和结构变化的有界投影，不携带节点标签或预先指定的目的地。被动结构读出是输出适配器，不再需要直接访问图；可选字符驱动器是独立适配器，只在外部存在 V1 符号字典时才有可读字符可用。

输出不会自动回灌为输入。未来如要研究自反馈，应通过独立躯体/环境适配器形成具有延迟、失真、噪声且可关闭的后果信号。

## 网络传输边界

网络传输不属于输入或输出总线，而是负责认证、校验、序列化和转发匿名帧的应用/边界适配器。

已实现的 WebSocket 协议为 `threemind-network/1`：

1. 连接 `/api/network/input` 或 `/api/network/output`；
2. 发送带协议版本、对端 ID 和共享令牌的 `hello`；
3. 输入端只能发送含匿名通道的 `sensory_frame`；
4. 仅在显式开启时，输入端可发送只含标量 `gain`、`budget` 的 `modulation_frame`；
5. 输出端接收匿名 `output_frame`。

共享令牌在本地加密保存，API 不会返回它。网络默认关闭；若服务不只监听本机回环地址，应使用 TLS 反向代理，并将令牌视为部署密钥。

`modulation_frame` 被限定为类似远端生理信号，而不是管理员命令：它不能创建节点、修改连接、提交文本或指定某个概念。

输入握手与感官帧示例：

```json
{"protocol":"threemind-network/1","type":"hello","peer_id":"sensor-a","token":"shared-secret"}
{"protocol":"threemind-network/1","type":"sensory_frame","consciousness_id":"optional-id","channels":{"0":0.42,"17":-0.10},"intensity":0.8}
```

允许的调制帧不含通道或图字段：

```json
{"protocol":"threemind-network/1","type":"modulation_frame","gain":0.85,"budget":0.70}
```

输出订阅会收到 `output_frame`，其中包含指标、匿名节点 ID/活动、匿名边和最新结构变化。远端通道标识会经每个本地意识自己的感官映射重新编码，绝不会成为 Core 标签。

## 设计结论

- 类似功能区的结构应由重复感官活动与连接自然形成，而不应预先划定脑区；
- 不同意识可以为相似外部载体形成完全不同的内部映射；
- 可读输出是适配器的解释，不是 Core 内部保存了文字或意义的证据；
- UI 与 CLI 属于管理平面：配置适配器、查看日志，但不实现联想动力学。
