# 执行资源、进度与任务故障预警

2026-09-08，F5e。入口在「设置 → 通知与邮件」，监测默认关闭。它是 Lab 的只读运维工具；与作为真实刺激的宿主／进程感官遥测分别配置。开启监测不会向输入总线发送数据，不会暂停任务、改变连接或将故障判为模型死亡。

## 配置和查看

项目所有者需要同时启用项目通知、执行预警事件和「启用可配置执行预警」。高级规则默认折叠，可配置指标、比较符、阈值、持续采样时长、重复提醒间隔、最大采样间隔及独立开关。图形／JSON 双向同步；JSON 有行号、高亮、格式化和校验，保存始终校验。每次保存创建规则版本，清空旧规则的持续窗口；历史通知仍保留原版本和原始依据。

预设是可领取任务等待达到 300 秒、过期未恢复租约至少 1 个、活动脑／种群距提交或租约起点达到 180 秒、宿主内存达到 95%。除租约外，默认要求 30 秒的采样持续窗口；重复间隔 300 秒，最大采样间隔 60 秒。它们只是可调整的工程阈值，不构成任意规模模型的性能保证。CPU 和进程 RSS 可另建规则，没有把充分利用 CPU 默认判为异常。

全部项目成员可查看最新观测、规则状态和通知，并导出当前观测 JSON。这个导出只包含一次观察及其当前规则状态，不冒充完整历史性能轨迹。通知中保留命中、重复、解除及缺失转换时的数值、单位、规则、时钟、范围和证据哈希；全部轮询样本不会逐条长期保存。

## 指标和覆盖范围

| 指标 | 含义与边界 |
| --- | --- |
| 可领取任务等待 | 本项目已到可领取时间的任务最大等待年龄；无排队任务为 0。schema 46 之前未知的状态变更时间保持未知，不通过当前时间猜测。暂停或终止的普通意识任务不参与。 |
| 过期租约 | 已过期但尚未完成恢复的任务数。下一次恢复后可以回落，不等于任务已永久失败。 |
| 提交年龄 | 正在持有有效租约的普通意识／生态种群，距最近实际提交或当前租约起点的最长宿主时间。没有这类任务时显示暂无执行对象。 |
| 进程 RSS | 本项目活动任务所分配执行进程的最大常驻内存，单位 MiB，不包括子进程。 |
| 进程 CPU | 同一执行进程范围的最大 CPU 占用，100% 表示一个逻辑核心；首次差分采样未知。 |
| 宿主内存 | 这些执行节点所在物理宿主机的最高内存使用率，包含其他应用，不是 ThreeMind 独占用量，也不等于容器 cgroup 额度。 |

资源采样复用执行节点公告和租约续期，进程内最短缓存 5 秒，不进行阻塞 CPU 采样。有效期 45 秒；任一相关节点缺失、过期或不可读取时，聚合值未知，不取剩余节点的最大值冒充完整观测。最多覆盖 256 个活动节点；超过上限明确说明范围不足。无活动任务与缺失数据分别显示。

等待、租约、提交年龄使用数据库宿主 UTC 墙钟；资源持续窗口按观测时钟推进，但相同缓存样本不重复累计持续时长。只有有效采样点满足条件，不能据此证明两次采样之间连续超限。间隔过大或缺失使持续窗口失效；宿主校时向后跳会重新计时。它们都不是 Core 的模拟时间。

## 故障、投递和部署

普通意识保留原有运行失败通知。生态、多代训练、研究协调器、证据采集和其他后台作业达到最终失败状态时，通过既有事务触发器产生「后台任务失败」。运行控制、自然活动耗尽、取消和执行异常保持不同含义。AI 和观察作业仍在各自调用／观察界面显示失败，不额外制造重复故障通知。

复用现有 notification worker 与 PostgreSQL，没有新增 MQ 或服务。每轮最多发现 10 个到期项目，每个项目约 5 秒检查一次，实际延迟受 worker 和数据库负载影响。即使邮件关闭，站内监测仍可工作；邮件受既有端点许可、权限、冷却和发送额度控制。监测代码本身发生非数据库异常时，停止该项目监测、显示经过脱敏的错误类别；修复后重新保存策略恢复。数据库故障沿用原 worker 重连机制。

schema 46 增加一个小型项目监测状态表，以及节点资源样本、任务状态时间字段；没有保存第二套模型。旧 notification worker 不领取新版本通知配置。升级需迁移数据库并更新 API、Runtime worker 和 notification worker。独立无数据库 Runtime 不依赖本功能。

详见[通知与邮件](v2-notifications.md)、[生态观察](v2-ecology-observer.md)和[本阶段验证](../benchmarks/2026-09-08-execution-health-validation.json)。工程验收中人为设置「等待 ≥ 0」用来验证提示链路，明确标为测试条件，不作为真实故障或意识研究结果。
