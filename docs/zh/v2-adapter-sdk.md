# 适配器公共契约、SDK 与接入验收

2026-09-08，F5f。现有 24 个适配器使用同一公共声明格式，但保留各自的数据协议和实现。Core、输入／输出总线及 `network/2` 编码没有因此改变，也没有增加数据库或第三方代码安装服务。

## 共用什么，各自保留什么

`threemind.adapter-contract/1` 声明适配器身份、协议版本、角色、可用传输、数据端口及单位、时钟域、身份依据、映射性质、恢复条件、背压、生命周期、错误和宿主能力要求。`threemind.adapter-manifest/1` 为该声明增加规范 JSON 的 SHA-256。它是可检查的接口说明，**不是可执行驱动、模型文件或设备授权**；校验和验证内容一致，不验证作者身份或代码可信度。

| 角色 | 现有入口 | 边界 |
| --- | --- | --- |
| 刺激输入 | `InputBus.schedule(Stimulus, metadata)`、各感官编解码器 | Core 只收到匿名刺激；信封、文字和标签留在工具层。整个载体应先完成解码／时间校验和预算预留。 |
| 执行器输出 | 当前身体端口与输出器官 | 将输出信号变成物理响应；不能以适配器内置善恶、任务目标或语义脑区替代学习。 |
| 被动观察 | `OutputBus.subscribe/publish`、原始读出 | 完整证据消费者各自收到独立副本；派生解释和显示筛选不改写原始激活。 |
| 载体过滤 | 身体过滤与来源策略 | 测量采样、适应、噪声、显式准入规则独立记录；不伪装成内核自发形成的选择。 |
| 资源 | `ResourcePort`／现有有限能量供给接口 | 使用已启用的资源机制与记账，不把资源值偷偷混成刺激或奖励标签。 |
| 显式控制 | 有期限的标量调制接口 | 需要单独声明和授权；协议没有开放任意节点／连接写入。 |

上述角色可以组合，网络设备分别声明输入、观察、控制和资源能力，并由设备绑定逐项授权；能力声明不会自动开启权限。传输可以是函数、HTTP、WebSocket、浏览器媒体、驱动或共享内存。后两项供第三方声明，不能据此认为内置适配器已经实现了它们。二进制、批处理、非阻塞硬件和不同恢复模式仍然可以使用专门的载体协议，不要求把每一帧变成 JSON。

## 接线、时间和单位

公共声明中的 `identity_fields` 是需要核对的字段名称，不含实际值。`configuration.*` 表示所属配置，不保证这些配置都在 `.tmind` 的 profile/5 内；例如世界／躯体继续依赖完整世界和 Runtime 恢复上下文。

网络设备的实际匿名接线仍使用 B13 的 `threemind.network-wiring/1`，包含稳定 `wiring_id`、感官种子、编码版本和校验和；凭据单独保存。部署到另一台机器时应复用模型、对应 profile、世界／身体定义以及必要接线和校准信息，不能用新的设备绑定 UUID 意外替换学过的匿名通道。公共声明不能代替这份接线清单。

Core 使用整数微秒；物理世界、采集时钟和宿主单调时钟分开声明。真实设备要记录采集时间到模型递送时间的校准、偏移、延迟及重同步过程；不能把宿主时间戳直接当成模型时间。输入帧排队之后保留其实际递送承诺和来源。物理计数的具体单位与可用性在各源数据中保留；抽象能量不能未经校准就标成焦耳。

`negotiate()` 比较明确的协议、角色、传输、时钟域、端口单位及恢复要求。单位按声明精确匹配，不自动把 `mm` 猜成 `m` 或插入转换。声明相符也需要实际驱动测试；声明不同则返回具体差异，不能静默选择另一个协议。`execution_authorized` 始终为 `false`，真正绑定仍走设备凭据和权限流程。

## 界面与 API

「设置 → 设备与适配器 → 接入验收」可以选择内置声明、导入第三方声明、下载清单，图形化选择所需协议、角色、传输和恢复要求。高级项提供时钟／单位核对，以及带行号和高亮的只读 JSON。导入仅校验文字和哈希，不加载路径、不执行上传代码、不创建模型或绑定。

普通适配器目录的「总线端口与契约」同步展示公共声明。当前身体与发声等固定投影明确标注为工程对照，不能当成已由训练形成器官分工的证据。

- `GET /api/v2/adapters/{id}/manifest` 返回内置声明和校验和。
- `POST /api/v2/adapters/validate` 接收 `manifest_json` 及可选 `negotiation`，返回结构结果、与已安装声明是否一致、具体不匹配项。
- 既有 `/adapters` 与意识内 `/adapters` 继续来自同一注册表，增加 `contract` 字段；宿主能力及实际运行状态仍独立查看。

两条新接口需要登录；不写数据库。最大声明 128 KiB，拒绝重复 JSON 键、未知字段、非有限值、损坏哈希及不支持的版本。第三方可以声明新数据协议，但不会被系统自动注册为可执行插件。

## 无数据库 SDK

安装项目后提供 `threemind-adapters`，也可以直接使用模块入口：

```powershell
python -X utf8 -m threemind_runtime.adapter_cli list
python -X utf8 -m threemind_runtime.adapter_cli describe remote-anonymous
python -X utf8 -m threemind_runtime.adapter_cli validate adapter.json --transport websocket
python -X utf8 -m threemind_runtime.adapter_cli probe remote-anonymous --backend native
python -X utf8 examples/adapter_sdk_demo.py
```

`describe` 输出声明；通过 shell 按需重定向保存，运行本身不会自动更新模型文件。`validate` 只读声明，不需要 Lab 或 PostgreSQL。协议不匹配退出码为 2。`probe` 显式创建小型独立工程样例，不触碰已有意识；支持 `reference` 和 `native`，缺少所选原生后端时失败，不自动替换。

内置可执行样例覆盖 network/2、匿名帧和文本感官。开发者可调用 `check_input_encoder(encode, carrier, backend=...)` 接入自己的固定样例；`encode` 返回有序 `Stimulus` 序列。原始载体可为二进制或 JSON 可表达对象，不要求驱动本身使用 JSON。仓库中的 `examples/adapter_sdk_demo.py` 展示四个 PCM16 样本通过统一网络接线形成刺激，既不指定脑区，也不生成连接或目标标签。

验收检查同一配置和载体的编码确定性、原载体不被修改、排队状态精确恢复、改换观察注释不改变 Core、恶意观察消费者不改写其他证据、显示跳过计数、容量拒绝不改变状态，以及消费者异常可见和解除订阅。报告保存样例哈希、编码哈希、最终脑哈希、后端与覆盖边界。它不依赖数据库、GUI 或云服务。

`check_input_encoder` 是面向确定输入样例的开发工具，不是实时硬件测试框架。默认至多 64 帧、256 个通道项和一秒内的刺激；持续、有状态感官须显式固定／恢复其采样与编码状态，再提供对照函数。真实硬件仍要自行验证超时、断线、背压、原始数据持久化、执行器物理响应和安全约束。Python 回调是开发者主动传入的受信任代码，本工具不是代码沙箱或认证机构。

## 与研究假设的关系

这次交付没有引入手工脑区、连接增删接口或新的可塑输出层。身体时延、位置、响应范围等差异可能在统一刺激规则下影响塑形，但其结果仍需训练和受控实验验证。当前固定电机投影如实作为工程基线保留，不能因为接口可用就宣称模型已经学会自主控制机器人。

机器人研发者可以在本机独立部署 Core／Runtime，驱动采集感官并经对应适配器递送，读取输出并产生身体动作。虚拟训练与实际部署还需保持或明确改变编码、身体校准、端口身份和时延；接入本身与是否学会控制是两项不同验收。参见[具身差异与功能分化](embodied-functional-differentiation.md)、[稳定网络接线](v2-network-devices.md)及[冻结验收记录](../benchmarks/2026-09-08-adapter-contracts-validation.json)。
