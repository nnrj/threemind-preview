# 生态训练容量、历史成本与测量边界

“不限速”是取消人为等待，不承诺任何配置都比物理时间快。脑模型、虚拟身体、物理求解、输入与完整读出、检查点和数据库共同决定实际速度。网页显示档位只控制观察负担，不改变这些科学参数。

## 本机短程容量探针

2026-09-07 使用原生 Rust Core、Python 3.11、MuJoCo 3.12.0、NumPy 1.26.4，在 16 个逻辑 CPU、约 23.37 GiB 可识别物理内存的 Windows 工作站运行。每种规模只测一次，同时有 Docker 构建及闲置工作站进程，不作为纯净吞吐基准。两种环境的测量发生在不同时间，其比值不是严格的加速效果。

从空脑开始，保留默认身体感官、读出配置和工具时钟，关闭繁殖，推进 **0.1 模拟秒**。没有 RGB、数据库、实际证据订阅者或浏览器。测量包含读出计算，完整存储／编码成本需要另外计算。这些脑平均约 8 个节点，不能代替成熟模型。

| 个体数 | 共享世界推进耗时（秒） | 独立环境推进耗时（秒） | 共享检查点后 RSS（MiB） | 独立检查点后 RSS（MiB） |
| --- | ---: | ---: | ---: | ---: |
| 8 | 0.236 | 0.073 | 76.31 | 80.25 |
| 32 | 1.108 | 0.284 | 79.65 | 97.00 |
| 128 | 5.054 | 1.093 | 93.50 | 164.50 |
| 256 | 7.229 | 2.252 | 111.13 | 250.95 |

推进耗时不包含初始化或检查点；RSS 是指定边界的采样，不是连续峰值。不同规模在同一进程顺序执行，分配器与库缓存会保留。256 个体的恢复元数据分别约 1.182／1.334 MiB，全部脑状态载荷约 3.340／2.914 MiB；实际展开对象会更大。

当前协调器按共同物理边界串行推进脑实例，不能把 16 个逻辑 CPU 当成已经有 16 倍训练速度。共享世界包含真实身体间作用，独立环境拥有各自的物理实例；它们是不同实验条件，不应为速度偷偷互换。允许 256 个身体不代表当前实现能对 256 个成熟脑实时训练。

可复跑命令（选择尚不存在的输出路径）：

```powershell
.venv/Scripts/python.exe scripts/benchmark-ecology-scaling.py --counts 8 32 128 256 --habitat shared --output .work/shared-probe.json --background-load "填写其他并发负载"
.venv/Scripts/python.exe scripts/benchmark-ecology-scaling.py --counts 8 32 128 256 --habitat independent --output .work/independent-probe.json --background-load "填写其他并发负载"
```

脚本记录完整参数、实现版本、元数据哈希及每个脑的哈希，不读取旧 `data/`。原始结果：[共享世界](../benchmarks/2026-09-07-ecology-scaling-shared.json)、[独立环境](../benchmarks/2026-09-07-ecology-scaling-independent.json)。

## 已处理的增长与剩余成本

- **死亡脑**：确认死亡、身体已脱离且事务成功后，释放可变引擎和展开比较基线，保留可验证的状态引用。66 个累计个体的既有探针全部哈希一致，最终 RSS 约从 260.32 降到 104.75 MiB；见[死亡脑保留测量](../benchmarks/2026-09-07-ecology-retention.json)。
- **页面账本**：详情不再把全部账户和资源池反复传到 Python／浏览器，库存按固定恢复点分页；原始账本完整保留。这不消除数据库解析大型 JSON 的成本。
- **原始脑数据**：Lab 使用已有关系数据、差分与分块恢复；独立生态 SQLite 使用按哈希分块状态。它们不会反复覆盖一个大模型 JSON 文件。
- **累计元数据**：当前恢复元数据仍包含全部个体工具、谱系、身体账户与资源池；序列化、守恒核对、部分循环及最终导出随累计数量增长。死亡脑按需读取没有把这些成本变成常数。
- **观察与证据**：原始读出节点必须完整保留。可以显式调整采样协议或关闭某类观察，不能把隐式裁剪当作优化。Python 对象复制与 JSON 编码仍有成本，成熟网络需要测量整条记录路径。

### 无订阅者时的证据复制

提交 `2d447e3` 将个体证据的深拷贝交给已有 OutputBus：无人订阅时只添加顶层信封，有订阅者时逐个隔离完整数据，不再预先复制一份无人接收的嵌套对象。读出计算、事件序号和采样时钟照常执行。加入了会主动清空嵌套数据的观察者，与第二个正常观察者、单观察者及无人订阅路径对照；全部恢复元数据、脑哈希和正常观察序列一致。含生态 Runtime／CLI／PostgreSQL 与读出保真的 **27 项回归通过，90.69 秒**。

32 个初始空脑、推进 0.1 模拟秒，交替执行四组成对测量：无人订阅的耗时中位数由 0.5895 降至 0.4401 秒，约减少 25.3%；完整订阅的中位数由 0.4637 变为 0.4982 秒，约增加 7.4%。后者仍需要完整复制，本次有并行验证负载且仅四组测量，不能据此宣称订阅路径加速，也没有用较好的单次值掩盖它。每一对的恢复元数据、全部脑哈希与完整观察哈希均相同。详见[全部成对测量](../benchmarks/2026-09-07-ecology-observer-copy.json)。这项优化不消除历史元数据和数据库存储成本。

同样的成对步骤已整理为可复跑脚本，固定旧函数并记录当前函数源码；运行 `.venv/Scripts/python.exe scripts/benchmark-ecology-observer-copy.py --output .work/observer-copy-recheck.json --background-load "填写并发负载"`。它不会覆盖已有测量；若任一完整性对照不同，会直接失败。

## 后续优化边界

应继续测量成熟模型、种群周转和真实 Lab 存储，分别报告物理步进、脑推进、读出、事务、传输和渲染耗时。热点若来自历史扫描，可增加活动索引、将不变历史工具状态引用化，并通过完整哈希和事件顺序对照验证；不能删除死亡者、弱活动或失败个体来缩短历史。

更高并行度可用于共同边界之间的独立脑计算、独立评估副本和独立世界。共享世界的物理结算、同时间事件顺序及群体原子提交仍要保持明确。多机共同物理仿真没有在本版实现，也没有用隐藏近似代替。

研究预算、完整证据导出上限和容器资源上限均应显式配置与报错，不等同于设备推荐。本页不据小型探针给出“某显卡或某内存能训练 AGI”的配置承诺；具体研究应以目标脑规模和完整记录方案先做短程试运行。
