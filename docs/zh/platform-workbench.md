## 进入和打开意识

按原命令启动工作站：

```powershell
.\scripts\start-lab.ps1 -Python .\.work\kernel-venv\Scripts\python.exe
```

打开 <http://127.0.0.1:8877>。首次设置页面为原本的 `local` 身份设置用户名及密码，保持其身份和既有资料归属。此后可记住登录；账号、角色及授权在“用户与权限”管理。

单人部署直接使用这个超级管理员账号即可，无需逐个菜单、项目或动作申请授权。AI 客户端一次登录后使用受保护配置续用；限定委托是可选渠道。删除／迁移确认、版本冲突及受管实验控制属于操作边界，不是权限申请。

默认首页是“意识工作台”。没有打开意识时，中间提供“新建意识”和“打开意识”，不会自动选择或运行最近实例。“打开意识”从有权查看的实例中选择，只读取状态与图像。图像布局、画面冻结、意识暂停分别操作；当前实例已经运行时，看图不会停掉它。

右侧有属性、文本刺激和真实读出、感官与输出面板。页面打开不申请摄像头或麦克风，不自动播放；上传选择取消不更改感官。实际实时采集需要运行中及实时模式，按提示显式操作。离开页面释放本页设备与播放资源，后台实例继续按原执行规则运行。

受生态、实验或冻结评估控制的实例可查看，运行操作仍由所属控制器处理。旧详情、恢复、历史分叉、导入及高级研究功能保留各自入口；Core-only 文件不代表完整个体。

## 新建默认、模板和准备态

“系统设置”无需选择项目，分别提供新建默认、配置模板、设备能力、AI、邮件、宿主执行、存储和个人偏好。新建界面的层次是**内核版本 → 该内核的配置模板 → 参数配置**；它们在同一界面，不是必须依次提交的步骤。先选择实际内核身份，例如 `continuous-memory/4`；下方说明解释其机制及可用执行后端。

模板默认选中该内核的系统新建默认；尚未保存系统默认时采用该内核自己的出厂默认。可显式采用同核内置研究模板、已保存模板或项目预设，然后继续修改参数。配置解析仍是：内核出厂默认 → 系统新建默认 → 显式选中的一份模板 → 本次修改。一个内核可有多个模板；模板名称不再冒充内核版本。切换内核会重新列出匹配模板，存在未保存修改时需确认。选择归属项目不会替换草稿。

“保存当前参数为模板”保存配置，不保存成长后的权重或完整个体。实例详情也可把已保存的实例参数转为模板；这项操作只读取配置及元数据版本，不启动、暂停、恢复或刺激实例。模板不能在后续修订中改为另一个内核；已有历史修订保持原样。

当前目录提供 16 个实际内核身份：`causal/1`～`causal/9`、`continuous/1`、`continuous-memory/1`～`continuous-memory/4`、`lif/1` 和 `unified-associative`。原 V1、V2、V3 是 `unified-associative` 下的三份历史参数模板，不是三个新内核。默认内核仍为 `continuous-memory/3`。这次整理不按版本号强拆连续家族的共享 Rust 实现。

`unified-associative` 仅支持 Python 参考后端，保留原 `97d8592` 的输入 epoch、内部 tick 和感官编码。旧标签编码不会被静默替换成现代匿名编码。其检查点采用独立 JSON 完整原包路径，不经过现代节点／连接的 Arrow 格式。执行后端属于宿主元数据 `execution.backend`，在科学配置 `spec` 之外；不支持的显式后端会报错。旧 causal 内核的结构出生采用各版原有规则；unified 尚无对应原规则时拒绝结构出生，空白新建及原样分叉仍可用。

新建默认“创建并准备”：保存配置及来源，不产生运行任务、恢复点或模拟推进。“创建并开始”是另一项明确操作。准备态可编辑允许调整的字段，保存和首次开始均检查元数据版本；出生固定项不能事后修改。

系统默认和模板具有独立修订。已经创建的意识保留自身实际配置；模板修改不会影响它。显示偏好只作用于本浏览器并按账号隔离，不改变模型动力学。宿主速度、队列与并发属于执行管理，不能当作 Core 能量参数。

2026-10-11 的本部署已显式完成数据库 67 → 68；其他部署更新代码后须先执行迁移，再启动新版服务，应用不会自行升级旧库：

```powershell
$env:PYTHONPATH = "$PWD\src"
.\.work\kernel-venv\Scripts\python.exe -m threemind_lab.cli migrate
.\.work\kernel-venv\Scripts\python.exe -m threemind_lab.cli doctor
```

迁移使用现有本机配置。工作站负责匹配后端的执行进程；独立部署执行进程时，Python 历史内核可用 `python -m threemind_lab.cli worker --backend reference --task-family kernel-reference`。迁移、测试边界及原件保存说明见[本轮交付记录](plans/kernel-creation-hierarchy-delivery.md)。

## 项目、资料和服务

导航分为意识工作台、研究中心、资料中心、系统设置、文档与帮助。研究与资料页面默认浏览全部授权项目，项目筛选仅过滤列表；对象详情、编辑草稿和发送目标按其真实身份保持。新建保存前明确归属项目，可以直接新建项目，不自动采用第一个项目。

项目详情集中管理成员、项目预设、研究规则和项目工具。旧链接继续解析到对应对象或独立项目工具页；切换筛选不把同一资料菜单换成另一套界面。

AI 供应商统一由平台目录管理，查看、配置、调用分别授权。迁移保留原供应商 ID、修订、密钥及调用费用关联，原项目使用范围继续通过授权表达；不合并同名供应商，不自动扩大使用范围。诊断可直接在服务目录发起，无需创建虚构项目。

邮件发送服务与项目事件规则分开。平台保存运输配置和密钥；项目选择获授权服务并保存事件、收件人等规则及固定服务版本。修改服务不自动修改旧规则、重发旧通知。铃铛汇总本人授权项目的通知，不要求先选项目。

## 退出与持续运行

主动退出默认“退出并继续运行”。也可明确选择允许独立控制且有暂停权的实例，等待确认暂停后退出；未确认时保持登录并显示错误，不把命令受理冒充暂停完成。受管实例不能在退出窗口绕过其控制器。

登录过期、断网、关闭页面及普通 CLI 客户端结束都不自动暂停实例。新操作仍须有效认证及当前权限；已接受运行的主体信息保留，账号会话不会写入科学检查点。工作站进程本身停止、机器断电和原有宿主安全保存机制是另一回事，不由退出登录触发。

AI、CLI、MCP 和 Python 采用同一后台服务与记录标准；非交互凭据和命令见[访问说明](platform-access.md)。独立 Runtime 的本机运行不需要 Lab 登录。
