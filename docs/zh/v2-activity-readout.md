# 时序活动读出器

[English](../en/v2-activity-readout.md)

2026-09-30：新增 [活动过程分析 V2 与检测工具](v2-observation-tools.md)。下文描述保留的 V1；V2 另记整个观察期间的动态变化，新建配置默认 V2。

旧算法保留为**活动稳态判定**（`temporal_readout`）。它要求候选集合、相对分布与总幅度同时稳定；旧结果 `converged`、`residual_decay` 等保持原值。“幅度衰减”是 `residual_decay` 的新显示名称，不修改已有证据。

新的**活动过程分析**（`activity_readout`，证据版本 `threemind.activity-analysis/1`）回答四个独立问题：

| 分析 | 判定与记录 |
|---|---|
| 响应模式收敛 | 刺激递送结束并满足最短观察后，尾段各次完整超基线向量与尾段末向量归一化比较，总变差距离均不超过配置值。全零或总量低于下限不归一化。记录首次达标窗口末的实际节点激活和排名。 |
| 幅度变化 | 另报稳定、下降、上升、波动或低于下限；不以幅度下降否定比例稳定。使用超基线总量，原始激活总量与向量同时保留。 |
| 周期活动 | 在等间隔采样中寻找三个非恒定重复周期；比较完整分布和幅度，允许节点集合相同而幅度周期变化。只表示采样发现的周期，不声称发现连续轨迹的精确周期。 |
| 响应结束 | 递送结束后，尾段超基线活动持续低于下限。背景活动仍可能存在，不能用它宣布意识死亡。 |

四项均可独立关闭。记录到模式收敛后仍继续观察其他项目，直到响应结束或观察预算截止。判定窗口末的排名保存在 `primary_result.nodes`、`candidate_ids` 和每节点的 `decision_activation`；`ranking_time_us` 是这次排名的时刻。`last_activation` 始终表示整个观察窗口最后一次采样，不能拿它覆盖更早保存的收敛结果。窗内峰值和积分另外保留。没有测到模式或周期时不编造一个主要响应。

## 新旧共存和操作

创建界面的新协议默认同时启用两者，新分析作为主要聊天结果；旧判定在读出记录中作为对照，不重复刷聊天消息、不重复触发 AI 解读。旧保存协议缺少 `activity_readout` 时视为未启用，恢复时不会自动加入新观察。独立 CLI 原有默认值同样保留。

图形配置与 JSON 共用配置目录。时序观察实验可选择继承来源、活动过程分析或仅原算法；探针始终在独立副本运行。结果页显示四类结论、判定时刻、窗口末激活、判定时激活、峰值与完整轨迹。CSV／JSON／报告可使用 `decision_activation`，历史 `last_activation` 列含义不变。

CLI 将以下内容保存为读出配置文件，并传入 `--readouts 新证据.jsonl --readout-config 配置.json`：

```json
{
  "structural_readout": {"enabled": false},
  "temporal_readout": {"enabled": true},
  "activity_readout": {"enabled": true}
}
```

## 边界与预算

新算法分析全部超基线向量，不用旧版前几个候选代替完整向量。读出阈值只影响派生分析，完整节点聚合与正激活／正超基线轨迹作为证据保存；未储存为正数的向量分量为零，但节点是否出现仍以完整节点聚合和源节点数核对。采样间采用左值保持估计，不能冒充连续观测。

默认每窗完整轨迹数值预算 2,000,000，另有累计节点、采样点数、同时窗口和模拟时长上限。超限明确删失，不静默裁剪节点。模式首次达标、完整观察是否因上限结束，分别记录；预算不足不是“没有发生”的证据。并行的读出器读取同一批只读节点采样，结束时互不终止。所有指标都在 Runtime 观察层，不写回内核。
