# 连续发声与激活图像输出

「感官与输入 → 器官输出」同时提供连续查看与完整历史记录。先在意识参数中开启发声器或投影器，运行时点击「跟随当前输出」接收最新已提交的控制帧；声音默认静音，需要另行点击「开启连续声音」。停止、离开页面、访问失效、运行暂停／结束或网络中断会释放声音资源。

器官是被动输出端。它读取匿名节点的实际激活，不读取标签、不使用语义解释或 TTS，不向输入总线自动回灌。实体机器人可以使用无数据库的 Runtime 输出接口直接连接器官；浏览器界面显示的是数据库已经确认的输出，带有持久化与传输延迟。

## 独立模拟时间采样

发声器与投影器各自有 `output_interval_us`，默认均为 100,000 µs，可设置为 20,000～10,000,000 µs。它们不再共用指标 `sample_us`，不受显示性能档位影响。

每个器官的下次采样时间由最近一次采样时间加自己的间隔确定。Runtime 在该模拟时刻只读投影，随后推进下次时间；暂停检查点保存两个时钟，恢复后继续。结束时可以记录一个明确标注 `terminal` 的末帧，暂停不伪造新的终止采样。修改器官配置后从修改后的当前模拟时刻建立新采样节奏，不更改历史记录。

器官时钟和输出事件随内核检查点原子提交。保存失败不会留下仅有读出、没有对应模型版本的部分证据。输出缓冲达到约 8 MiB 时实施数据库背压，不静默舍弃科研采样。Python 参考内核与 Rust 原生内核都通过了不规则器官时刻下的最终状态对照，额外观察不改变固定输入的核心结果。

## 声音与图像映射

发声器选择超过阈值的前 `maximum_voices` 个活动节点，按激活降序、身份升序确定并列。匿名节点 $i$ 对应 48 个等比频点之一：

$$f_i=f_{\min}\left(\frac{f_{\max}}{f_{\min}}\right)^{(i\bmod 48)/48},\qquad A_i=\min(1,\max(0,g_a a_i)).$$

默认下界 110 Hz、上界 1,760 Hz（不含上界）、增益 $g_a=1$；默认频点对应旧版的四个八度／半音映射。上下界可以在图形配置中调整，上界必须严格大于下界。幅度饱和仅发生在器官端，不改节点激活。浏览器监听音量另在本页面调节，只控制当前扬声器。

图像继续采用匿名身份的确定性哈希落点；同一像素的多个节点取最大亮度：

$$P_j=\max_{i\mapsto j}\operatorname{round}(255\,\min(1,\max(0,g_p a_i))).$$

投影亮度增益 $g_p$ 默认为 1。尺寸、增益、间隔均可配置；此灰度投影与三维意识网络图不是同一功能，像素碰撞也不是模型中的连接。

## 连续跟随与完整证据

浏览器通过经过项目授权的 SSE 连接跟随已提交输出。服务最多为一个连接保留每种器官的最新记录，按不同器官分别更新声音／图像，避免慢客户端积累无界播放队列。页面显示模拟时间、数据库提交版本和为了跟随最新状态而跳过的已保存记录数。第一次连接从最新位置开始，不倒放此前所有输出。

持续声音使用可复用振荡器，在控制帧之间做短幅度渐变以避免点击噪声。它跟随当前提交与网络到达节奏，**不是逐条按模拟时间重放的完整录音**。冻结、慢计算或网络中断时不会无限维持旧声音；控制帧超过与器官间隔相关的等待窗口会自动静音。关闭器官配置后，当前跟随会清除该器官的旧输出。

完整记录保留在同一数据库中，慢查看连接跳帧不会删除它们。「完整输出记录」可翻页、试听单帧、下载该帧合成 WAV／PNG，并导出完整 JSONL；模型证据包也包含器官记录。单帧 WAV 是所选控制值的半秒合成，不是设备录制。高频控制值会选择足够的合成采样率，避免越过 Nyquist 上限。

## Runtime 与模型格式

`threemind_runtime.output_organs.OutputOrgans` 可在不依赖 Lab／数据库的宿主程序中使用：用 `output.subscribe(name, consumer)` 绑定器官输出总线，读取 `next_us`，让内核推进到该时刻，调用 `observe(engine)`。订阅者各自得到隔离的控制帧；Lab 的证据记录也是一个订阅者。`capture()` 保存器官采样状态，恢复时传入 `state`，宿主重新绑定订阅者。过了应采样的时间再调用会明确报错，不能悄悄跳过并冒充完整输出。

新增六项器官参数进入共同配置目录，并随 `threemind.runtime-profile/4` 保存。Python／Rust 与独立 SQLite Runtime 均支持当前 profile；旧 profile/1～3 的字段集合及哈希仍能读取、原样往返，旧 profile 没有的新器官设置由新宿主采用默认值。没有改变内核的模型状态格式或默认动力学。

API 为 `GET /api/v2/projects/{project}/runs/{run}/organs/monitor`。每条 `output` 事件包含最多两个最新记录、游标、当前启用状态、运行状态和跳过数量；`ended` 表明应关闭连接。会持续复核项目权限及会话有效性，拒绝非许可 Origin；每个 API 进程最多 32 个活动查看连接。当前实现以 250 ms 周期读取 PostgreSQL，再经 SSE 推送；不声称是从内核直接零延迟传输，也不为此引入 MQ。

本阶段恢复连续发声／图像查看和独立间隔。远程设备专用令牌／匿名 WebSocket、旧躯体与环境工具以及其余内核机制仍在[能力恢复清单](v2-capability-restoration.md)中。
