## Evidence and reproduction

Original registration, pre-expression numerical amendment and the two post-initial-result controls remain separate. The archive includes teaching, measurements, physical telemetry, full anonymous processes, snapshots, calibration/training provenance, weights, raw text, failure notes, PNG/SVG/HTML and scripts. Input model71 and metadata are copied into`frozen-input`; inference prefers that preserved copy. No older model was changed.

Reading`results.json`or the viewer requires no new Core execution. The generic CLI can replay one or multiple processes through archived manifests; a different reader must create a new output rather than overwrite evidence. Checkpoint paths are relative to model manifests.

A full rerun needs the matching repository revision/dependencies/input/background, a new project and a new work directory. Order: register, reanalyse input routes, sources/training probes, four expression regimes, initial tests, three continued histories, frozen-expression tests, registered supplements, continuous observation and publication. Do not run`prepare`again in the old directory. Incomplete cases are retained and rejected for explicit diagnosis, not deleted to hide a failed attempt. Runner signatures and staged source copies identify revisions.

Actual Core identity is recorded in each snapshot's`metrics.kernel_id`and state: `threemind.continuous-memory/2`. The platform manifest's generic old-engine capability label is not this batch's kernel selection.
