# Default performance: 6.3 versus 6.1

Preregistered on 2026-11-15 in response to the author's request for a brief performance experiment and investigation of non-negligible regressions. This is an isolated engineering benchmark. It does not resume cognitive studies or change production kernels, defaults, or existing individuals.

Compare A: default 6.1; B: default 6.3; C: 6.3 with only `subthreshold_expiry_enabled=False`. Use identical anonymous stimuli and advancement times. All other settings, including the quiet period, remain at their birth defaults. Compare complete numerical C/A states after excluding version and configuration metadata. C/A measures implementation overhead; B/C isolates the expiry change. Each engineering instance completes its inputs continuously; timing repetitions use separately created instances.

Native Rust workloads are 128-node sparse initial connections, 128-node dense initial connections, 512-node sparse initial connections, and 128 weak-input channels with one recurring strong channel, each lasting 120 internal seconds. The first three use paired/all-channel initial inputs followed by four channels of strength 0.4 every 0.5 seconds. The weak workload sends four separate 0.0001 inputs every 0.1 seconds and one 0.3 input every 0.5 seconds. Python additionally tests 32-node sparse and 32-channel weak workloads for 20 seconds. These cover operating costs and are not independent cognitive samples.

An A-only calibration fixes the batch repetition count to target 0.75 seconds of advancement, bounded between 1 and 20; all three variants use that count. Each variant has one warmup. Six measured rounds use all six variant orders, balancing their positions. Measure birth, input enqueueing, advancement, read-only observation, complete-state serialization and restoration separately. Save raw timings and the final complete state of each round. Observation and storage must leave simulation state unchanged.

The primary endpoint is advancement time. Report paired ratios and fixed-seed, 2000-resample bootstrap 95% intervals over timing rounds. A 10% slowdown is the practical investigation threshold. A ratio reaching 1.10 or an interval crossing 1.10 triggers six confirmation rounds, at most twelve in total. A slowdown is confirmed when both sets have ratios at least 1.10 and lower interval bounds above 1. A combined upper interval below 1.10 supports no slowdown reaching the registered threshold; otherwise report unresolved precision. Apply the same rule separately to enqueueing, observation, saving and restoration. Memory/file increases of at least 10% and 1 MiB/4 KiB respectively also trigger confirmation. No composite score is used.

For a confirmed regression, compare C/A and B/C, event and transmission counters, expiry checks, graph size and actual simulated duration. Bounded Python profiling may identify Python functions; it is not evidence of Rust function timings. Additional diagnostic hypotheses are declared before their tests. No production optimization is authorized.

Run serially with one-second resource monitoring, retaining 5/4/5/25 GiB of commit/RAM/C/E headroom. Stop subsequent work at the next complete worker boundary if a reserve is crossed. Worker timeout is 180 seconds, raw-data budget 256 MiB, total budget twenty minutes. Originals remain in ignored `.work/kernel63-performance-20261115/`; earlier results are untouched. Freeze source, binary, protocol and tool hashes before execution. A C/A numerical mismatch blocks its performance interpretation pending investigation. Deliver bilingual reports and a small recomputable summary; complete states remain outside Git.
