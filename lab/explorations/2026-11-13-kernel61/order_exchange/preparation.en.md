# Preparing the event-order state-exchange apparatus

2026-11-13. This directory prepares the state-exchange part of E21 under comprehensive revalidation plan v2. It currently contains a draft research tool only. No batch has been registered, no individual has been created and no exchange has been executed. There are no experimental results. The batch may proceed only after R51n is completed and its stopping decision is checked.

Historical E21 used four anonymous material blocks, two facilitation settings and opposite teaching orders. Four state groups were exchanged at the same simulated time to test whether connection weights carried order-dependent responses. The proposed replication retains this scale and all 16 combinations: 16 references would each provide 32 single-test diagnostic copies, giving 512 copies. The references would come from the current 6.1 teaching experiment; historical originals are used only for comparison.

Preparation checks the cues, maintenance inputs, enqueue order and timing of all 512 historical conditions; see `materials.py`. The new batch would derive waiting copies from the 16 complete teaching endpoints together with their observer state, wait 30 seconds under the original schedule, save complete boundaries and check each Core hash against the corresponding R51n pre-cue hash. This preserves observer and input-bus state rather than treating a Core-only pre-cue file as a complete individual.

Kernel6.1 updates state on local clocks. Two weights in a saved file can refer to different last-update times, so they must be aligned in time before being interpreted as current weights. The proposed preparation uses the existing same-time configuration API on separate research copies, retaining all configuration values. Every state change from that explicit operation must be recorded, and response trajectories must be compared with an untreated copy. The operation must neither advance simulated time nor discard in-flight events. If an apparatus requirement fails, the apparatus must be corrected before scientific interpretation.

The groups retain the historical questions, with fields specified for the actual 6.1 state: W contains base connection weights; S contains connection decay ages, retention scales and usage history; N contains persistent node state and usage history; D contains rapid node activity, fatigue, short-term enhancement and synaptic resources. The exact fields are listed in `intervention.py`. Any legacy field still serialized but inactive under the configuration is retained and its actual change reported. Exchanging identical values cannot establish a mechanism's irrelevance. Fixed-function addresses and connection topology are not exchanged.

Changing a weight or decay age requires recalculating the affected connection's local deletion deadline. Exchanging rapid activity also requires consistent emission schedules and the active-node index. These derived changes are listed separately. The draft tool creates no engine and does not modify source snapshots. Before formal use, every combination, sham and self-exchange still needs validation through the public save/restore interfaces, including a check that the numerical deadline calculation agrees with actual schedules.

The formal protocol, measurement checks, complete budget and registration remain to be completed. This draft does not authorize changes to production Core, defaults or frozen batches. E21 timing, repetition and sensory-formation conditions, together with E22 dose-matched comparisons, remain in the coverage table and are not replaced by this sub-study.
