# R51t correction to like-for-like storage accounting

14 November 2026. Registered after the independent apparatus and before formal teaching. The original frozen protocol and initial budget result are retained.

The initial cost script compared every file in each new stage with the historical E12 local stage directory. The new directory also contains raw input frames, queue and delivery receipts, complete pre/post-intervention states and field differences, graph projections and initial observer state. Historical local stage directories did not contain these additional files; raw inputs were held by the research API. The resulting ratio of roughly 2.4–3.4 therefore compared different recorded contents.

Accounting now follows the comprehensive plan's requirement to compare equivalent states and records. Historical directories contain the final complete state, diagnostic milestone states, trajectories, observations, events and results. Their new counterparts are final.tmind, diagnostic milestones.zip, trajectory.json.xz, observer.json.xz and result.json. The new trajectory file includes process samples, observations and events. Teaching and waiting stages additionally duplicate their final state in an end milestone; that copy is supplementary audit evidence. Input audits, pre/post-intervention copies, projections and initial observer state are also reported separately, with actual allocation for every file.

Comparable storage reaching twice the historical amount still pauses execution, as does a 50% excess over the apparatus estimate. The full 2-GiB originals budget, 2 GiB each for archive and readback, 128 MiB for analysis and 25-GiB disk reserve remain unchanged. All additional records count toward the full budget. Nothing is deleted, rounded or sampled less frequently. The full estimate is historical record volume times the largest comparable ratio, plus 1.5 times the largest supplemental stage allocation for every stage, existing materials and a 64-MiB margin. Intervention field-difference JSON is losslessly compressed with XZ preset 1; original apparatus JSON remains and decoded bytes must match exactly. A failed check prevents formal execution.

The separate comparable_budget.py tool provides prepare, run and analyze. Preparation checks costs and runs the six calibration copies. Only after both checks pass does it register the evidence and archive and retire the exact old memory STOP under a lock. Formal execution uses the frozen execute_timescales.py and retains collection of Python objects at each complete boundary. Teaching, parameters, interventions, snapshot counts, scoring and scientific stopping rules remain unchanged. The original study_timescales.py, apparatus and STOP text remain intact, as do production kernels and defaults.
The original 34-stage apparatus finished completely. Its 1-GiB private-memory guard recorded a peak of 1,121,406,976 bytes; system commit headroom remained at least 14.69 GiB. The final six apparatus stages did not explicitly collect Python observation objects between stages, whereas the original formal runner already does so after every complete stage. A separate qualification repeats those six calibration stages from their complete initial states with boundary collection. Final Core state, observer state and every process record must exactly match the first apparatus, and peak private memory must stay within the original 1-GiB cap. No formal individual is retrained, and internal timing and inputs are unchanged.
