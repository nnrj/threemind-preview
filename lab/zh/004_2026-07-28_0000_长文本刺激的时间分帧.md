# 004 — 长文本刺激的时间分帧

[中文](004_2026-07-28_0000_长文本刺激的时间分帧.md) | [English](../en/004_2026-07-28_0000_temporal-framing-of-long-textual-stimulation.md)

**日期：** 2026-07-28  
**状态：** 实现与实验方法修正；尚待长时间验证

## 观察

一次通过 UI 提交多段长文本后，运行服务曾表现为无响应：图形更新停止到达、不能及时开启新意识，随后浏览器连接断开。连接丢失后出现了 Windows socket 与 WebSocket 代理报错；这些报错被视为后续症状，而非最初原因。

与持续背景刺激的比较很关键。背景帧本来就是随时间、有先后地到达。通过一次 UI 操作提交的长文本，不应被重新解释为其中全部感官脉冲在同一瞬间同时激活。

## 近因与修正

输入路径此前缺少针对大文本载体的时间分帧与背压控制。单个请求可能在一个处理轮次中调度过多工作，随之而来的图变化与输出活动会挤占正常的 API 和 UI 更新。

因此，输入路径被组织为可审计的载体流：

1. 文本载体被拆分为有序帧；
2. 每帧保留来源、序号、强度/包络和时间元数据；
3. 输入总线按顺序排队，并跨 epoch 推进帧，而不是静默丢弃或重排；
4. 传输与输出路径使用有界流控/背压，使较慢的观察者不能迫使运行网络承担无界工作量。

这项处理的目的不是暗中缩短文本，也不是把它替换成语义摘要；而是保留外部事件原有的时间结构：长刺激需要时间到达。

## 与工作假设的关系

这是方法学结果，而不是认知现象的主张。它保护实验的一项核心前提：刺激是连续且有顺序的，联想应来自局部、处在时间中的触达，而非人为构造的一次性批量操作。

它也为未来的非文本感官适配器提供了共同契约。音频、图像、视频、遥测或躯体信号可以采用不同编码，但其帧都需要来源身份、顺序、时间和可审计传递。

## 必要验证

1. 以不同帧大小和帧间 epoch 间隔发送同一长载体；比较完成时间、队列深度、API 响应性、图统计与被动输出历史。
2. 验证全部帧都按顺序进入刺激日志，不发生静默截断或重复传递。
3. 仅在有界测试环境中，将分帧呈现与刻意的同时呈现对照；报告激活、可塑性和稳定性差异。
4. 测试慢速或断开的观察者，确认输出流控保护运行时而不改变 Core 的拓扑规则。
5. 在重启和强制中断后重复，借助持久化历史区分“传递失败”和“观察失败”。

## 解释边界

时间分帧避免把实现伪影误认为内部崩溃或意识性质。它本身并不能使长文本后的响应获得语义，也应作为实验装置的一部分接受验证。
